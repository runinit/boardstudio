# Private Case mechanical-settings controller contract

This note and `web/src/presentation/mechanical_settings_controller.rs` define an unmounted page-private controller for F7.4 settings requests. The published ticket, React parity, parent acceptance and browser verification remain open. No public Core, application, schema, CAD, Runtime or CSS interface changes are part of this slice.

## Injected page ports

The parent creates one `MechanicalSettingsController` for the editor lifetime and supplies:

- `current`: a cheap current-state read containing the accepted `AcceptedSnapshot` (its document and scene remain shared `Arc`s), the effective configuration shown for the active canonical/physical scope, the captured `MechanicalSettingsIdentity`, and current admission/lifecycle/durability facts. The admission bit covers current Runtime, selected workspace, physical-instance authority, Ready/Saved revision, and no preview/gesture. It excludes this controller's own in-flight state; the parent combines `is_busy()` when deciding whether controls can submit.
- `resolve(snapshot, scope, proposed_document)`: a narrow local-future callback that creates fresh current contours from the captured accepted snapshot and scope, applies the proposal's physical-instance projection as appropriate, and runs the existing Core `ResolveMechanical` request. The returned `MechanicalAssembly` supplies only suggested closure locations here. Cached `CadScene` is not an initialization source.
- `load_mounting_hole`: an async lazy-source loader returning the existing normalized bundled `ceoloide/mounting_hole_npth` `PartDefinition` behind `Rc`. It must not create external catalogue content or re-normalize with a different policy.
- `next_operation` and `submit_replace`: the parent allocates a fresh `OperationId`; `submit_replace` registers the exact outcome slot through `Runtime::observe_operation` before submitting exactly one `Event::Edit` containing `EditOperation::ReplaceDocument`, then returns that slot. Errors returned before submission leave the accepted document untouched.
- `project_closure_clearance(document, definition)`: the existing pure projector, returning `Result<ProjectDoc, String>`. A planner error (including unsafe mounting-hole reference allocation) is surfaced as Failed before any Runtime submission.
- `publish`: a page-owned bounded feedback store. Replace each request's Pending state with its own terminal state, retain a busy request while reporting a separate raced rejection, and key rows by full captured identity, request ID and field ID.

The controller has no Runtime/session mirror, timer, request registry, or event-history authority. The existing editor-lifetime `request_sequence` signal is owned above workspace conditionals and passed into the settings component. The controller reserves one admitted request through Resolving and the exact observed Runtime outcome; a raced request gets its own immediate Failed feedback without displacing that reservation.

## Transaction flow and guards

At admission, the complete request identity must equal current editor lifetime, Case scope generation, full `Scope`, accepted snapshot token/revision, active board and configuration board, and the root's current edit guards. A current-state notification during Resolving also checks the captured token/revision. After each await, the controller re-reads and revalidates that complete identity before using any result or submitting.

The controller starts from the captured accepted canonical `ProjectDoc`; the effective configuration projection is only the field-edit base. `Enable` uses the existing `case_settings::initial_settings` helper and requires no current configuration. Update and Disable require a matching configuration for the active board. Physical writes use the existing `case_settings::update_instance_settings` linked-construction policy; the selected stored config and shared construction change, non-target stored mechanical configs remain intact, and link flags follow the helper. Canonical writes change only `ProjectDoc.mechanical`. No UI edit mutates the accepted document in place.

For non-gasket configuration where `closure_mounts` is absent, the controller writes the proposed configuration into a temporary candidate, resolves from fresh captured contours, and sets `closure_mounts = Some(...)` from the assembly suggestions. An empty successful result becomes `Some(vec![])`; existing explicit empty/nonempty lists skip initialization. Suggested closure IDs receive the `auto-closure/` prefix, boss kind, 2.2 mm hole diameter, and source-derived height `plate_to_pcb + pcb_thickness + max(bottom_foam_thickness, battery_height)`. Gasket selection removes only automatic closure mounts, ensures the source default gasket layout/internal configuration, preserves existing gasket travel when internal gasket data exists (otherwise 0.1), and resets integrated frame/bottom/middle choices.

Every accepted field patch applies the React plate-family/gap/derived-foam coupling and standard process normalization before closure clearance projection. Process normalization preserves unrelated processes/order/extension fields, keeps foam as cut-sheet/EVA, synchronizes represented standard thicknesses, and resets incompatible materials. An explicit method selection resets non-foam standard process material even if the old material remains valid. The controller then calls the Result-returning closure projector and submits one replacement document, so mechanical configuration and generated PCB hole parts/definitions/layout/board membership share one Session transaction.

`settle()` is driven by the existing page Runtime-version signal and observes only the operation slot returned by this request. `Completed` is not Saved: the controller waits for a different accepted snapshot token, a revision newer than the base, Lifecycle::Ready, and Durability::Saved at that accepted revision. It then compares the exact stored canonical/instance configuration effect—including every stored instance configuration and link bit—and a narrow closure evidence projection (generated closure parts, generator source/parameters, and board/layout membership). It never retains a predicted full document or acknowledges by matching a global error string. Failed terminal outcomes and lost scope release only their own request and publish exact Failed feedback. The UI keeps its local numeric draft until matching Saved/Failed feedback when acceptance advances before durability.

## Source scope and remaining evidence

The source behavior is grounded in `app/src/ui/MechanicalAssemblyPanel.tsx`, `app/src/mechanicalPresets.ts`, `app/src/createProjectActions.ts`, `app/src/hardwareInstances.ts`, and `app/src/closureClearance.ts`. Existing Rust settings helpers are in `web/src/case_settings.rs`; the root page owns the Runtime, async Core resolver, lazy normalized catalogue definition and mounted wiring.

Remaining gates: source contract review of this exact controller, strict WASM compilation and tests in the root integration turn, mounted public-route interaction, save/undo/redo/failure behavior, same-scope remount and physical linked-instance verification, and browser parity. This unmounted file does not claim F7.4 acceptance or close any parent join.

Refactoring finding: RF002 is bounded to the existing private page boundary. The controller receives narrow ports because Runtime submission, async CAD resolution and lazy imported definitions are page-owned; preserving those owners avoids widening shared APIs. No new refactoring finding or public seam is proposed.
