## How to work here (hard-won)

- **Never `git stash`.** Commit WIP instead. Use `/usr/bin/git -C <abs path>` if a worktree guard refuses
  bare git. Isolated agent worktrees sometimes start on stale `94766ab0b`: check and reset to dev tip first.
- Cargo needs the sandbox lifted (target not allowlisted). Package is `boardstudio_core`; build jobs are
  12 in `.cargo/config.toml`, never override. Browser step needs the sandbox lifted too.
- Native test guard: `scripts/check_native_tests.py` + `scripts/check-native-tests-baseline.json`. Never
  hand-edit the JSON; run `python3 scripts/check.py test --update-native-baseline` and commit additions.
  Agents forgot this once (112), so say it in every implementer prompt.
- **Red first, shown failing, then green.** 112 was written code-first and a reviewer found two high
  defects; the fix round was red-first. State this in prompts for low-effort models.
- Per ticket: implement on an isolated worktree branch → independent review (code-review skill, Standards
  + Spec axes) → fix findings red-first → merge `--no-ff` to `dev` → `check.py repo test lint` on merged
  `dev` → save evidence to `.evidence/` (gitignored) → remove worktree/branch (unlock first if the agent
  process was still alive). Mutation checks: `scripts/mutation-check.py`, one mutation per behaviour.
- Models used successfully: Sonnet at low effort for implementation, Sonnet at medium for review,
  Haiku for light/ticket chores.
