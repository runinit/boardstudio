# Map: Typed generator parameters

Label: wayfinder:map
Source: research and plan of 2026-10-09, requested while resolving
[typed-core-edits 04](../typed-core-edits/issues/04-refresh-included-keyboards.md)

## Destination

Generator parameters are typed end to end. Core never writes a wrongly typed value, saved
projects that hold the bad values are repaired by a versioned migration, Core rejects
mistyped or undeclared parameters on edit, and the conventions are documented and linted.
Option B of the 2026-10-09 research; renaming the parameter vocabulary or adding integer
and enum kinds (option C) is out of scope.

## Notes

- Decision basis: [ADR-0003](../../adr/0003-rust-footprint-generators-in-core.md) and
  [ADR-0004](../../adr/0004-document-format-version-and-id-rename.md).
- Tracker conventions: [docs/agents/issue-tracker.md](../../agents/issue-tracker.md).
- GitNexus `impact` before each symbol edit and `detect-changes` before each commit; the
  index is stale, so say so. Native Core tests run in a non-nested checkout.
- Never run `check.py release`. Do not merge to `dev` without the user.

## Decisions so far

- Repair saved strings with a v3 to v4 migration, not per-load coercion: ADR-0004 rejects
  an unversioned rewrite on each load, and `migrate_json` does not detect change at the
  current version. Detail in [03](issues/03-migrate-saved-generator-strings.md).
- A mechanical pair keeps everything linked, with explicit exceptions (user, 2026-10-09,
  [ADR-0008](../../adr/0008-linked-halves-stay-linked.md)); this replaces the recommendation
  in 06 and in the 02 progress note.
- Unknown parameter names are warnings on Open and errors on edit, so real user projects
  are not refused: [04](issues/04-validate-generator-parameters-in-core.md).

## Progress

- 01 resolved: closure clearance holes write numeric `hole_drill`/`hole_size` and are
  regenerated by `generators::normalize_definition`; two regression tests fail on the old
  string code and pass now; boundary transcript re-blessed (16 lines: the 8 parameter lines
  plus `-0.0` pad `y` and rotation from the normalizer), native and WASM parity pass.
  Commit `46610e2a8`; evidence in the
  [ticket Outcome](issues/01-closure-holes-via-generator-normalization.md). Next: 03.
- 02 resolved (commit `e5f253fab` and the Outcome commit): every half of the seven measured
  splits and of Sofle RGB and Choc keeps the closure mounts Core proposes from its own outline
  (4 per half) and all 20 halves export. A first attempt that only removed the empty-closure
  edits made Core refuse every measured left half; the cause was recipe order (the right half's
  proposals joined the pair after the link), so the recipe now initializes closures before
  linking. Sofle v2 has none (gasket mount). Core still links initialization proposals to the
  pair and `enable` still skips a legacy second half; ticket 06 asks for that decision, and a
  known-gap test pins current behaviour (superseded by ADR-0008, see 06). Fit findings (holes inside the controller bay, tight
  switch gaps) are in the [ticket Outcome](issues/02-restore-closure-mounts-in-recipes.md).
- 03 resolved (implementation `fd7640a9a`, docs `a115b4c31`, verification follow-ups `0e5a4369f`
  and `f5def9feb`): format version 4 converts the saved numeric strings in generator parameters to
  numbers on definitions, parts and assembly members, and removes empty or whitespace-only number
  and list text. Non-empty list text such as `"[1,2,3]"` is not converted; it stays text, as in the
  old 1 to 2 step. Implemented by Haiku, reviewed by a Sonnet verifier (no functional defect), and
  re-run by the integrating Sonnet session: a browser test loads a saved v3 closure project through
  IndexedDB (red with the step disabled, green with it); `repo lint typecheck browser`, `build` and
  the native `test` pass (`quick` did not complete: environment limits, see the ticket); evidence and limits in the
  [ticket Outcome](issues/03-migrate-saved-generator-strings.md). Next: 04.
- 06 decided (user, 2026-10-09, [ADR-0008](../../adr/0008-linked-halves-stay-linked.md)): a mechanical
  pair keeps everything linked; the known-gap test from 02 and the shipped split data still follow
  the superseded behaviour until 06 is implemented.

## Not yet specified

- Core building the mounting-hole template itself and removing the `mountingHole` wire
  field (the page still loads and sends it with each mechanical edit).
- Closure holes are de-duplicated only against each other, not against authored mounting
  holes (Sofle's measured holes); closure positions can land on switches. Surfaces in 02.

## Out of scope

- Renaming the parameter vocabulary (`hole_drill`/`hole_size`, `drill`/`outline`,
  `via_drill`/`via_size`, Case `hole_diameter`/`boss_diameter`) and adding integer or
  enum parameter kinds: breaks saved documents and golden schemas, and diverges from
  upstream (ADR-0003).
