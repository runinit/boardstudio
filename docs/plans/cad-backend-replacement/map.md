# Map: Complete CAD backend replacement

## Destination

Replace BoardStudio's entire Cadrum CAD backend with Monstertruck, preserve intended features and accuracy, and remove OCCT/C++ from CAD production, build, packaging and required-test paths. Own the outcome through verified production integration; qualification experiments and individual resolved tickets are progress. Production remains Cadrum until full acceptance is established.

Completion requires the feature assessment as amended by the dated scope decisions below in current production code, passing required native/WASM/browser checks, comparable performance measurements, and an actual dependency/build/packaged-artifact audit demonstrating CAD no longer requires OCCT/C++. Exact geometry and exact STEP export are required for generated **cases and PCBs only**, built through013's layered2.5D path. Preview meshes cannot substitute for those exact solids. Keycaps use appearance/optional-print meshes; vendor STEP uses complete source-retaining preview/alignment/collision meshes. Those mesh paths are the approved design. Preserve independent accuracy and strict source completeness; internal STEP roundtrips alone do not prove interoperability. No general exact3D Boolean engine is required, and OCCT/C++ cannot remain as a final fallback.

Vendor STEP assets retain immutable original bytes, original source geometry/face information and every occurrence, unit conversion and placement; reject incomplete imports. Assume millimetres when units are absent. Repairs use the latest user-approved vendor-preview allowance `max(2 × authenticated declared precision, 0.02 mm)`, recorded in the [STEP implementation handoff](../../../.evidence/claude-step-fixes/PLAN.md); retain declared precision separately. The user additionally approved an explicit per-file preview repair budget on2026-10-17, which may exceed declared precision: retain both values, enforce the selected bound, record actual movement separately, preserve original bytes/source geometry and never silently remove geometry. A requested repair budget does not certify a collision error bound. The user approved **supported tolerance bands by default, with refinement on demand and0.01 mm as an explicit tighter check** on2026-10-17. Basic collision validation in014 reports intersection, clearance and contact locations with those bands; results without sufficient accuracy remain uncertain. No fixed0.01 mm analysis mesh is required for ordinary display or validation. A0.1 mm display request alone does not establish a certified error bound.

The user authorizes API adaptation and fixes to poor Cadrum behavior as part of this replacement. Preserve intended product capabilities and correct geometry, rather than reproducing implementation quirks or known bugs. Update affected callers and tests together, document intentional behavior changes with independent acceptance evidence, and retain the agreed polygon, missing-unit and support-tolerance policies. This does not authorize unrelated refactoring or loss of supported features.
