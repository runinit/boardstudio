# Separate Editor workspace ownership without changing lifetimes

## Workflow

Installed BMad skills govern orchestration, ticketing, review and verification. Legacy sources and historical notes retain behavioral requirements and evidence, not their proof-map, mutation, fixed-review or ordered-closure protocols. Functional acceptance and explicit human/phase approvals remain unchanged.

## Description

Adopt only the approved production-composition proof phase of the original Editor ownership specification. The maintainer can supply the existing test Runtime to the real application composition and verify navigation, pending work, reconciliation and genuine teardown without a second application. Original parent 001 remains open at its exact source path; this phase neither completes that parent nor schedules the remaining ownership extractions.

## Outcome

Maintainers can demonstrate that real application composition preserves editing and lifetime behavior before considering further ownership moves, with unchanged production startup.

## Requirements

- R1 (proposal R1; original 002 Scope and constraints / Acceptance criteria): Tests supply the existing Runtime through one private production-composition seam while normal startup retains its constructor, one subscriber, reconciliation and provider ancestry.
- R2 (proposal R2; original 002 Acceptance criteria): A scope-correct two-board mounted fixture submits a real edit with filtered reply/save gates, bounded waits and independent saved/accepted assertions, without cross-scope warnings or dropped-Signal errors.
- R3 (proposal R3; original 002 Acceptance criteria): Actual workspace/header controls preserve surfaces, production board selection reconciliation and Export Back/Escape/header return to the last non-Export workspace; workspace cycling creates no accepted-document edit.
- R4 (proposal R4; original 002 Acceptance criteria): A held edit survives workspace leave/return with once-only settlement and no obsolete feedback or draft writes; reused-ID project replacement establishes a new session identity and rejects retained stale callbacks, with late-reply rejection explicitly evidenced at its real adapter seam.
- R5 (proposal R5; original 002 Acceptance criteria): Library hides rather than remounts Editor; actual Editor-only and App removal followed by releasing held work causes no stale DOM, navigation, focus or dropped-Signal access while Session-owned work retains its existing drain/save rules.
- R6 (proposal R6; original 002 Verification; original map Shared implementation and verification contract): Existing useful tests remain, preferences/global DOM are isolated and restored, normal startup ships no fixture controls/alternate persistence, and evidence records baseline, exact commands, diagnostics and receipt scope.

## Constraints

- Preserve existing hook scopes, three lifetimes, operation-specific admission and shared authorities. No fake App, competing subscriber, active-only workspace controller mount or wholesale mockup merge. Source: original 002 Scope and constraints; original map Shared implementation and verification contract.
- This phase moves no workspace controllers and changes no UI policy, camera formula, schema or public cross-crate contract. No registry, framework, broad draft cache or duplicate authority. Source: original 002 Verification; original map shared contract; proposal Approved direction.
- Use BMad for review and verification; do not fabricate failing evidence or relabel historical partial results.
- No explanatory HTML, root-DOM removal, manually advanced generation or serialized Open behind a held edit may stand in for real teardown/reconciliation or delivery after accepted replacement. Keep any controlled-adapter proof explicitly lower seam. Source: original map shared contract; original 002 Acceptance criteria.

## Done when

1. The production seam and complete original 002 acceptance work through the real subscriber/providers and controls; normal startup behavior remains unchanged.
2. Real mounted scope driving, hidden-versus-removed owners and held-work completion have warning-free observable evidence; failure to drive/unmount safely stops further extraction rather than waiving the gate.
3. BMad governs implementation, review and verification; record actual results without a separate ordered-closure protocol.
4. Changed-scope quick checks, lint where browser/WASM-only Rust changes, page-only WASM compilation, page-bin mounted suite, relevant Runtime tests and existing mounted Editor tests pass with exact baseline/current receipts. This is not original 013's full integrated extraction acceptance.
5. Evidence distinguishes fresh runs, reused lower-seam results and historical mockup observations. Closing this adopted phase never closes source parent 001 or original 013 automatically.

## Boundaries

- Owner: `epic-production-composition-proof` owns all R1–R6 and the sole implementation entry, original 002.
- Touch point: existing Runtime/Session/Core test support and controlled adapters — consumed by the composition fixture; owner: `epic-production-composition-proof`.
- Touch point: current workspace/header/Export/Library surfaces, selection providers and cleanup resources — exercised, not redesigned or extracted; owner: `epic-production-composition-proof`.
- Touch point: current browser preferences and global DOM/listeners — isolated and restored; owner: `epic-production-composition-proof`.
- Out: original 003–013 as executable work in this phase, broader release/storage/renderer/package journeys, new hardware/provider/GPU qualification, and changes to another plan. Their original obligations are not declared satisfied or canceled.
- Tracer: real edit → held save → actual workspace transition → accepted publication → genuine owner removal.
