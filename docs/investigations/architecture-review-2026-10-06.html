ProblemSession rebases every queued Event::Edit's revision but not its absolute payload, so the last writer wins. Each controller then re-derives settlement from snapshot tokens and durability.

SolutionMake application the one module that owns edit admission policy (rebase / strict / reject), resolves intent against accepted state, and reports where an edit landed. Controllers hold a ticket and read one settlement value.

    Wins
  • Locality: revision policy in one module
  • Leverage: one interface, ~35 controllers
  • Reproducer becomes a native Session test
  • Deletes ~40 Pending* structs
  • Mounted tests keep focus/ordering only

The investigation asks that pending/rejection/retry behaviour be settled before an interface is chosen. This card names the module and its ownership, not its interface.

Top recommendation

1 · Edit settlement module in application

It is the only friction here with a reproduced data-loss consequence, and its mechanism is not limited to the Inspector. Every queued ReplaceDocument (51 web sites) can undo edits accepted after it was captured. Deepening application's edit interface removes that overwrite at the seam where it originates. It also deletes the settlement logic that ~35 controllers re-derive, and turns the open investigation's reproducer into an ordinary native Session test.

Sequencing: build card 3's in-process Core adapter as the test harness for card 1, then let card 2's intent-level edits shrink the remaining ReplaceDocument surface. Card 5's dropped model offsets are an independent, verified bug worth fixing on its own.
