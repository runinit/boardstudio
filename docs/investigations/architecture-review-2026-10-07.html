Problem
The edit ticket is deep, but settlement stops at one ticket. Each panel re-implements the pending → landed / failed / retired handling, and the panels disagree about Settlement::Retired. Example: settle_ticket and settle_field are byte-identical.
Solution
Add one Dioxus-free pending-edits module on top of the edit ticket. It owns ADR-0005's rules (field edits queue and the latest value wins; one-shot actions disable), restoring the accepted value on failure, and the owner-liveness check, which reads the captured scope instead of four hand-written owner_is_live checks. It also absorbs resolver boilerplate (31 × base_revision: 0, 47 × empty transaction_id, and 18 resolver epoch checks that Session's own epoch rejection already makes unreachable).
Wins
  • Locality: one Retired policy
  • Leverage: one interface, ~15 panels
  • Native suite replaces wasm-only proofs
  • Delete 15 holders, 14 enums
  • "Retire" stops meaning two things
  • New panels get ADR-0005 for free

Problem
On native builds the whole runtime module is swapped for a 65-line stub. Panel tests either call resolvers by hand or use HookPort, a second copy of Session's resolution rules that can drift. ADR-0005 asks that tests use the route production uses.
Solution
Promote NativeEditDriver into the native test Runtime: the real Session and CoreEngine, in-memory saves, and the same hold/fail gates under the test-support vocabulary InProcessAdapters already uses. The Core and persistence seams already have two adapters each, so the seam is real.
Wins
  • Delete HookPort, PlacementRuntime, stub
  • Tests cross the production seam
  • Shorter browser check step
  • Verifies candidate 01 natively

Problem
The resolver contains a web-side domain engine that copies Core's defaults (default_material, the 3.5/5.0 mounting datum) and answers with a whole-document replacement, so either copy can drift.
Solution
Make it a typed-core-edits slice: Core applies a mechanical patch, keeps one copy of the defaults, and reports precise changed IDs. The controller shell, which is already deep, stays as it is.
Wins
  • One copy of mechanical defaults
  • ~1,170 lines of tests become Core contract tests
  • No outline recompute for scalars
  • One fewer ReplaceDocument resolver (57 today)
Follows ADR-0006. Sequence it after SetWiringMode settles the pattern.
