## 01 — duplicate identities and revision overflow

**Evidence.** [Ticket 01 acceptance](../plans/rust-best-practices/issues/01-reject-duplicate-identities-and-revision-overflow.md#L11) is substantially necessary:

- Public `CoreEngine::handle(Open)` only checks format/version before preparing and publishing ([`core/src/lib.rs:238–253`](../../core/src/lib.rs#L238)). `prepare_open` stages a clone, runs scripts/layout/constraints, then validates layout and halves ([`prepare.rs:26–101`](../../core/src/mirrored_half/reconcile/prepare.rs#L26)). Neither layout validation (which immediately succeeds without layouts, [`layout.rs:7–10`](../../core/src/matrix/layout.rs#L7)) nor halves validation (which immediately succeeds without hardware, [`halves.rs:242–245`](../../core/src/mechanical/halves.rs#L242)) establishes generic top-level uniqueness.
- Constraint resolution collects all parts into a `BTreeMap` keyed by ID, then writes the resulting pose back to *every* matching part ([`constraints.rs:232–236,308–315`](../../core/src/constraints.rs#L232)). Two free parts with the same ID but different poses therefore collapse to the later pose even without a constraint. Subsequent ID-addressed operations are ambiguous. This is source-level reproduction evidence, not an executed Open test.
- Constraint IDs are **already** checked by `claim_id` on stored/prepared records ([`constraints.rs:206–210,245–258`](../../core/src/constraints.rs#L206)); keep a regression, do not duplicate this as a second conflicting solver policy. Boards/definitions/matrices/nets still need admission uniqueness even if a particular downstream consumer happens to refuse one duplicate fixture.
- Commit uses `self.document.revision + 1` ([`lib.rs:700–717`](../../core/src/lib.rs#L700)); undo/redo pops the source stack and pushes the other stack **before** incrementing ([`lib.rs:822–834`](../../core/src/lib.rs#L822)); remap review clears `protected_handoff` **before** `revision += 1` ([`lib.rs:387–413`](../../core/src/lib.rs#L387)). Rejecting max only on Open is insufficient: an accepted max-minus-one revision can legitimately advance to max.
- Edits are staged and base-revision checked ([`lib.rs:491–494,572–609`](../../core/src/lib.rs#L491)). Put admission validation on Open/replacement before identity-keyed normalization can erase evidence, and retain a publication invariant for generated output. Do not reject cross-kind equal IDs unless the domain actually requires a shared namespace; the ticket asks for uniqueness *within* six collections.

**Smallest acceptance changes.** Keep all four existing criteria; append: “Every refused transition preserves accepted document, revision, outline cache, undo/redo contents and protected handoff. Compute the checked next revision before changing any of these.” Test max-minus-one → max → refused next transition, nonempty undo/redo at max, and a valid handoff fingerprint at max. An empty history or wrong fingerprint would only exercise an earlier guard. Keep unique-document controls and one duplicate case for each named collection on Open and replacement; assert the old accepted document remains intact. Preserve existing errors/no-op behavior where no revision is advanced.

## 02 — monotonic mechanical identities

**Evidence against the present wording.** [Ticket 02](../plans/rust-best-practices/issues/02-preserve-monotonic-mechanical-identities.md#L7) combines three different mechanisms:

| Kind | Current allocation/removal behavior | Actual gap |
| --- | --- | --- |
| Opening | Persisted `next_opening_identity`, max-existing and pair floor; removal does not lower it ([`edit.rs:3682–3697`](../../core/src/mechanical/edit.rs#L3682)) | Undo restores an older document/counter; unchecked highest/floor/next increments |
| Vertex | Persisted per-opening `next_vertex_identity`, same floor approach ([`edit.rs:3700–3713`](../../core/src/mechanical/edit.rs#L3700)) | Same undo gap; deleting/recreating owners also matters |
| Critical fit | Scan from 1 for first unused ID, checked increment ([`edit.rs:2495–2530`](../../core/src/mechanical/edit.rs#L2495)) | Remove/add and undo/add reuse holes; a sparse imported max suffix does **not** overflow this search |
| Hardware entry | Same first-gap allocation with checked increment ([`edit.rs:2576–2617`](../../core/src/mechanical/edit.rs#L2576)) | Same reuse; sparse max suffix does **not** overflow |
| Mount | First-gap `usize` search across ordinary/closure mounts, parts and case-body mounts ([`edit.rs:2837–2855`](../../core/src/mechanical/edit.rs#L2837)) | Reuses holes if all those other owners release the ID; a lone max suffix does **not** make the ordinal overflow |

Existing protection must survive: `evaluate_edit` retires missing targets and missing opening/vertex IDs ([`edit.rs:88–167`](../../core/src/mechanical/edit.rs#L88)); the Case controller also captures opening removal guards ([`mechanical_settings_controller.rs:274–324,591–606`](../../web/crates/case/src/mechanical_settings_controller.rs#L274)). Those tests must not be described as evidence that all five kinds are broken on ordinary removal.

**Why queued edits are still relevant.** Session deliberately queues `ResolveEdit` non-strictly ([`session.rs:772–780`](../../application/src/session.rs#L772)), resolves against the then-accepted snapshot, and stamps the current base revision ([`session.rs:1541–1574`](../../application/src/session.rs#L1541)). The production adapter's resolver ultimately submits the ID-bearing patch after `evaluate_edit` ([`mechanical_settings_controller.rs:738–778`](../../web/crates/case/src/mechanical_settings_controller.rs#L738)); ordinary hardware/critical-fit changes are not opening guards or reviewed pair actions ([same file:591–606,672–694](../../web/crates/case/src/mechanical_settings_controller.rs#L591)). Therefore base-revision checks do not distinguish old item A from a replacement B reusing A's ID. A stale setter resolving after remove/add can edit B; for openings/vertices, add/undo/add can recreate the same identity despite ordinary removal protection. A genuine regression must queue the stale setter behind the replacement sequence, not merely submit a raw old-revision command (which Core correctly rejects).

**Lifecycle is part of the fix.** Reservation arithmetic also runs without minting: disable snapshots reservations, pair dissolution/materialized survivors merge floors, and typed instance writes preserve floors ([`edit.rs:1005,1569,1636,3756–3795`](../../core/src/mechanical/edit.rs#L3756); [`edit.rs:1013–1021,1573–1580`](../../core/src/mechanical/edit.rs#L1013)). `identity_reservation_of` does `highest + 1`; `merge_identity_floor` does `floor + 1`. Fixing only `reserve_*` leaves imported max-suffix panics on these transitions. Staging already supplies rollback ([`edit.rs:49–59`](../../core/src/mechanical/edit.rs#L49) and the staged clone in `apply_with_ledger`); propagate exhaustion rather than saturating into a reusable identity.

**Recommended design boundary.** Non-reuse belongs to one *document session*, not one settings-panel mount or one undo snapshot. A successful Open creates a new SessionEpoch; ordinary edits/undo do not ([`session.rs:1947–1971`](../../application/src/session.rs#L1947)), and queued old-epoch intents retire ([`session.rs:1477–1485`](../../application/src/session.rs#L1477)). Core Open separately resets history ([`lib.rs:250–252`](../../core/src/lib.rs#L250)). Keep existing serialized opening/vertex counters and extend allocation reservations consistently, but preserve session high-water marks outside the history snapshots (or explicitly merge them on every history restore, including absent configurations/owners). Seed from imported live IDs and existing reservations; reset only on a successful explicit Open, not preview/evaluation, failed edits, undo, disable/re-enable or panel remount. Owner keys must distinguish canonical board/physical instance and vertex owner; preserve mount's existing cross-collection collision checks. Do not add a global UUID dependency or change the entire identity format. A Core-local reservation ledger is a smaller coherent session boundary than teaching each UI setter about tombstones; ensure Core reconstruction/recovery is either a new epoch or restores those reservations.

**Exact acceptance rewrite.**

1. Parameterize remove/add and add/undo/add over all five kinds; verify a fresh ID and that an old-ID setter cannot mutate the replacement. Retain opening/vertex existing removal controls.
2. Exercise the real queued resolver at least for first-gap reuse and history reuse, with unchanged board/instance/session scope. Assert retirement or clear rejection and unchanged replacement values, not a particular new ID number.
3. Replace “max suffix currently panics for every kind” with “allocation honors imported/reserved high-water marks and cleanly refuses exhausted namespace”; include max **counter**, max suffix, near-max increment and sparse-ID cases. The first-gap kinds are a new monotonicity requirement, not an existing demonstrated max-suffix overflow.
4. Add atomic exhaustion checks on disable, targeted replacement and pair dissolution/materialization wherever reservation merging runs. Test separate owners, disable/re-enable, undo of configuration creation, and fresh Open reset. Preserve existing mount collision exclusions.

Ticket 01 is useful shared atomicity work, not a logical prerequisite to reproducing this independent ID bug.

## 03 — constraint recursion

**Evidence.** [Ticket 03](../plans/rust-best-practices/issues/03-bound-constraint-solver-recursion-depth.md#L7) identifies a real unbounded call path. `pose` uses an active-path set to reject cycles, but recurses through `drive` to source authority and both framed owners, and directly through assembly parents ([`constraints.rs:505–623`](../../core/src/constraints.rs#L505)). Memoization stops repeated work only *after* each pose resolves. The public Open preparation and edit route both invoke this solver ([`prepare.rs:48–51`](../../core/src/mirrored_half/reconcile/prepare.rs#L48), [`lib.rs:598–609`](../../core/src/lib.rs#L598)). No input depth bound is established by those callers.

**Smallest path.** A conservative named active-depth budget checked at entry to `pose`, before recursion, covers all dependency edges without replacing the solver. A bound on the existing `visiting` set can avoid a separate counter; preserve cycle-before-depth behavior where a repeated active ID is encountered. Choose a conservative limit and validate native plus packaged WASM rather than claiming a portable safe frame count from intuition. Keep completed-node memoization and all existing evaluation/precedence semantics. An iterative heap stack is a larger alternative, not a requirement; it would make “12,000 must Err” inconsistent unless a separate resource limit remains.

**Exact acceptance changes.** Replace the implementation “depth or heap stack” choice with “enforce one documented conservative active dependency-depth limit across source authority, framed source/target owners and assembly parents.” Keep the 12,000-depth refusal test, but construct IDs so lexicographically first target depends on all later targets: iteration is `BTreeMap` order ([`constraints.rs:289–299`](../../core/src/constraints.rs#L289)). A source-first ordering may resolve each node from cache and never create a deep call stack, falsely passing the test. Add below/at/above-budget fixtures, a cycle control, both framed-owner edges and assembly-parent coverage, and unchanged accepted state after refused Open/edit. Runtime stack exhaustion and an appropriate WASM-safe numerical limit were not measured here.

## 05 — non-finite rings and malformed GPIO

**Already solved / defended.** [Ticket 05 acceptance](../plans/rust-best-practices/issues/05-reject-non-finite-support-coords-and-bad-gpio-pins.md#L11) does not describe the current public behavior:

- `validate_poly` rejects every non-finite coordinate first; rational conversion itself uses `ok_or`, not `unwrap` ([`support_owner.rs:49–56,132–156`](../../contracts/rust/src/support_owner.rs#L49)). Both support-area validation and profile normalization use it ([same file:287–290,341–348](../../contracts/rust/src/support_owner.rs#L287)). An infinity regression already exists ([same file:433](../../contracts/rust/src/support_owner.rs#L433)).
- The separate boolean self-intersection API returns `false` for a non-finite coordinate before its private exact-orientation helper is reachable ([`contracts/rust/src/lib.rs:182–186,242`](../../contracts/rust/src/lib.rs#L182)). That API is not a validation `Result`; do not change its signature/meaning just to remove a defended conversion assertion.
- `gpio_spec` and `gpio_spec_flags` really contain `parse().expect(...)` ([`firmware.rs:745–769`](../../core/src/firmware.rs#L745)), but public scan-pin admission verifies exact terminal/GPIO membership against a selected built-in controller profile, including rows, columns, direct and auxiliary pins ([same file:252–272](../../core/src/firmware.rs#L252)). Wired UART has its own `known` guard ([same file:340–352](../../core/src/firmware.rs#L340)). Encoder GPIOs are also checked against the profile/reserved/used sets **before** `gpio_spec_flags` ([`encoders.rs:65–106`](../../core/src/firmware/encoders.rs#L65)); both halves are prepared ([same file:128–130](../../core/src/firmware/encoders.rs#L128)). A caller cannot import a custom controller table through this request.

**Recommendation / exact acceptance replacement.** Wontfix the requested public “emit unresolved marker for P1.X” behavior: it would weaken the existing fail-closed firmware contract. If retaining a coverage ticket, require NaN/positive/negative infinity in exterior and hole normalization to return Err; require malformed scan/encoder pins on central and peripheral requests to return Err without a panic or successful firmware package; preserve supported controller outputs. Optional private helper cleanup may parse with `if let Ok(pin)` and retain its existing unresolved marker, tested directly—but explicitly say public generation still rejects malformed requests. No support implementation rewrite or numeric-library migration is necessary.

## 06 — ZipWriter Drop and receipt integrity

**Verified against the locked primary source.** Core pins `zip = 9.0.1` ([`core/Cargo.toml:24`](../../core/Cargo.toml#L24), [`Cargo.lock:4509–4519`](../../Cargo.lock#L4509)); older cached zip sources are not authoritative. The installed registry source agrees with [zip 9.0.1 `write.rs`](https://docs.rs/crate/zip/9.0.1/source/src/write.rs):

- `finish(self)` calls fallible `finalize()?` before closing the writer (source lines 1295–1307). If that returns Err, the consumed writer still drops unfinished.
- Drop retries `finalize` if not closed and writes its error with `write!(io::stderr(), ...)`, not `eprintln!` (1606–1615). This is direct process stderr, so libtest's normal per-test output capture is not a sufficient defense.
- `finalize` writes the last file and central directory/footer (1428–1434); `abort_file` only removes one entry (940 onward), not the entire archive or Drop behavior. Context7's generated summary says “may fail silently”; the locked implementation above is stronger evidence and contradicts that shorthand.

Core's `pack` uses `?` for start/write/finish and a `BoundedWriter` whose later writes keep failing above the limit ([`archive.rs:243–297`](../../core/src/archive.rs#L243)). Thus [ticket 06](../plans/rust-best-practices/issues/06-silence-zipwriter-drop-stderr-on-limit-errors.md#L7) has a genuine teardown path. Existing size-limit tests already exercise small limits ([`archive.rs:592` onward](../../core/src/archive.rs#L592)); no fresh stderr run or INCOMPLETE receipt was produced in this research.

**Smallest safe direction.** Make size exhaustion sticky in the bounded sink: return the original size error once, then discard subsequent teardown writes without growing the backing Vec, while maintaining coherent logical Write/Seek positions. Ensure *all* packing error exits can drop safely, including a limit reached during consumed `finish`. Preserve failure at the API: no path may return the partial archive as success. This is a candidate requiring focused regression evidence, not a proven patch. Do not disable the limit and finish into an unbounded Vec, leak the writer with `mem::forget`, change process-global stderr, or upgrade zip solely to hide this message.

**Exact acceptance changes.** Add child-process stderr capture for limit failures during header/start, compressed data/entry close and central-directory finish; assert size error, no returned archive, no Drop diagnostic and no backing-buffer growth beyond the configured logical byte cap after failure. Keep successful roundtrip controls. Replace the receipt clause with “Run the supported `scripts/check.py test --receipt <path>` invocation (using README-supported argument ordering/options) and verify complete terminal observations and no ZipWriter Drop diagnostics”; Cargo alone creates no BoardStudio receipt. Receipt collection is explicitly opt-in in [`scripts/check.py:76–77,583–615,703`](../../scripts/check.py#L76). Do not present stdout sanitization or ignoring incomplete records as the archive fix.
