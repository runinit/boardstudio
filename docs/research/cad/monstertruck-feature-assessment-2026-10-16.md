# Monstertruck replacement assessment for the Cadrum CAD backend

Researched 2026-10-16 against BoardStudio `be319d54347d70613b746eef0e02cf3db0a0fd88` and a fresh clone of `virtualritz/monstertruck` at `d2ad1ed7aa420b7f32cd2c1e3ad319b46d593652` (`v0.4.1-3-gd2ad1ed`). The required destination is complete removal of OCCT and C++ from production, build, and required test paths. No application code was changed and no production build or benchmark was run.

## Qualification status after the initial assessment

The table below records the initial API assessment, rather than current qualification results. The [ongoing qualification record](monstertruck-qualification-2026-10-16.md) supersedes its historical corpus counts and unresolved support-policy description. The user selected complete OCCT/C++ removal, rejection of self-crossing supports, exact enforcement of the written support-owner cutoff, and millimetre defaults for missing STEP units with incomplete imports rejected.

The exact support check is implemented in Core and direct CAD validation with 52 focused tests passing; all 144 ordinary generated-support observations retain their old result. Frozen prism-v15 evidence passes all 53 generated STEP inputs. The fresh pole-v18 34-file vendor corpus has 15 strict-gate passes and 19 errors, unchanged statuses and retained bounds, with 16 fewer invalid and degenerate edges than v15. Those errors include mesh diagnostics and are not 19 parser failures. Browser and generated-input results remain tied to their earlier snapshots. Boolean closure and several trimmed-surface meshes remain unresolved. Browser, independent Rust validation, cache ownership, and full feature-port work are separate gates. Production still uses Cadrum, and the final no-OCCT/C++ requirement is not met.

## Finding

The user's2026-10-17 [scope decisions](../../plans/cad-backend-replacement/map.md#scope-decisions-2026-10-17-user) amend this historical assessment. Exact geometry and STEP are required only for generated cases and PCBs, through013 layered line/arc construction and direct planes/cylinders/cones. PCB outline plus drilled holes at board thickness is included.009 keycaps use appearance/optional-print meshes, with displaced dishes and separate mounts/legends; exact keycap STEP and004 cutters are excluded. General exact3D Booleans are off the critical path;006 adopts013 and closes demonstrated remaining feature gaps. The API inventory/table below remains historical research, not a mandate to implement obsolete routes.

Vendor STEP uses tolerance-bounded meshes for display, alignment and basic collision validation, preserving original bytes, source geometry/face information and every part/occurrence with correct units and placements. Incomplete imports remain errors; missing units default to millimetres. Repairs remain bounded by applicable authenticated source precision. The user approved supported tolerance bands by default and refinement on demand on2026-10-17, with0.01 mm reserved for an explicit tighter check; insufficient accuracy remains uncertain.014 owns intersection/clearance/contact queries and those bands. Exact-solid vendor import is not universal. See [007](../../plans/cad-backend-replacement/issues/007-strict-step-import.md) and [014](../../plans/cad-backend-replacement/issues/014-vendor-mesh-collision-validation.md). Historical strict-gate results are not new asset-contract passes. OCCT/C++ removal and applicable independent accuracy checks remain mandatory.

Monstertruck has the basic ingredients for a Rust B-rep replacement: profile/wire and surface builders, extrusion/revolution, B-rep solids, CSG, STEP I/O, tessellation, and bounds. That establishes a plausible implementation route; it does not establish feature parity. BoardStudio's operations use Cadrum types directly in case construction, caches, and keycap generation, so this is a port of the builders and cache ownership as well as a replacement of the `CadKernel` implementation.

The most consequential gaps are already evidenced: Monstertruck's STEP reader passed only 16 of 33 vendor files under the earlier strict measurement gate, and the BoardStudio gasket experiment failed or timed out at the first circular mounting-hole cut. The first is importer/adapter qualification; the second is a generated-geometry boolean failure. Neither is fixed by available API names. Complete removal also requires removing the Cadrum build/oracle path and proving the selected Monstertruck dependency graph builds for the BoardStudio WASM/native targets without C++.

## What “remove C++ completely” entails

Two implementation details need explicit treatment rather than a mechanical
type substitution:

- **Cache copies:** Monstertruck vertex and face `Clone` share their underlying
  geometry through `Arc`; `builder::clone` creates another topology with copied
  geometry. Cadrum's staged cache assumes its ordinary `Solid::clone` isolates
  mutations. Select and test the appropriate copy operation before porting
  that cache; pointer sharing alone is not a failure if all operations preserve
  immutability. [Vertex cloning](https://github.com/virtualritz/monstertruck/blob/d2ad1ed7aa420b7f32cd2c1e3ad319b46d593652/monstertruck-topology/src/vertex.rs),
  [face cloning](https://github.com/virtualritz/monstertruck/blob/d2ad1ed7aa420b7f32cd2c1e3ad319b46d593652/monstertruck-topology/src/face.rs),
  [mapped topology clone](https://github.com/virtualritz/monstertruck/blob/d2ad1ed7aa420b7f32cd2c1e3ad319b46d593652/monstertruck-modeling/src/builder/mod.rs).
- **Material checks:** current tests use Cadrum `Solid::contains` to detect
  material missing from roofs, sockets and walls, and compare both directions
  of solid subtraction. Monstertruck's inspected `Inside` analyzer is for
  polygon meshes; replacing those checks with the candidate's own coarse mesh
  would weaken the evidence. Preserve independent analytic/material checks or
  qualify an appropriately accurate solid classifier. For the production
  support-containment check, a separately proved planar containment/area
  calculation could avoid needing a general B-rep mass-property implementation:
  both operands are unit-height prisms. This is a candidate approach, not an
  established equivalent; input precision and the existing threshold must be
  preserved. [Mesh inside analyzer](https://github.com/virtualritz/monstertruck/blob/d2ad1ed7aa420b7f32cd2c1e3ad319b46d593652/monstertruck-meshing/src/analyzers/in_out_judge.rs),
  [current containment check](../../../cad/wasm/src/model/construction.rs),
  [material equivalence checks](../../../cad/wasm/src/model/construction/equivalence.rs).

In this assessment, exact CAD means retaining the boundary-representation
geometry and existing accuracy requirements, rather than replacing curved
solids with preview triangles. It does not imply symbolic or infinite-precision
volume computation. Likewise, the sampled keycap corners and font outlines
already used by BoardStudio remain the intended profiles.

Upstream has a usable Rust-only subset boundary: the umbrella crate's default features are `modeling` and `meshing`; `solid`, `step`, and `assembly` are separately selectable; GPU and rendering are optional and the broad `full` feature enables them. `monstertruck-solid`'s default boolean implementation is the Rust `marching-ssi` backend. A narrow standalone Cargo metadata probe for the candidate modeling/solid/meshing/STEP feature set resolved 111 WASM-target packages and 102 native-target packages, with no `cc`, `cmake`, `bindgen`, `cxx`, `cxx-build`, `cadrum`, `occt`, or `opencascade-sys` packages. Metadata reports Rust-level `links` values for `rayon-core` and `wasm_bindgen`; multiple Rust build scripts are present in the transitive graph. This is positive dependency-resolution evidence only: no compile/link check was done, and the probe excludes BoardStudio host/build dependencies and the optional Monstertruck healing crate. Details and exact lockfiles are in the gitignored `.evidence/monstertruck-feature-assessment/` directory.

To meet the hard requirement, BoardStudio must select a narrow feature set (do not enable `full`, `gpu`, or `render` without need), then verify all of the following after the integration exists:

1. Re-run `cargo tree` and inspect metadata for the integrated BoardStudio WASM and native/test targets; the narrow probe has no C/C++ CAD packages, but it is not the eventual application graph. Inspect build-dependencies and target-specific dependencies as well as normal dependencies, then verify the actual native and WASM links.

## Recommended qualification order

Historical recommendation below is superseded by the current map:013 layered cases/PCBs →006 adoption, with008 exact export in parallel;009 mesh keycaps and007/014 vendor assets/collision converge at010 browser integration →011 performance →012 removal.
