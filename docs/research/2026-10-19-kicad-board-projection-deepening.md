## Recommendation

**Narrow the initial Strong candidate to a moderate, bounded parsing/projection-locality refactor.** The preview module already hides substantial interpretation behind a small interface. Its length alone is not a defect. The evidenced opportunity is repeated parsing of the same original board by preview and exact extraction, with callers coordinating the results. Introduce only private parsed-board ownership/reuse inside Core's artifact module; retain separate preview and exact projection policies. Do not create a common geometry framework, force a single traversal, or merely relocate the large function. Evidence: [`board_source`](../../core/src/artifact/preview.rs#L416-L537), [`read_board_source`](../../core/src/artifact/mod.rs#L28-L50), [`extract_board_source`](../../core/src/artifact/mechanical_extract/board_source.rs#L20-L102), and [`import`](../../core/src/artifact/module_import.rs#L68-L278).

**Proposed decision:** parse the original board once per relevant artifact operation; let preview and exact extraction consume that same validated root and original text under private artifact visibility. Keep existing top-level artifact request/reply shapes. Module import already needs the root for its circuit and must reuse it rather than parse again for each projection. A small private parsed-board owner is justified only if the old parse/root-selection paths are removed; a wrapper retaining every old raw-source path fails the deletion test. The compatibility footprint constructed during module import is a separate input and is not covered by “original board once.” This is a refactor proposal, not a measured speed claim.

## Duplicated rules versus legitimate differences

1. **Share syntax ownership, not acceptance policy.** Three modules parse/select the same board root. Their existing error categories/messages and ordering differ: preview uses ParseError, module import uses Validation, exact extraction distinguishes parse errors from validation. A private common parsed representation must preserve each public route's observable envelope; it must not silently standardize diagnostics. [Preview error](../../core/src/artifact/preview.rs#L7-L9), [import error/root selection](../../core/src/artifact/module_import.rs#L7-L9), [import parse](../../core/src/artifact/module_import.rs#L77-L85), [mechanical errors](../../core/src/artifact/mechanical_extract.rs#L697-L703).
2. **Coordinate conventions overlap, but validation differs.** Preview and mechanical points invert KiCad Y; pad anchors are footprint-local while pad angles are board-frame absolute. Preview transforms the anchor once and uses the pad angle; exact extraction transforms the anchor and rotates the drill offset by the absolute pad angle, including B.Cu. Preserve these rules; do not sum footprint and pad angles or mirror the source twice. [Preview pose/transform](../../core/src/artifact/preview.rs#L39-L66), [preview pad](../../core/src/artifact/preview.rs#L272-L342), [mechanical point](../../core/src/artifact/mechanical_extract.rs#L664-L676), [exact drill placement](../../core/src/artifact/mechanical_extract/board_source.rs#L600-L673). **Proposed decision:** leave these arithmetic implementations intact in this first slice; concentration of parsing does not establish that their differently validated parsers are interchangeable.
3. **Preview approximation is not exact PCB geometry.** Preview joins near endpoints within 0.002 mm and emits sampled contours; exact extraction uses exact endpoint equality and retains authored curves/identities and named ambiguity refusals. [Preview contours](../../core/src/artifact/preview.rs#L371-L410), [exact chaining](../../core/src/artifact/mechanical_extract/board_source.rs#L342-L399), [exact equality](../../core/src/artifact/mechanical_extract/board_source.rs#L578-L580). Do not consolidate these tolerances.
4. **Thickness defaults are deliberately not source facts.** Preview displays 1.6 mm by default but returns optional authored thickness separately. Direct board read preserves missing thickness. Module import separately treats absent/nonpositive/nonfinite thickness as unknown and adds a gate; imposing the preview's upper limit on that metadata path would change behavior. [Preview thickness](../../core/src/artifact/preview.rs#L428-L437), [module thickness/gate](../../core/src/artifact/module_import.rs#L111-L114), [gate](../../core/src/artifact/module_import.rs#L178-L184), [regression](../../core/tests/module_import.rs#L509-L541).
5. **Graceful import and strict direct read differ intentionally.** Direct read refuses an incomplete exact source; module import retains source provenance and circuit data with mechanical gates. Preview alone can approximate unsupported custom pads and emit diagnostics, while physical extraction refuses unresolved via spans. [Read orchestration](../../core/src/artifact/mod.rs#L40-L50), [import exact gate](../../core/src/artifact/module_import.rs#L208-L221), [preview approximations](../../core/src/artifact/preview.rs#L294-L311), [physical via policy](../../core/src/artifact/mechanical_extract/board_source.rs#L677-L737), [provenance/gating tests](../../core/tests/module_import.rs#L244-L294).
6. **Model and artwork projection has no evidenced exact-extraction counterpart.** Preserve model path values, IDs/order, reference fallbacks, side, pose, offset/rotation/scale and hidden-model exclusion without introducing a model-path normalizer. Preserve raw-span-aware text decoding and distinct board versus footprint fabrication-layer filtering. [Models](../../core/src/artifact/preview.rs#L454-L490), [text decoding](../../core/src/artifact/preview.rs#L13-L24), [graphic filtering/text](../../core/src/artifact/preview.rs#L174-L259), [footprint surfaces](../../core/src/artifact/preview.rs#L540-L579).

## Proposed module change and deletion test

Scope reaches the artifact dispatcher/direct read, preview, exact board extraction, module import and their regression tests. Generated preview remains a caller of the existing preview operation; source-footprint artwork remains a caller of the existing graphic projection, not a board parser. No exported contracts, persisted schema, generator settings or dependencies need change. [Artifact request/reply variants](../../core/src/model.rs#L2409-L2513), [generated preview](../../core/src/artifact/kicad/output.rs#L10-L30), [footprint projection entry](../../core/src/artifact/mod.rs#L53-L58).

- **Proposed decision:** use the smallest private parsed-board representation necessary to keep original source spans and the parsed document alive together; no owned normalized copy of every form, public AST contract, trait, pluggable adapter, lazy cache or generic visitor.
- **Proposed decision:** original-source parsing/root selection is owned once; preview and exact projection use that root without calling the parser themselves when it is already available. Preserve preview limit checks before expensive preview parsing on raw-source entry routes. Reuse module import's existing parsed root without imposing a new whole-import cap or changing its error order.
- **Proposed decision:** keep exact extraction's current curve/ownership/drill algorithms, module import's compatibility contour tessellation/centering, and preview's current graphical traversal. Two projections over one AST are legitimate; merging traversals is not a requirement.
- **Deletion test:** removing the proposed owner should force parse/root lifetime/coordination back into direct read and module import. If removing it only removes pass-through methods, reject that design. The implementer must show removal of duplicate original-source parses/root selection, not claim success by moving the 122-line function. Net line savings and runtime savings are **unknown** until a real diff/measurement; neither is an acceptance threshold.
- **Not recommended now:** deleting module import's synthetic-footprint compatibility path. Its 0.02 mm tessellation determines the center; exact bounds intentionally do not replace that frame. Changing it risks placement and legacy compatibility. [Compatibility construction/center](../../core/src/artifact/module_import.rs#L115-L207), [shared-frame rationale](../../core/src/artifact/mechanical_extract/board_source.rs#L85-L98).

## Architecture constraints

- Rust/Core remains the owner; do not reintroduce a JavaScript generator or worker round trip. Generator parameter declaration/type/name checks are unaffected and must not migrate into projection. [ADR-0003](../adr/0003-rust-footprint-generators-in-core.md#L5-L20), [ADR-0009](../adr/0009-generator-parameters-checked-in-core.md#L14-L39).
- CAD migration requires exact case/PCB geometry and source-complete behavior, not preview meshes as replacement solids. The approved scope includes PCB outline plus drilled holes at thickness. [CAD scope](../plans/cad-backend-replacement/map.md#L7-L17).
- Geometry/cross-crate changes require one combined spec+standards review at closure; limits, source preservation and allowances remain unchanged. No new tolerance budget or repair policy is authorized. [Closure decisions](../plans/cad-backend-replacement/map.md#L27-L35).
- Persisted-outline fabrication-grid validation is a separate rule; do not reinterpret ADR-0012 as permission to snap imported exact source curves or replace preview endpoint tolerance. [ADR-0012](../adr/0012-bounded-outline-validation.md#L4-L17).
- Use the current glossary's Board, physical board instance, accepted document and footprint generator vocabulary. This work is stateless artifact projection, not an accepted-document edit. [Glossary](../../GLOSSARY.md#language), [board vocabulary](../../GLOSSARY.md#mechanical-relationships), [stateless artifact request](../../core/src/artifact/mod.rs#L60-L91).
