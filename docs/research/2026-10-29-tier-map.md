## 4. `check.py quick` as the PR-gate engine (ticket 09 work items)

1. **Diff base must be the PR base SHA, not `main`.** `changed_files()` hard-codes
   `base="main"` (`scripts/check_quick.py:64`) and takes no base argument
   (`scripts/check.py:675-683`). On a stacked branch the merge-base with `main`
   is ancient, so a stacked diff against `main` selects nearly everything.
   Ticket 09: `changed_files(root, base)` with base from `--base` /
   `BOARDSTUDIO_QUICK_BASE`, wired to `github.event.pull_request.base.sha`.
2. **Fix the checkout depth so the base exists.** All three `actions/checkout`
   steps (`.github/workflows/check.yaml:23,44,90`) set no `fetch-depth`, so the
   default depth-1 clone has no `main`/`origin/main`; `changed_files` then falls
   back to `"HEAD"` (`scripts/check_quick.py:64-66`) and selects only dirty
   files — a silent near-no-op gate in CI. Ticket 09: `fetch-depth: 0` (or an
   explicit `git fetch origin $BASE`) before computing the diff.
3. **Build lane (conflict resolved).** `quick` skips builds by design while the
   gate keeps build → build runs as an explicit `build --fast` lane in the web
   job ahead of the drag smoke (reusing `run()`'s build-before-smoke insert,
   `scripts/check.py:543-567`), not inside `quick_plan`'s affected selection.
   `release` stays main/dispatch-only (existing `release-build` gating).
4. **Count-guard accounting.** `missing()` checks only binaries the run executed
   on partial runs, but fails a run binary whose baselined names didn't execute
   (`scripts/check_native_tests.py:146-156`) — a smoke-filtered PR run would go
   red on the guard. Ticket 09 must teach the guard the smoke manifest (or skip
   it unless the run executed full binaries); every moved test stays in the
   baseline until ticket 11 proves removal, then re-baselines via
   `--update-native-baseline` on a green FULL run.
5. **Triggers and job names.** Tier only on `pull_request` (quick path); `push`
   to `dev`/`main` and `workflow_dispatch` run today's default full plan.
   Job names `native`, `web`, `release-build`, `release-deploy` and
   `release-build: needs: [native, web]` (`.github/workflows/check.yaml:17-21,90-92`)
   stay byte-identical so required checks keep resolving.

## 5. Smoke-set rule (agent-applyable, no judgment calls)

**Rule SMOKE-1.** For each native baseline binary and each browser crate launch,
the PR-gate smoke test is the test minimizing `(median warm wall time, test
name)` among tests that killed ≥1 mutant in the accepted kill matrix; ties break
by lexicographic test name. **Rule SMOKE-2 (diversity).** No two smoke tests may
have identical kill sets unless each is the sole killer in its binary/launch.
**Rule SMOKE-3 (unpinned).** Binaries/launches with no kill-matrix data use the
lexicographically-first executed test as a placeholder smoke AND are recorded
`unpinned` in the manifest; placeholder smokes are tripwires, not proven killers.
The kill matrix + timings live in a checked-in manifest (suggested
`scripts/smoke-manifest.json`) that the gate loads; ticket 11 backfills it.
Any test absent from the manifest runs full (untiered = gate).
