# 08: Dead-dependency inventory (research findings)

Date: 2026-10-29. Branch: `research/dead-deps`. Ticket: `docs/plans/ci-wall-time/issues/08-dead-dependencies.md`.
Scope verified: 18 workspace members (`Cargo.toml:3-22`) plus `cad/wasm` (own workspace/lockfile;
excluded at `Cargo.toml:23-27`), 427 locked packages in the root `Cargo.lock`
(`grep -c "^name = "` = 427), 177 in `cad/wasm/Cargo.lock`.

## Method

`cargo metadata --no-deps` dependency enumeration for every workspace member, then a
cfg-agnostic textual reference search per direct dependency: word-boundary grep for the
crate ident (`-` → `_`, honoring cargo-metadata `rename`, e.g. the `dioxus-primitives`
`package =` rename) over every `.rs` file that can compile as part of that crate —
`src/`, `tests/`, `examples/`, `build.rs`, including `#[path]`-included files — covering
all targets, cfgs, and features simultaneously. A hit under ANY cfg disqualifies the item,
per the ticket's rule. Zero-hit candidates were then cleared against four false-positive
traps (each documented per item):

1. derive-only `serde` (derive macros emit `serde::` paths without naming the crate) —
   ruled out by a second grep for `Serialize|Deserialize|serde::`;
2. `dep:` feature entries with no code use (`web/Cargo.toml:22`, `web/Cargo.toml:24`);
3. cross-crate `#[path]` includes (`web/crates/host/src/lib.rs:21`,
   `web/crates/host/src/boundary_parity.rs:11` include `core/tests/support/*`, which use
   only `boardstudio_core` + `serde_json` — both host deps under the `page` feature);
4. a `rename`-with-dash grep bug that initially flagged `dioxus-primitives` (actually
   used: `web/crates/layout/src/objects/matrix_setup.rs:7`,
   `web/crates/layout/src/setup_guide.rs:8`, `web/crates/ui-shared/src/controls.rs:9`).

Alternate-path reachability for every removal candidate was spot-confirmed with
`cargo tree --target wasm32-unknown-unknown -i` (wasm32 target installed).

## Headline

**16 removable dependency edges, 0 packages evicted from any lockfile, ~0 predicted
PR-gate wall saving.** Every candidate package stays reachable in every build graph via
another workspace edge (details per item), so no compile unit leaves the full-page,
full-workspace, or per-crate graphs, and `Cargo.lock` is unchanged by any single removal.
Value is manifest hygiene + smaller audit surface, not wall time. Removals still must land
after 03's warm baseline per the map's standing rules and re-measure after.

## Ticket leads: disposition

- **Unused `renderer/vendor/cgmath-0.18.0` fallback — ALREADY GONE, no action.**
  `renderer/vendor/` contains only `cgmath-next-0.18.1/` (+ `cgmath-next-security.json`,
  `README.md`); no `cgmath-0.18.0` directory exists. The root `[patch.crates-io]`
  (`Cargo.toml:29-30`) points at the vendored `cgmath-next`, and the `Cargo.lock` `cgmath
  0.18.0` entry carries no `source =` line (path-patch signature). The stale fallback was
  removed before this checkout; nothing to itemize.
- **Full-catalogue loading — NOT a Cargo dependency; re-scope as asset/build follow-up.**
  `web/crates/catalogue/src/catalogue.rs:8-11` embeds `catalogue/parts/imported-parts.json`
  (314,020 bytes) via `include_str!` and `load_bundled` (`catalogue.rs:95`) parses the whole
  file per (reversible) variant behind a hash-keyed cache (`catalogue.rs:96-113`), so every
  catalogue consumer pays full-parse + binary bloat. Separately, `scripts/build-web.py:77-78`
  copies the 43 MB / 1,371,473-line `catalogue/modules/imported-modules.json` into site
  assets on every page build. Neither is removable as a dependency edge; both want a
  lazy-loading / split-catalogue follow-up ticket with its own measurement.
- **Repetitive mechanical-settings field definitions — NOT a dependency; code-dedup
  follow-up.** `web/crates/case/src/mechanical_settings.rs` is 7,911 lines with
  `mechanical_settings_controller.rs` (1,997), `mechanical_settings_mount.rs` (1,780), and
  `mechanical_pair.rs` (1,945) alongside; shared-control migration already absorbed the
  field primitives (per project memory), so what remains is per-field wiring repetition.
  No Cargo edge involved; needs a dedup ticket, not a removal.

## Limits

- No `cargo check`/`clippy`/test runs (read-only ticket; verification is textual +
  `cargo metadata`/`cargo tree` resolution only). Each removal still needs its own
  follow-up commit with a green full gate per the map's standing rules.
- Feature-powerset builds were not enumerated; instead the search is cfg- and
  feature-agnostic (a hit under any gate disqualifies), which is strictly conservative
  for the ticket's "no feature/cfg combination references it" bar — except generated code:
  only `runtime/build.rs` generates code and it uses `boardstudio_core` + std only.
- Proc-macro/derive indirection was cleared only for the `serde` items (the one case where
  use-without-naming occurs in this tree); all other zero-hit items are function/type
  crates that must be named to be used.
- Predicted saving is structural (lockfile/graph unchanged — verified, not timed); no
  before/after wall receipts were taken, and none would be meaningful for edge-only removals.
