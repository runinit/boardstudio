# Matrix layout dependents inventory

Date: 2026-10-22. Source-only inventory for the proposed ergogen-parity matrix layout rework. The comparison baseline is [ergogen-layout-engine-comparison.md](2026-10-22-ergogen-layout-engine-comparison.md); that document records current formulas and measured differences. This file maps the BoardStudio contracts that must survive semantic changes.

Risk means risk of behavior/data breakage if a new formula or model is introduced without migrating or adapting the named consumer. **Critical** means identity, wiring, accepted geometry, or mirrored reconciliation can be corrupted; **high** means user-visible geometry/edit behavior changes; **medium** means projection or documentation drift.

## 1. Persisted model and geometry contract

| Existing contract | Source and current assumption | Risk |
|---|---|---|
| `Matrix` is a persisted rectangular `rows × columns` grid with positive uniform `pitch`, world `origin`, optional matrix `rotation`, local X/Y `mirror`, `edgeGap`, board/definition/part ownership, diode direction, and sparse parameter vectors `rowOffsets`, `columnOffsets`, `columnStaggers`, `columnSplays`, `columnOrigins`. Serde uses camelCase field names, defaults missing vectors, skips empty vectors, and denies unknown matrix fields. | `core/src/model.rs::Matrix`; `core/src/matrix.rs::valid_matrix`, `valid_projection_matrix`; `core/src/validate.rs`. Existing layout validation also requires each `Layout` to own a distinct matrix on its board (`core/src/matrix/layout.rs::validate_layouts`). | **Critical** for schema and geometry. New cumulative fields need defaults/validation and old vector semantics retained or explicitly migrated. Anchors cannot silently relax the distinct-layout ownership rules. |
| A `MatrixCell` is a sparse exception keyed by `(row,column)`: enabled/deleted state, optional definition/variant, local-frame offset and rotation, plus `assemblies` and optional `assembliesLocal`. Deleted is a tombstone; absent cell means default enabled cell. | `core/src/model.rs::MatrixCell`; `core/src/matrix.rs::project_matrix`, `set_matrix`; `core/src/matrix/deletion.rs`. | **Critical**: cell identity is coordinate-derived; additions to cells must preserve sparse/default/tombstone behavior and local offset meaning. |
| `MatrixAssembly` stores companion identity/definition, key-local offset, optional relative turn, and side. | `core/src/model.rs::MatrixAssembly`; `core/src/matrix.rs::set_matrix`; `core/src/matrix/layout.rs::assembly_placements`. | **High**: changing key frames changes the rigid transform applied to diode/LED and other assemblies. |
| `location()` first sums independent row/column/key offsets with uniform pitch and cumulative stagger, then applies splay pivots from selected column down through zero, local mirror, matrix rotation, and world origin. Key heading is matrix rotation + cumulative splay (negated by either mirror) + cell rotation. | `core/src/matrix.rs::location`, `column_rotation`, `column_basis`, `project_matrix`. | **Critical**: this is the root geometry kernel. Current assumptions are additive independent offsets, uniform pitch, rectangular coordinates, absolute custom pivots, and one free-standing matrix frame. Every derived pose must agree with the replacement kernel. |
| Stable primary member IDs are `matrix/<id>/r<row>c<column>`; companions append `/<assembly-id>`. IDs deliberately encode stable coordinates, not array order. | `core/src/matrix.rs::member_id`, `companion_id`; consumers in electrical, keymap, mirror, and UI modules below. | **Critical**: changing IDs or renumbering on layout edits breaks bindings, nets, constraints, archive references, and mirrored correspondence even if geometry is unchanged. |
| `edgeGap` is a per-matrix clearance and must remain smaller than pitch; it is not the point spacing itself. | `core/src/matrix.rs::valid_matrix`; `web/crates/layout/src/mirrored_pair_geometry.rs`; keycap and canvas projections. | **High**: users expect clearances and key bounds to remain consistent when pitch/layout formulas change. |

Current formulas and ergogen comparison: `docs/research/2026-10-22-ergogen-layout-engine-comparison.md` (especially “How a BoardStudio matrix is laid out”, “Propagation”, and D1–D9). That source confirms the current engine has no per-key cumulative orient/shift/rotate/padding, no inherited horizontal spread, absolute custom splay origins, additive rather than replacement precedence, and no matrix-to-matrix anchor field.

## 2. Core edit paths and preservation behavior

| Edit or operation | What it does/preserves | Assumption and rework risk |
|---|---|---|
| `SetMatrix` | `core/src/lib.rs::apply` → `core/src/matrix.rs::set_matrix`. Rebuilds live switch and companion parts from the matrix, retains compatible existing parts and identity/reference/metadata, remaps connected pads when a switch definition changes, cleans removed membership from boards/nets/constraints/outlines, and calls `layout::sync`. Shrinking dimensions truncates only parameter vectors that were no longer extended beyond prior bounds; cells outside old bounds are filtered. Authored companions are carried by `matrix::placement::carrying_authored_companions`. | **Critical**. Incoming payload and regenerated parts must agree on the new pose rule. Preserve IDs, unrelated authored metadata, nets and constraints during rebuild. New parameter fields need resize/truncate policy. |
| `SetMatrixSplay` | `core/src/matrix/splay.rs::update`; the `SetMatrixSplay` arm in `core/src/lib.rs::apply`. `Origin` accepts a world point, converts it into the pre-splay matrix frame, sets a custom origin, then `preserve_columns` writes compensating `columnOffsets` to this and every later column so key poses do not move. Angle `Following` changes this and later column headings; `Column` compensates the next column's angle and writes offsets to later columns so only the chosen column changes. Authored companions carry; constrained companions remain solver-owned. | **Critical**. This preserves current poses by materializing hidden offsets/counter-angles. A relative-origin redesign must define how existing absolute origins and compensation vectors migrate, and preserve “This column” behavior. |
| `SetMatrixPlacement` | `core/src/matrix/placement.rs::update`; typed `MatrixPlacementChange` in `core/src/model.rs`; `core/src/lib.rs::apply`. Absolute-value edits set a single stagger/column offset/row offset. Column stagger is inherited by later columns; offsets remain independent. `ColumnOffsetToStagger` transfers Y into current stagger, subtracts it from next stagger, clears the offset, and is refused when it would move geometry (default-origin splay). No-op is valid. Authored companions carry and only moved IDs are reported. | **High**. New cumulative shift/spread changes what “one entry” affects. Preserve old conversion as a one-shot geometry-preserving action or document and migrate its eligibility. |
| `MoveParts` on matrix keys | `core/src/matrix/layout.rs::move_keys`, called by `core/src/lib.rs::apply`. Converts world delta through inverse matrix rotation, mirror and cumulative splay into a `MatrixCell.offset`; older absolute pose overrides are absorbed into this parametric offset. Carries authored key companions by the same world displacement; constrained keys remain solver-owned. Moving both linked halves at once is refused. | **Critical**. Current inverse assumes cell offset is in column/splay frame and not key-rotation frame. With cumulative transforms, inverse mapping must select the key’s effective frame and update the correct local parameter without moving later keys unexpectedly. |
| Disable vs delete cell | `SetMatrixCellsEnabled` keeps slot/identity semantics but excludes generated members; `RemoveMatrixCells` / `RemoveSelectedMatrixCells` tombstones the coordinate and removes generated parts/dependencies. | **Critical**. Disabled slots keep rectangular coordinate numbering; tombstones must not create snapping geometry or silently transfer old metadata. |
| Remove row/column (compaction) | `core/src/matrix/deletion.rs::remove_axis` shifts all later row/column numbers and associated part IDs (including companions) down by one; removes the corresponding row/column parameter entry, updates both linked matrices, remaps constraints/nets/outline sources/board ownership, rebuilds via `set_matrix`, then syncs. Removing the only axis removes the whole matrix. | **Critical**. Coordinate IDs are renumbered here by explicit simultaneous remapping; anchors and new per-key parameters must be remapped or detached deliberately. A copied numeric anchor can otherwise retarget to the next key. |
| Remove matrix / setup | `core/src/lib.rs::apply::RemoveMatrix`; `web/crates/catalogue/src/matrix_setup_operation.rs::{prepare_matrix,next_matrix_id}`; `web/crates/layout/src/objects/matrix_setup_controller.rs`. Setup currently seeds a rectangular grid at 19.05 mm pitch, with configured key/diode/LED assemblies and `edgeGap`; actual creation goes through `SetMatrix`. | **High**. Keep setup defaults, generator definitions, assembly choices and matrix ownership. New fields need a backward-compatible neutral seed. No KLE point-layout importer or full ergogen points importer was found in the searched Core/web import routes; `core/src/migrate.rs` only renames legacy Ergogen library IDs, not layouts. |

`SetMatrix`, splay, and placement also participate in mirrored-half canonicalization/inverse mapping: `core/src/mirrored_half/inverse.rs`, `hosted.rs`, and `reconcile/{prepare.rs,mod.rs}`. Treat typed operation shapes, operation IDs, changed-ID reporting, undo/replay, and dual-edit conflict rules as compatibility surface, not just the stored `Matrix` struct.

## 3. Mirrored and linked halves

| Feature | Source and current contract | Risk |
|---|---|---|
| Pair reflection | ADR-0008 (`docs/adr/0008-linked-halves-stay-linked.md`) declares matrices (cells, stagger, offsets, splay), keys, layouts, assemblies, wiring, boards, and mechanical features linked. ADR-0010 (`docs/adr/0010-mirrored-half-is-a-core-maintained-reflection.md`) stores a full reflected copy and re-derives after accepted edits/Open; mirror edits inverse-map to source. Numbering is retained: same row/column means same physical key/pins. | **Critical**. A rework must reflect every new parameter and anchor dependency deterministically and keep numbering stable. An inter-matrix anchor can cross pair ownership and needs explicit reflection/inverse rules. |
| `layout::reflected` | `core/src/matrix/layout.rs::reflected` copies rows/columns/pitch/edge gap/origin/rotation/mirror/diode direction and all offset/stagger/splay/origin vectors. It flips cell turn and assembly handedness while retaining source cell coordinates. It refuses local `Mirror::Y` for linked pairs. | **Critical**. Add new persisted layout fields here, and specify anchor mapping; a mirror matrix must not keep an anchor to the source key unless that is intended. |
| Synchronization | `layout::sync` regenerates paired matrix from source. `layout::sync_components` reflects linked independent companions. Reconciliation and lifecycle logic in `core/src/mirrored_half/{reconcile.rs,lifecycle.rs,matrix_addition.rs}` maps member IDs, coordinate shifts, deletions, constraints, circuits and persisted correspondence. | **Critical**. Geometry that depends on another matrix requires dependency ordering, cycle handling, closure updates, and source/mirror association across sync, reconcile, undo, Open, and deletion. |
| Exceptions/local companions | Pair members default linked; explicit Local/Omitted exceptions remain item-scoped (ADR-0010, `core/src/mirrored_half/reconcile.rs`). `assembliesLocal` allows a half to keep local diode/LED choices; newly created mirror cells inherit that half's local preset. Components use `boardstudio.mirroredComponentSource` links and can be substituted/local. | **High**. Preserve per-item exceptions and avoid forcing anchor updates or regenerated companions through a local/omitted item. |
| Mirror pose rules | Matrix mirror toggles `Mirror::X`; pair reflection maps matrix origin/heading; keys negate cell rotation; companions reflect local X offset and angle. Independent non-key components use a distinct full-heading rule (`layout.rs::reflected`, `sync_components`; ADR-0010 amendments). | **Critical**. New cumulative headings affect switches and companion transforms differently. Keep generator parameters unchanged and test heading/side/pad identity for rotated pair maps. |

## 4. Companions, constraints, and offsets

| Feature | Source and assumption | Risk |
|---|---|---|
| Diode/LED assemblies | `MatrixAssembly` entries generate `matrix/<matrix>/r<r>c<c>/<assembly>` parts. `core/src/matrix.rs::set_matrix` places offset in the key heading frame and adds assembly rotation. Setup presets create MX/Choc solder/hotswap/RGB combinations in `web/crates/catalogue/src/matrix_setup_operation.rs`. | **Critical** for footprint placement and electrical scan; preserve assembly IDs, local offset/rotation/side, and generated child IDs. |
| Companion placement modes | `core/src/matrix/layout.rs::companion_mode`, `assembly_placements`; `MatrixScene.companions` in `core/src/model.rs`. Precedence: explicit constraint → authored pose → follows key. `core/src/matrix/placement.rs::carrying_authored_companions` rigidly moves Authored companions when matrix geometry changes; constrained companions are settled by solver. | **High**. Do not collapse authored offsets into the new key transform or override constraints. Scene and solver must classify identically. |
| Part-offset constraints | `core/src/constraints.rs::pose`, `retune_offset`, `core/src/part_offset_constraint.rs` and `core/src/matrix/layout.rs::move_keys`. Constraints use Part IDs as endpoints and can constrain a key or assembly to another key/part; `PartOffset`/`Offset` offsets use their own frame/axis contract. | **Critical**. A key anchored to another matrix can already be a constraint endpoint in principle, but it is not the same as a matrix-level anchor. Deletion/compaction must remap or remove endpoints; solver must place against final source pose. Preserve frame-specific offsets. |
| Outline dependencies | `OutlineFeature::PartEnvelope`, `outline_controls`, outline versions and constraints can reference key/companion part IDs. `core/src/matrix/deletion.rs::remap_parts` detaches or prunes removed identities in the same edit. | **Critical**. A moved key changes envelope and clearance geometry; anchor/member deletion must never silently retarget authored outline control points. |

## BoardStudio-only extended features that must be preserved

- **Independent** row, column, and key offsets (`rowOffsets`, `columnOffsets`, `MatrixCell.offset`) alongside inherited stagger; these are established meanings, not redundant ergogen aliases.
- “This column” splay (`MatrixSplayAffect::Column`) and its geometry-preserving compensation behavior.
- Editing a custom splay origin in world space while preserving every key pose by adjusting column offsets.
- Local in-place X/Y mirror, including Y mirror support for unpaired matrices; linked halves currently reject Y mirror.
- Persisted, continuously synchronized linked mirrored halves with inverse edits, same physical key numbering, and Local/Omitted exceptions.
- Per-cell switch definition/variant overrides, deleted tombstones, per-key diode/LED assemblies, local companion assignments, authored companion poses, and explicit constraints.
- Stable coordinate member IDs and deterministic electrical row/column topology independent of geometry.
- Geometry-preserving offset-to-stagger conversion, with Core-owned eligibility check and one-step undo.
- Core-authored scene axes, draft projection without member IDs, actual projection using materialized part poses, and changed-ID/undo contracts.

## Hidden compatibility traps

1. **Compensation is persisted state.** Splay-origin and “This column” gestures write offsets/counter-splay values. These values look user-authored but encode pose preservation; a new origin/spread model must detect and migrate or retain them.
2. **The same saved fields have stable semantics.** Stagger inherits; row/column offsets do not. Reinterpreting offset as cumulative shift silently changes existing projects and makes Inspector/Relations values lie.
3. **Coordinate IDs are domain identity.** They are embedded in nets, bindings, constraints, board/matrix/layout membership, references, companions, outline controls, mirror correspondence and selection state. Geometry parity does not compensate for changed IDs.
4. **Parts are materialized, not computed only at display time.** Export, collision, outline and mirrored workflows often read stored `Part.pose`; changing `location()` without updating `set_matrix`, drag inverse, reconcile, and draft/actual projection creates split geometry.
5. **Mirror reflection is more than negating x.** Matrix origin/heading, local mirror toggle, cell turn, companion offset/turn, non-key full-heading rule, sides and pin numbering each have separate contracts.
6. **An inter-matrix anchor forms a dependency graph.** Define evaluation order, cycles, missing/deleted anchor behavior, anchor matrix deletion/compaction, mirrored source-vs-target mapping, local/omitted exception behavior, undo, and whether descendants move on source edits before adding it to the model.
7. **Uniform pitch is used for dimensions as well as placement.** Key centers can become irregular while key size, keycap size, PCB/plate opening and snap spacing still derive from pitch and edge gap. Those are separate quantities.
8. **Sparse vectors are implicit zero-filled arrays.** Short vectors, explicit trailing zeros, and resize/truncate behavior have meaning in serialization, SetMatrix, placement updates, reflection, deletion, and conversion.
9. **Cell state has two axes.** Disabled preserves a generated identity slot but removes active projection; deleted is a tombstone and compaction is a separate operation. “Skip” parity must not conflate them.
10. **Scene schema is a public boundary.** `MatrixColumnBasis` and `MatrixScene` are serialized to web/runtime and golden transcripts; web owns controls but Core owns parameter geometry. Do not rebuild the new formulas in UI code.
11. **Companion ownership precedence matters.** Constraint > authored > follows is shared by solver and scene. A key transform edit must preserve authored relative pose while constrained members remain constrained.
12. **Archive versioning and strict serde interact.** `CURRENT_VERSION=6` and `deny_unknown_fields` make even additive matrix fields a compatibility concern for older binaries; semantic reinterpretation needs a migration plan, not just defaults.
