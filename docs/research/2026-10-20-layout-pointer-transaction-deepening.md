# Layout pointer transaction — architecture candidate 01

2026-10-20 · Read-only architecture research. Scope: the Layout 2D selection/part-move pointer transaction, its shared pan, and their mounted/browser and Session handoffs. This is not a proposal for an interface or an implementation.

## Finding

**Promising, bounded deepening; not a canvas-wide gesture rewrite.** Editor currently coordinates hit selection, a pending/active part drag, pointer capture, Space-pan, Escape, scope cleanup, and Session events across separated closures and an inline SVG. A Layout-owned pointer transaction could concentrate those rules while leaving the page shell responsible for workspace composition and application lifetime. The strongest counterweight is that selection identity is intentionally App-owned, navigation is already extracted and shared, and transform/outline/placement gestures have different ownership and commit policies; absorbing those would make the seam wider rather than deeper. [`web/src/presentation.rs:259-275,2880-2922,5571-5619,5789-6214,6228-6504,8309-8632,8781-8783,8895-8912`](../../web/src/presentation.rs); [`web/crates/ui-shared/src/canvas_navigation.rs:65-85,151-234`](../../web/crates/ui-shared/src/canvas_navigation.rs); [`web/crates/layout/src/objects/layout_transform_toolbar.rs:161-176,1448-1468`](../../web/crates/layout/src/objects/layout_transform_toolbar.rs); [`web/src/presentation.rs:8795-8812,8922-8950`](../../web/src/presentation.rs).

## Actual transaction and friction

1. The Dioxus App creates `SelectionAdapter` signals and subscribes to Runtime: a changed scope clears selected context and range anchor, increments generation, and invokes registered cleanup; invalid contexts and membership changes are reconciled independently. `Editor` retains this adapter, Layout state, and the shared canvas navigation handle. Thus a pointer owner cannot silently become a second document or selection authority. [`web/src/presentation.rs:259-275,299-355,359-423,2880-2922`](../../web/src/presentation.rs); [`docs/adr/0014-document-authority-and-captured-lifetimes.md:9-13`](../adr/0014-document-authority-and-captured-lifetimes.md).
2. `layout_canvas::Scene` renders accepted/preview geometry and forwards matrix-cell and part pointer-down events. Matrix-cell down selects a scoped context and stops propagation; it does not start the ordinary part-move drag. Part down arbitrates active tools, scope/generation and gesture occupancy, optionally handles splay pick or Space-pan, resolves selection kind and range/toggle/replace, then captures the SVG pointer and records positions **only** for a replace-selection with eligible selected parts. A separate selection-move handle seeds essentially the same pending `Drag`. [`web/src/presentation/layout_canvas.rs:93-131,300-345,374-395`](../../web/src/presentation/layout_canvas.rs); [`web/src/presentation.rs:8309-8417,8419-8631,8895-8912`](../../web/src/presentation.rs).
3. SVG `pointermove` first delegates placement tools, then checks pointer, rendered scope/generation, live Layout owner, current Session gesture and pan. Client-coordinate movement (not a view-box change) activates the pending drag; the handler derives snap inputs from current selection/matrix, sends `GestureBegin`, verifies the Session-owned generation, then samples moved positions. `pointerup` either commits a placement, finishes a camera-only pan, sends `GestureEnd` with the final point, or cancels if coordinates are unavailable. `pointercancel` and lost capture share cancellation, but respect the active tool owner and only cancel an owned active part gesture. [`web/src/presentation.rs:5789-6007,6009-6214,8781-8783`](../../web/src/presentation.rs); [`web/crates/ui-model/src/canvas_interaction.rs:57-67`](../../web/crates/ui-model/src/canvas_interaction.rs); [`web/crates/ui-model/src/selection.rs:459-493`](../../web/crates/ui-model/src/selection.rs).
4. Escape has priority branches for matrix/pair/part placement and pending splay pick before ordinary drag cancellation; workspace departure also cancels the scoped drag. Navigation/board departure cancels and clears selection before `Navigate`. App's scope-transition cleanup releases pointer capture and only cancels an owned active non-pan Session gesture. These are lifetime rules, not incidental UI handlers. [`web/src/presentation.rs:4994-5007,5571-5604,6161-6226,6240-6409`](../../web/src/presentation.rs); [`web/crates/ui-model/src/selection.rs:459-493`](../../web/crates/ui-model/src/selection.rs).
5. The friction is not lack of helpers: `CanvasNavigationState` already owns pan construction/finish, wheel zoom and Space state, but exposes its shared `Drag` and Space cell for page-level arbitration. Editor still coordinates part-down, the move/up/cancel closures, keyboard priority, cleanup registration, and inline SVG wiring; `workspace_composition::canvas` explicitly excludes Layout for this reason. [`web/crates/ui-shared/src/canvas_navigation.rs:16-20,37-73,76-123,151-234,249-282`](../../web/crates/ui-shared/src/canvas_navigation.rs); [`web/src/presentation.rs:5571-5619,5789-6214,6228-6504,8309-8632,8781-8783`](../../web/src/presentation.rs); [`web/src/presentation/workspace_composition.rs:94-105`](../../web/src/presentation/workspace_composition.rs).

## Ownership and invariants at risk

- **Seam location:** within Layout presentation, at the Editor-to-2D-canvas interaction handoff, with a page-level adapter for the App-owned selection and shared navigation; not in Core, Session, or generic navigation. Scene already presents typed hit events and the inline SVG owns capture/keyboard handlers, whereas App owns scope reconciliation and Runtime's subscriber. This would keep the module's interface about the pointer transaction rather than moving the whole Editor. [`web/src/presentation/layout_canvas.rs:108-131,208-238`](../../web/src/presentation/layout_canvas.rs); [`web/src/presentation.rs:259-275,299-423,8781-8783,8859-8870`](../../web/src/presentation.rs); [`docs/adr/0014-document-authority-and-captured-lifetimes.md:9-13`](../adr/0014-document-authority-and-captured-lifetimes.md).
- **Authority and commit:** the visual Layout canvas combines accepted design and transient preview, not a writable copy. Session exclusively owns gesture generation, normalization/snap, frame-coalesced preview, strict-revision gesture commit, cancellation, and release effects; Runtime applies browser pointer capture and animation-frame effects. Do not substitute the ordinary queued field-edit policy for this captured gesture: ADR-0005 explicitly preserves strict gesture commits. [`GLOSSARY.md:7-10,289-305,322-327`](../../GLOSSARY.md); [`application/src/session.rs:1114-1177,2173-2322`](../../application/src/session.rs); [`web/crates/runtime/src/runtime.rs:2001-2056`](../../web/crates/runtime/src/runtime.rs); [`docs/adr/0005-resolve-queued-edits-at-execution.md:16-20,40-56`](../adr/0005-resolve-queued-edits-at-execution.md).
- **Captured lifetime:** pointer ID, scope, selection generation and Session gesture generation guard stale move/up/cancel events; `LayoutOwnerIdentity` additionally binds accepted token/revision and workspace. A scope switch, accepted revision change, canceled Session gesture, or capture loss must not commit an obsolete movement or clear a newer owner. Selection context and anchor survive ordinary rerenders but are invalidated on scope/context changes. [`web/crates/ui-model/src/state.rs:11-32`](../../web/crates/ui-model/src/state.rs); [`web/crates/ui-model/src/selection.rs:459-493,508-540`](../../web/crates/ui-model/src/selection.rs); [`web/src/presentation.rs:336-419,5879-5929,6088-6158`](../../web/src/presentation.rs); [`docs/adr/0014-document-authority-and-captured-lifetimes.md:9-13`](../adr/0014-document-authority-and-captured-lifetimes.md).
- **Arbitration and pan:** placement, outline and transform may claim the canvas before ordinary movement; Space+primary-button pan can begin at the SVG or over a part, must not create a Session edit, and applies camera movement only on release. A window listener admits Space without prior canvas focus except in typing controls; Escape and unmount must release the captured pointer without turning pan into a move. [`web/crates/ui-model/src/canvas_interaction.rs:11-55,69-74,83-134`](../../web/crates/ui-model/src/canvas_interaction.rs); [`web/crates/ui-shared/src/canvas_navigation.rs:76-123,151-234`](../../web/crates/ui-shared/src/canvas_navigation.rs); [`web/src/presentation.rs:6161-6226,6431-6504,8479-8495`](../../web/src/presentation.rs).

## Depth, locality, deletion test

The potential depth is **moderate-to-high for ordinary Layout part movement**: one transaction owner could hide the pending-vs-active transition, capture/retirement, owner checks, Session begin/sample/end/cancel and pan arbitration that are now spread across down/move/up/cancel, Escape and cleanup paths. Its leverage is fewer facts for Editor and mounted tests to coordinate; its locality is one place to inspect a stale-release or lost-capture bug. This is an architectural inference from the duplicated drag seeding and split handlers, not a measured reduction yet. [`web/src/presentation.rs:5571-5604,5879-6007,6088-6214,6401-6409,8419-8631,8895-8912`](../../web/src/presentation.rs).

**Deletion test:** deleting a worthwhile Layout pointer owner should force the transaction ordering and lifetime guards back into those Editor closures, while leaving `Session`, `Runtime`, App selection, and `CanvasNavigationState` intact. If an extraction merely forwards each existing handler plus the same shared `drag`, `space_down`, SVG and owner checks, it would fail the test: a pass-through with a larger interface. The existing navigation abstraction already handles pan math and camera commit, so duplicating it offers no depth. [`web/src/presentation.rs:4960-4971,5789-6214,6431-6504,8419-8632`](../../web/src/presentation.rs); [`web/crates/ui-shared/src/canvas_navigation.rs:65-85,151-234`](../../web/crates/ui-shared/src/canvas_navigation.rs).

## Evidence, gaps and disconfirmation

- Native Session tests exercise gesture cancellation, release effects and stale preview retirement; the browser Runtime implements capture/frame effects. A real-page Playwright smoke exercises trusted part and transform drags, live preview, pointer capture, durable save and exact Undo; its Escape-cancel scenario is the **stagger transform handle**, not an ordinary part drag. This is useful evidence but does not establish Layout part `pointercancel`, lost capture, scope switch mid-drag, Escape mid-part-drag, or Space-pan end-to-end. [`application/tests/durable_session.rs:1507-1552`](../../application/tests/durable_session.rs); [`web/crates/runtime/src/runtime.rs:2001-2056`](../../web/crates/runtime/src/runtime.rs); [`scripts/test-drag-interactions.cjs:140-156,158-211,213-289,385-411`](https://github.com/runinit/boardstudio/blob/c4c33da1dfa0ec293c9de7bc4482be9188eb5832/scripts/test-drag-interactions.cjs); [`docs/adr/0021-test-real-workflows-natively-and-browser-behavior-mounted.md:5-9`](../adr/0021-test-real-workflows-natively-and-browser-behavior-mounted.md).
- Existing unit/mounted checks cover first-wins canvas arbitration, real client-motion threshold and global Space handling; `layout_canvas::Scene` has a callback-refresh mounted fixture. They do not by themselves exercise the full Editor-owned transaction and Session/browser effect chain. A change at this seam would need targeted mounted checks for ordinary part down→move→up, cancel/lost capture/Escape, stale owner departure, and Space-pan with no document edit, while Session's commit semantics remain covered by native workflow tests. [`web/crates/ui-model/src/canvas_interaction.rs:137-176`](../../web/crates/ui-model/src/canvas_interaction.rs); [`web/src/presentation/layout_canvas.rs:108-131,574-615`](../../web/src/presentation/layout_canvas.rs); [`docs/adr/0021-test-real-workflows-natively-and-browser-behavior-mounted.md:5-9`](../adr/0021-test-real-workflows-natively-and-browser-behavior-mounted.md).
- Disconfirming evidence: the navigation module already owns pan; matrix-cell selection intentionally does not start part movement; transform handles use their own `TransformDrag` and pending-edit resolver rather than Session's `MoveParts` gesture; outline/placement have their own arbiter branches. `LayoutWorkspaceState` already owns Layout preferences and view state. A universal Layout gesture owner would conflate distinct commit contracts and probably increase interface burden. [`web/crates/ui-shared/src/canvas_navigation.rs:65-85,151-234`](../../web/crates/ui-shared/src/canvas_navigation.rs); [`web/src/presentation.rs:8309-8417,8781-8812,8922-8950`](../../web/src/presentation.rs); [`web/crates/layout/src/objects/layout_transform_toolbar.rs:161-176,1448-1468`](../../web/crates/layout/src/objects/layout_transform_toolbar.rs); [`web/src/presentation/layout_workspace.rs:119-201`](../../web/src/presentation/layout_workspace.rs).

**Assessment:** investigate a bounded Layout part-move pointer owner at the 2D canvas handoff, retaining App selection, shared pan implementation, and Session/Runtime authority. Treat tests for cancellation and owner retirement as the gate; do not assume the existing transform smoke covers this transaction.
