## Findings and recommendation

1. **The split is justified, but state extraction has already started.** Existing workspace modules contain real state and rendered surfaces; `Editor` still assembles controllers, accepted-state projections, event admission and cross-workspace follow-ups. Moving only the remaining markup would leave that ownership problem intact.
2. **Code ownership and mount lifetime are different decisions.** Move workspace orchestration into existing bin modules, initially through unconditional workspace hooks in the existing `Editor` scope. Do not make controllers active-workspace-only. PCB plan resolution, Keycaps fit, Keymap operations and mechanical settings explicitly require Editor lifetime, even when their UI is absent.
3. **There is already a mounted real-Editor seam.** `layout_layers_tests::host` mounts production `Editor` with the real browser Runtime using in-process Session/Core and memory persistence. It is not a fake workspace controller. However, it is **not the complete production App seam**: its subscriber and Export-return provider omit important App behavior.
4. **The provisional proposal needs two corrections.** The guide should own guide lifecycle/orchestration, not shared instance preference or Layout's geometry-script visibility merely because those currently live in `SetupWorkspaceState`. Likewise, Layout's current `assembly_3d`, selection-kind and snap state are consumed by other workspaces; keep their shared identity rather than silently giving each workspace a copy.
5. **A ready-for-agent spec needs a small composition prototype, not a new framework.** Prove one mount with production scope/selection reconciliation and Export return tracking, and one coherent workspace extraction with unchanged provider ancestry. Exact private return types and callback ordering are not settled by this report.

## 1. Constraints that the extraction must not reinterpret

- Workspace containers and composition stay in `web/src/`, the `boardstudio-web` bin. Existing workspace crates remain feature owners; Runtime stays presentation-independent and has no Dioxus. No additional crate or reversal of dependency direction is needed. [Architecture, lines 7–18 and 75–94](../architecture.md#L7-L94).
- There is one accepted-document authority. UI owns drafts, pending display, selection and view state, not a second editable document. Queued field edits resolve against the accepted document when executed; one-shot actions disable while pending; retired observations are silent, and a landed edit does not create a new “Saved” UI status. [Architecture, lines 27–55](../architecture.md#L27-L55); [ADR-0005](../adr/0005-resolve-queued-edits-at-execution.md); [editing terms](../../GLOSSARY.md#L215-L252).
- Do not combine this extraction with converting existing replacement resolvers or changing mechanical/matrix semantics. ADR-0006 identifies replacement as existing debt, not permission to add more. Matrix placement mathematics and mirrored-half rules stay in Core. [ADR-0006](../adr/0006-replace-document-for-import-and-recovery.md); [ADR-0007](../adr/0007-matrix-gestures-edit-named-parameters.md); [ADR-0008](../adr/0008-linked-halves-stay-linked.md).
- A **board** is the PCB design; a **physical board instance** is one realization. Both identities matter to Case admission; the electrical plan deliberately removes instance identity. [Glossary](../../GLOSSARY.md#L113-L145); [`current_input`](../../web/crates/pcb/src/pcb_wiring/controller.rs#L1001-L1033).
- This is a behavior-preserving ownership change, not a visual redesign, camera reset policy, persistence migration or fabrication-readiness change. [Product constraints](../../PRODUCT.md#L43-L72).

## 2. Current structure and lifetime map

### 2.1 Three lifetimes, not just “page” and “workspace”

**App lifetime:** `App` creates Runtime, the version notification signal, `SelectionAdapter`, scope generation/transition history, project-creation signals, workspace selection, compact panel flags, Export return workspace, case-generation policy, layer visibility and themes. Its one Runtime subscriber performs synchronous scope reconciliation and increments the version. App drop unsubscribes and submits `Close`.

**Editor lifetime:** App mounts one unkeyed `Editor` while an accepted document exists. Opening the project browser sets the host's `hidden` attribute; it does not conditionally remove Editor. Workspace switches, including Export, also do not select a different Editor. Source does not impose a fresh Editor mount for every project/board change while accepted state remains present. Preserve existing per-owner invalidation rather than introducing an automatic all-state reset on project ID.

**Visible child lifetime:** workspace canvas/viewer/Inspector branches, guide drawer versus ordinary panels, and Layout 2D versus the shared 3D viewer mount conditionally. Drafts and DOM-owned resources inside those children can have a shorter lifetime than their controllers. “Hidden panel” is not synonymous with controller unmount, nor does every panel visibility toggle necessarily unmount its content.

Evidence: [`App` subscriber/drop, 299–435](../../web/src/presentation.rs#L299-L435); [App providers and Export tracking, 437–550](../../web/src/presentation.rs#L437-L550); [App host, 729–732](../../web/src/presentation.rs#L729-L732); [Editor rendering, 8634–9117](../../web/src/presentation.rs#L8634-L9117).

### 2.3 Provider and effect placement matters

App provides Runtime/version, adapter, workspace, compact panels, return workspace, Case generation, layer visibility and themes. Editor adds layer-dock and assembly-action outlets, `InstanceSelection` through setup state, `CaseSelection`, Parts state contexts, `RelationHighlight`, Keymap operation contexts, Keycaps edit context and the mechanical-settings controller context. They are currently in one ancestor scope of all rendered slots. A workspace controller rendered as a sibling cannot simply provide context to an Inspector rendered elsewhere.

Preserve these relationships first by keeping custom workspace hooks in the Editor scope; “implementation moved into a workspace module” need not mean “new Dioxus scope.” The guide-name hook is before the accepted-scope guard, whereas SVG/camera/placement and later hooks are after it. Do not move later hooks into a workspace `match` or create a new early-return path through a hook sequence. Existing `workspace_composition` functions are dispatch/render helpers, not six independent controller mounts.

Evidence: [Editor providers/hooks, 2880–3258](../../web/src/presentation.rs#L2880-L3258); [accepted guard, 3561–3566](../../web/src/presentation.rs#L3561-L3566); [Keymap context providers](../../web/crates/keymap/src/keymap/layer_controller.rs#L96-L164), [binding](../../web/crates/keymap/src/keymap/binding_controller.rs#L523-L605), [macro](../../web/crates/keymap/src/keymap/macro_controller.rs#L242-L331); [Keycaps edit context](../../web/crates/keycaps/src/keycaps_settings.rs#L383-L418); [mechanical controller provider](../../web/crates/case/src/mechanical_settings_mount.rs#L75-L215).

## 3. Minimal deep-module interfaces

These are recommended responsibilities and interface constraints, **not approved Rust signatures**.

### Shared shell contract

`Editor` should retain the common ancestor providers/outlets, shared authorities, routing and panel layout. Pass existing `Rc<Runtime>`, version/workspace signals, `SelectionAdapter`, panel handles and captured owner identities rather than inventing another store. Keep the single canvas arbiter and shared view-mode/snap identity. Prefer a small private grouping of repeatedly used shell handles only if an actual extraction needs it; do not pass an `EditorState` containing every workspace's internals.

Workspace modules should accept those authorities and a small number of explicit peer capabilities, mount their existing lower-crate controllers, compute their own projections/admitted callbacks, and produce the actual workspace surfaces. Keep the existing objects/toolbar/canvas/Inspector structure during migration, but make the workspace module construct its own input values: the caller should not still build fifty fields of its Inspector. Surface results can be existing typed inputs initially, then private rendered slots where that reduces caller knowledge. Do not add a generic workspace trait/registry just to dispatch six fixed variants.

Current `SharedObjectsInput`, `CanvasEventHandlers` and the private composition enums are useful existing seams, not proof that one universal workspace interface is needed. Case currently borrows a `ReadModel` in its objects input; returning `'static` Elements requires deliberately owning the relevant projections, not accidental deep document copies or lifetime-erasing wrappers. [Composition types](../../web/src/presentation/workspace_composition.rs#L6-L69); [Case inputs](../../web/src/presentation/case_workspace.rs#L120-L168).

## 4. Concrete lifetime and movement hazards

### Pending edits and drafts

- **Do not cancel authoritative work merely because the UI leaves.** Keymap hooks keep controller state for Editor lifetime but retire visible observations when workspace/scope generation changes. Mechanical settings likewise retains controller/request sequence while its presentation generation invalidates old Case controls. [Keymap layer owner](../../web/crates/keymap/src/keymap/layer_controller.rs#L137-L164); [binding owner](../../web/crates/keymap/src/keymap/binding_controller.rs#L552-L605); [macro owner](../../web/crates/keymap/src/keymap/macro_controller.rs#L270-L331); [mechanical mount](../../web/crates/case/src/mechanical_settings_mount.rs#L75-L99), [settlement effect](../../web/crates/case/src/mechanical_settings_mount.rs#L302-L366).
- **Do not promise blanket draft preservation.** The shared helper preserves newer drafts against older results and distinguishes field-binding epochs. The UI's owner rules may intentionally retire observations or reset fields on selection/workspace changes. A module move must preserve that exact policy, including clean accepted projection, not introduce a workspace-wide draft cache. [`PendingEditSignals::bind_field/unbind_field`](../../web/crates/ui-shared/src/pending_edit_helpers.rs#L173-L250); [`settle/apply_to_field`](../../web/crates/ui-shared/src/pending_edit_helpers.rs#L360-L462).
- A moved field must unbind from the same helper that settled its submission. `OwnedEdits::follow_owner` replaces observations and rebinds still-mounted fields; it does not cancel Session edits. Keep field and one-shot bindings and their drop handlers together. [OwnedEdits](../../web/crates/ui-shared/src/owned_edits.rs#L1-L74).

### Async preparation, completion and cancellation

- Repository code uses both Dioxus `spawn` and `wasm_bindgen_futures::spawn_local`. Do not replace one with the other during extraction. Keycaps fit, placement, physical setup and wiring resolution use explicit alive/request/owner checks after awaits; those checks must run **before** accessing dropped Signals. [Fit guard](../../web/crates/keycaps/src/keycaps_fit.rs#L180-L224); [physical setup](../../web/crates/pcb/src/pcb_physical_setup/controller.rs#L236-L305); [wiring guard](../../web/crates/pcb/src/pcb_wiring/controller.rs#L1064-L1088).
- Moving a `use_drop` from Editor to an active-only child changes when `alive` becomes false, when listeners disappear and when pending UI follow-ups stop. Mechanical settings also starts a mounting-hole load in `use_hook`; making that mount active-only would repeat the load and needs separate teardown scrutiny. [Mechanical mount initialization](../../web/crates/case/src/mechanical_settings_mount.rs#L85-L114).
- Preserve exact post-Landed navigation and saved-state checks; do not infer success by re-reading a requested value. Physical setup explicitly permits only a matching accepted scope transition for reassignment, not arbitrary departure/return. [Page transition admission](../../web/src/presentation.rs#L3330-L3366); [`finish_operation`](../../web/crates/pcb/src/pcb_physical_setup/controller.rs#L679-L776).

### Canvas ownership, geometry and handlers

- There is one `CanvasInteractionArbiter` shared by matrix placement, mirrored pair, part placement, outline editing and matrix transforms. Matrix setup and pair setup additionally mask one another's `can_open`. Duplicating the arbiter in extracted modules would permit conflicting transactions. [Mount/arbitration](../../web/src/presentation.rs#L2991-L3135); [event priority](../../web/src/presentation.rs#L5789-L5878), [cancel](../../web/src/presentation.rs#L6161-L6227).
- PCB and Layout share `Drag`, the active SVG and pan state, but not identical hit admission. Preserve PCB locked/readiness checks, modified-hit selection-only behavior, Layout matrix-cell selection rules, gesture threshold, ownership rechecks and pointer capture release. Shared navigation already owns Space-pan and wheel target math; feature-specific transaction routing remains separate. [PCB drag](../../web/src/presentation.rs#L6505-L6691); [Layout selection/drag](../../web/src/presentation.rs#L8309-L8632); [shared navigation](../../web/crates/ui-shared/src/canvas_navigation.rs#L37-L149).
- Preserve the one cleanup registration in `SelectionAdapter`: App invokes it synchronously when scope changes. Editor stores weak references and an ID, and drop removes only its own registration. Losing that bridge or installing one per workspace can cancel the wrong gesture or leave pointer capture alive. [App cleanup](../../web/src/presentation.rs#L336-L356); [Editor registration](../../web/src/presentation.rs#L5571-L5619).
- The `ResizeObserver`, SVG ref, Runtime surface and surface-size signal must agree. Current mount updates all three, observer replacement disconnects the previous observer, and Editor drop disconnects it. Camera fit needs measured dimensions and mounted toolbar height. Do not create per-slot SVG refs or reset Session camera during extraction. [Observer](../../web/src/presentation.rs#L4584-L4628); [mount](../../web/crates/ui-shared/src/canvas_navigation.rs#L125-L149); [fit/zoom basis](../../web/src/presentation.rs#L4630-L4915).
- Camera behavior is not one interchangeable formula: Layout uses accepted bounds for its basis but displayed bounds for some fitting; Keymap displays an effective zoom scale ratio; finding navigation captures the source surface/basis before switching. Reuse existing math without “normalizing” these distinctions. [Basis and footer](../../web/src/presentation.rs#L4630-L4755); [source finding basis](../../web/src/presentation.rs#L5122-L5134).

### Routing slots, providers and mounted outputs

- `WorkspaceRoutingSlots` allocates stable tree/navigation handlers early; closures capture their handles before implementations are replaced at lines 6796–6797. Layout findings has the same `resume` slot pattern. Preserve fresh targets, initialization-before-use and owner validation; replacing these with one-time captured closures can leave stale accepted identities. - Layer docking already has ownership-tagged publish/clear-on-drop behavior. Keep provider/outlet above the moving viewer and preserve owner tagging so an old viewer's drop cannot clear a new viewer's controls. Parts assembly actions also use a shared provider. [Layer dock](../../web/crates/ui-shared/src/layer_dock.rs#L4-L42); [assembly action provider](../../web/crates/parts/src/parts.rs#L27-L35).
- Avoid changing keys, slot nesting, wrapper DOM, IDs, CSS ancestry or event bubbling as incidental cleanup. There is a mounted canvas regression specifically covering geometry memoization while callbacks/selection/preview/layers update. [Scene props](../../web/src/presentation/layout_canvas.rs#L108-L132); [regression](../../web/src/presentation/layout_canvas.rs#L617-L625).

### Framework evidence, pinned to Dioxus 0.7.10

The pin is explicit in [`web/Cargo.toml`, 57–62](../../web/Cargo.toml#L57-L62). Context7 was consulted using `/dioxuslabs/dioxus/v0.7.10`; where its answer linked `main`, the tagged official source was fetched before relying on it:

- [`use_hook`, `spawn`, `spawn_forever`, `use_drop`](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/core/src/global_context.rs): hooks store state in the current scope; `spawn` is canceled on component drop; `spawn_forever` uses root scope; `use_drop` stores cleanup through a hook. Moving code into an ordinary called hook does not itself introduce a component scope.
- [`use_context` / `use_context_provider`](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/hooks/src/use_context.rs): context consumption is cached on first render, provider initialization is once through `use_hook`, and context should use interior mutability for changes. Provider relocation/replacement is not ordinary reactive prop passing.
- [`use_callback`](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/hooks/src/use_callback.rs): keeps its handle and replaces the inner callback each call; it does not signal-track callback readers. Do not substitute `use_hook(|| callback)` for a refreshed callback.
- [Hook ordering](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/hooks/docs/rules_of_hooks.md) and [reactive prop guidance](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/core-macro/docs/component.md): keep unconditional ordering and explicit `use_reactive` dependencies when converting captured values to props.

These sources do not establish that every proposed new scope/slot topology will be equivalent. Actual remount, focus, observer and drop ordering remain browser-test/prototype questions. In particular, removing a root DOM node in a test is not evidence that Dioxus unmounted its scopes; exercise an actual conditional child removal or drop a retained VirtualDom.

## 5. Cross-workspace flows that must survive intact

### Parts → Layout placement, and PCB → Parts → Layout → PCB

Matrix assembly placement is admitted from Parts only when the canvas arbiter is free; it invokes matrix placement, changes to Layout 2D, clears tree/range selection and closes panels. General component placement and guided/PCB-controller placement are already owned by `part_placement::use_controller_placement`, not by the Parts canvas. The hook receives Parts selection/query, guide state, Layout snap/target, shared selection and canvas-center authorities. Do not transfer it into an active-only Parts Inspector.

Controller choosing is guided when the current guide is in Wiring; otherwise it is admitted from PCB, retains a chooser owner and opens Parts with query `controller`. Placement loads definitions asynchronously and uses workflow-specific owner predicates. Existing hook tests cover stale preparation, 3D cancellation, arbitration and no post-unmount selection. [Matrix transition](../../web/src/presentation.rs#L3004-L3032); [placement host](../../web/src/presentation.rs#L4916-L4940); [controller choosing/preparation](../../web/crates/layout/src/part_placement.rs#L472-L650); [saved-state/unmount regression](../../web/crates/layout/src/part_placement.rs#L3288-L3317).

Mounted modules add a second route: Layout/PCB module hit validates scope/token/revision and module definition, selects its Parts definition, expires Parts selection/preview epochs and browses Parts. “Open placement” returns to PCB only for the same selected module/definition. Attachment navigates/selects the new module only after its exact result token/revision and Parts selection generation match. [Page module routes](../../web/src/presentation.rs#L4129-L4320); [`PartsWorkspaceState::select_mounted_module`](../../web/src/presentation/parts_workspace.rs#L57-L66).

### Guide physical setup, Layout creation and wiring

Guide request consumption waits for the accepted matching project and deduplicates request IDs; preference persistence is separate. Stage activation sets Layout for Project/Layout/Wiring, Case for Case, Export for Review, and coordinates an explicit panel-reveal exemption with ordinary workspace defaults. The page stage handler also clears selection. Project physical setup uses a predicate reading current guide/project state at admission, not a boolean captured while the drawer was visible.

Physical setup has one busy gate for Project and Case intents, resource preparation, pending-edit settlement and exact follow-up instance navigation. Instance preference reconciliation waits while setup is busy or a drag is active. ### Keycaps finding → Layout/Case, camera and focus

The page constructs accepted-navigation authority and checks current fit findings, targets, scope/generation and mechanical layers. It captures the Keycaps source camera basis, records the admitted finding marker and dispatches route actions. Layout routes change workspace, select the tree destination and queue a fit; Case routes select a layer/body and clear conflicting layer selection for body findings. Panels are revealed/pinned. A later effect validates the destination selection as well as scope/token/revision, computes geometry, sets camera and schedules owner-checked focus. Navigation lifetime remains alive across the workspace switch.

Moving only the click handler leaves a major chunk of Keycaps ownership in Editor; moving the whole thing into a Keycaps-only child kills the queued destination work. Move admission + dispatch + pending-fit coordination together, using shared shell routing/surface/Case-selection capabilities. ### Case/instance selection

Case tree actions validate captured scope/token/generation and `InstanceSelection`. Selecting an assembly clears layer and part-tree selection and invokes shared navigation; merely navigating an assembly intentionally differs. Body, layer, PCB and gasket selection are distinct routes. The shared navigator validates requested physical instance membership, remembers explicit preference, resolves the effective instance, cancels scoped drag, clears tree/range anchors and submits `Navigate`. Preserve previous same-scope display geometry separately from current editable/resolved settings. ### Export return behavior

App remembers the last non-Export workspace and closes compact panels when entering Export. The header Export toggle enters or returns using that shared signal. `ExportWorkspace` Back uses the rendered return value; its document Escape listener reads the live return signal and removes itself on drop. Review wiring clears part/tree/range selection, pins/reveals Inspector and routes PCB; Review case routes Case and reveals Inspector without that same selection clearing. Keymap's firmware export is a guarded direct Runtime operation, not necessarily entry to the Export workspace.

## 6. Mounted testing: what is available and what is missing

### Existing practical seam

`web/src/presentation/layout_layers_tests.rs::host` supplies contexts and subscribes Runtime version updates, then mounts **the production `Editor {}`**, including its actual controllers, dispatch and slots. Its tests use `runtime::project_name_test_support::new_runtime/open_document`, `VirtualDom::provide_root_context(runtime)` and `dioxus_web::launch::launch_virtual_dom`. It exercises real layer visibility and accepted/preview findings reaching the Editor footer/Inspector. The relation-highlight tests also mount real Editor; selected-key tests have another real `editor_host`.

Evidence: [layers host and mount](../../web/src/presentation/layout_layers_tests.rs#L46-L117), [visibility assertions](../../web/src/presentation/layout_layers_tests.rs#L142-L183), [preview test](../../web/src/presentation/layout_layers_tests.rs#L194-L255); [relation Editor host/mount](../../web/src/presentation/layout_relation_highlight_tests.rs#L200-L277); [selected-key Editor host](../../web/src/presentation/layout_key_selection_actions/tests.rs#L455-L537).

The browser test Runtime is the real WASM Runtime with installed in-process adapters, **not** the native `runtime_test_stub` type. `new_runtime` disables active-project restoration; `open_document` installs real Session/Core, selects memory persistence and opens through `Event::Open`. Core/persistence can be gated or failed; outcomes, accepted/saved documents and held effects can be observed. Driver calls are necessary because the adapter holds Runtime effects until driven; callbacks may enqueue more after asynchronous turns. Use state-based bounded waits and await gate-entry signals rather than fixed sleep as the sole evidence.

Evidence: [target-specific Runtime modules](../../web/crates/runtime/src/lib.rs#L33-L47); [browser support](../../web/crates/runtime/src/runtime.rs#L7933-L7975), [gates/saved document/driver](../../web/crates/runtime/src/runtime.rs#L8123-L8221); [asynchronous real Core adapter](../../web/crates/runtime/src/in_process_support.rs#L136-L203); [bounded test wait pattern](../../web/crates/keymap/src/keymap/queued_edit_tests.rs#L180-L236).

### The precise gap: Editor is mountable; App is not dependency-injected

`App` constructs `Runtime::new` internally. Providing a Runtime root context does not replace that constructor. Existing Editor hosts duplicate only a subset of App setup:

- layers host subscribes only `version += 1`, not App's scope generation, transition record, selection retention or cleanup invocation;
- relation host manually increments version after edits, rather than using the production subscriber;
- hosts alias `ExportReturnWorkspace` to the workspace signal itself, so entering Export does not reproduce real return tracking;
- production header navigation/Export toggle and project-browser hiding are outside Editor;
- Runtime has **one** notifier slot: another test subscriber replaces the existing one. Do not add competing per-workspace subscribers.

Evidence: [App Runtime construction](../../web/src/presentation.rs#L259-L275), [subscriber](../../web/src/presentation.rs#L299-L424), [return provider/effect](../../web/src/presentation.rs#L453-L463); [layers host](../../web/src/presentation/layout_layers_tests.rs#L46-L87); [relation probe/host](../../web/src/presentation/layout_relation_highlight_tests.rs#L80-L86), [host](../../web/src/presentation/layout_relation_highlight_tests.rs#L200-L238); [`Runtime::subscribe/unsubscribe`](../../web/crates/runtime/src/runtime.rs#L760-L784).

**Therefore:** one reusable mounted-Editor fixture is available in principle today, but “one mounted page seam covers everything” is not yet established. Tests using a manual adapter-generation increment cannot demonstrate production App normalization after physical reassignment.

### Minimal new seam, only where needed

For workspace-local extraction, reuse/consolidate an existing real-Editor host, expose its existing workspace/adapter signals through a test-only probe, and mount production `WorkspaceObjectNavigation` alongside Editor when testing ordinary workspace buttons. That does not require a fake controller or a production workspace interface solely for tests.

For App/Editor integration (scope cleanup, physical reassignment, Export return/header and project-browser lifetime), prototype separating Runtime construction from the **existing production App composition**: a thin startup wrapper creates Runtime, and an internal mountable composition receives the same `Rc<Runtime>` and owns the current production subscription/providers/header/Editor. Do not duplicate the subscriber into another test host and call it production coverage. Exact helper/component shape and allowed file scope need approval in the later spec; no such seam was implemented here.

Additional fixture requirements:

1. Open a minimal real document through Core with at least two boards, colliding IDs across replacement projects, keys/layers and explicit physical instances where relevant. Seed guide preferences deliberately and restore changed local-storage panel/guide preferences; memory document saves do not isolate browser preferences.
2. Establish nonzero canvas size and real attached DOM for fit/pointer/focus assertions. Include production styles only where measured layout is under test. Global IDs/selectors and document listeners mean these mounts should not coexist accidentally.
3. Gate only the relevant Core request when background PCB/fit queries can race; use `InProcessCore::gate_matching_reply` where necessary. [Filtered gates](../../web/crates/runtime/src/in_process_support.rs#L91-L113).
4. Start with real 2D actions. Case/3D findings can reuse accepted, identity-matched CAD fixture installation (`set_cad_scene_test`) where needed, but that is not a kernel/renderer integration test. Packaged browser checks remain needed for actual worker/GPU behavior. [Case fixture](../../web/src/presentation/case_workspace.rs#L1279-L1343); [architecture test limits](../architecture.md#L52-L73).
5. For unmount assertions, retain/drop a VirtualDom or conditionally remove Editor beneath a mounted owner, release held replies, and assert no subsequent UI/navigation/focus writes. Existing lower-level placement and Keycaps tests demonstrate these patterns; many DOM tests merely call `root.remove()` and cannot establish scope teardown by that alone.

The existing WASM runner selects `--bin boardstudio-web`, page-only features; workspace crates run their own `--lib` tests. ## 8. Recommended green-at-each-step sequence

“Green” below is a future verification requirement, not a statement that this working tree currently passes.

1. **Establish the seam before ownership moves.** Consolidate only the minimal real-Editor fixture needed for composition characterization. Prototype the production-App dependency seam for scope/Export cases; prove that mounting, switching, one real edit, gated reply and real unmount work without a fake controller. Record existing baseline failures separately from this refactor.
2. **Take Keymap as the first bounded ownership slice.** In `keymap_workspace`, move its source/projection/controllers, admitted selection/layer/export handlers and input construction together. 3. **Move PCB orchestration, preserving shared exports.** Let `pcb_workspace` own wiring mount/actions/source/projection/Inspector choice and PCB hit admission. 4. **Move Parts/Case shell wiring, then guide orchestration.** Parts owns its browser/module ports; Case owns settings/tree/display/finding composition. Retain one shared physical-setup controller. 5. **Move Keycaps navigation as one workflow.** Include settings/fit ownership, admission, source-basis capture, pending Layout fit and focus/marker state; keep Editor lifetime. Verify the real finding-to-Layout path and stale same-scope selection before moving canvas code.
6. **Finish Layout and shared canvas orchestration.** Move Layout controllers/projections/Inspector priority, its gesture chain and rendered transaction canvas together. ## 9. Rejected approaches and unresolved questions

### Rejected by current evidence

- **Six active-only controller components:** contradicts explicit lifetime contracts and breaks cross-workspace pending fit/placement and shared plan consumers.
- **Only extracting helpers/markup or wrapping existing huge input structs:** leaves accepted-owner admission, controllers and slot construction in Editor; reduces file size, not caller knowledge.
- **A generic workspace framework, new crates, event bus, global controller registry, duplicated Session, or universal mock controller:** unnecessary for fixed private composition and conflicts with existing ownership direction/test seam.
- **Moving everything into one `EditorController`/mega-state context:** renames the monolith and obscures which fields are safe to share.
- **Per-workspace camera, arbiter or instance preference:** behavior changes, not extraction. Shared 3D mode is already consumed by Layout/Keymap/Keycaps.
- **Broad draft persistence, new retry policy or edits rewritten as part of this task:** not requested; existing owner/binding semantics are intentionally finer-grained.
- **One enormous end-to-end scenario replacing feature tests:** harder to diagnose and expensive; add page coverage for composition only. Native tests and fixture-recorded route effects are not equivalent to browser DOM/pointer/focus coverage.

### Decisions supported by source

- Keep containers in the bin and lower-crate feature ownership intact.
- Keep current Editor-lifetime controllers/assessments and common provider ancestry initially; custom workspace hooks can deepen modules without adding new mount scopes.
- Reuse real Runtime test support and existing mounted Editor composition.
- Keep selection/instance/canvas authority shared; workspace admission must preserve captured scope, generation, token/revision and destination checks.
- Make guide lifecycle a coherent module, but preserve one physical-setup workflow serving both guide and Case.

### Prototype / agreement needed before a ready-for-agent spec

1. **Production App injection seam:** choose and demonstrate the smallest way to mount its actual provider/subscriber/header logic with a test Runtime. This is the main coverage blocker for board/instance normalization, Export return and library/close lifetime.
2. **One deep workspace interface:** prototype the first Keymap slice enough to prove controller + rendered content ownership without exporting its controller internals back to Editor. Determine whether existing typed slot inputs or private Elements give the smaller interface; preserve hook scope/provider ancestry either way.
3. **Callback order across shared routes:** confirm refresh/registration timing when workspace hook construction replaces routing slots, including Keycaps fit and Layout findings resume. Source shows the dependencies, not equivalence of every proposed ordering.
4. **Browser fixture viability:** verify nonzero sizing, focus/pointer capture, preference isolation and actual scope unmount under the bin test runner. Do not extrapolate from source or DOM root removal.
5. **Scope of shared state cleanup:** explicitly agree that instance preference remains shell-owned and shared 3D/snap/selection-kind behavior remains unchanged. Decide only the module location of those hooks, not a new user-facing policy.
6. **Reconcile the moving checkout and baseline:** source and unrelated UI/Export work changed during research. Refresh line ranges/callers and establish a known test baseline before implementation. Do not overwrite or fold unrelated user changes into the extraction.

No blocker requires a new library, public cross-crate interface or full application rewrite. The core research outcome is a lifetime-preserving ownership split with a small, real composition test gap—not a file-splitting exercise.
