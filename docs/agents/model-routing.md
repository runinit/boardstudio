# Model routing

The user's direct requests take precedence over these defaults. Select from the available catalog; do not switch providers without the user requesting it. If a requested selection is unavailable, report that rather than silently substituting another provider.

| Work | Preferred route |
| --- | --- |
| Hardest tasks and complex multi-stage planning | Opus 5.5 high via Claude; Wonder max via the Meta provider as the user-approved fallback. |
| Ordinary, well-defined implementation | Terra 6.1 high via Pi or Spark 1.3 Contributor xhigh via the Meta provider. |
| Predefined builds, tests, reads and research collection | Terra 6.1 low via Pi or Spark 1.3 Contributor low via the Meta provider. |
| Ordinary independent review | Terra 6.1 high via Pi. |
| Consequential, disputed or cross-cutting review | Opus 5.5 high via Claude or Wonder max via the Meta provider. |

Collect research at low effort, then route synthesis according to its complexity. A long command alone does not justify an expensive model; route diagnosis by the complexity of the problem.

Coordinate delegated implementation with pointers. A handoff is complete with a verified change and checks, a reproducible failure and a concrete materially different next experiment, or the exact blocker. After two inconclusive attempts, escalate the evidence and a different question rather than repeat. Respect the user's provider choices when escalating.
