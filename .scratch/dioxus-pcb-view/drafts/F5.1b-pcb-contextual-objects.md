# PCB contextual Objects inventory

## Problem Statement

Dioxus reuses Layout's grouped matrices, physical instance and grouping controls in PCB. The pinned TypeScript PCB workbench instead shows the selected board, its Outline versions and bridges, then every actual board part with its definition and front/back side. This prevents reliable comparison and makes a primary matrix key behave like a Layout group when the user wants PCB part wiring.

## Solution

Show the same PCB-specific flat inventory and selection summary. Selecting a row selects that exact actual part and opens its existing PCB wiring Inspector. Outline disclosures and board switching retain their existing accepted-session behavior.

## User Stories

1. As a designer, I want the selected PCB board at the top of Objects, so the inventory's scope is clear.
2. As a designer, I want Outline, its versions and bridges in the reference hierarchy, so I can inspect the active board outline.
3. As a designer, I want each actual board part shown once in document order, so I can locate switches and non-key components alike.
4. As a designer, I want the definition name and front/back side on each row, so I can distinguish matching references and mirrored components.
5. As a designer, I want a matrix's primary switch to be an individual PCB part, so selecting it opens the switch wiring context rather than Layout authoring.
6. As a designer, I want the selected reference, board/PCB path and selected count below the tree, so I can see what I am inspecting.
7. As a designer, I want Layout-only grouping and physical-instance controls absent from PCB, so controls reflect the active workbench.
8. As a designer, I want disclosure and selection to leave project history unchanged, so inspection cannot edit my design.
9. As a designer, I want switching boards to use current accepted parts and scope, so an old row cannot select a part on another board.

## Implementation Decisions

- Derive the private PCB tree from the accepted ReadModel. Reuse the existing outline/version/bridge projection, then append actual selected-board parts in document order.
- Use explicit component contexts and actual part IDs for all parts, including primary matrix switches. Preserve existing strict selection admission and Inspector controllers; do not introduce another selection authority.
- Share the existing global selection kind across workspaces, as the reference does. A part-tree action changes it to Part through the current selection adapter.
- Make the existing Objects composition contextual: preserve Board, hide Layout-specific selectors and the duplicate project heading in PCB, and append a PCB selection footer.
- This is presentation and selection work. No schema, wire, provider, CAD, history or durable edit change is needed.

## Out of Scope

PCB Add object/New board composition, all host artwork/findings visibility, remaining camera/footer controls, protected electrical handoff qualification and full F5/F3 parent acceptance remain in their existing queues. The view does not synthesize module footprints as durable board parts.
