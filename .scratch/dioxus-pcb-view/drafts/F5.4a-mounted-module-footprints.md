# Mounted-module footprint visibility

## Problem Statement

The Dioxus PCB view omits mounted daughterboard footprints and their independent
Layers control, even though the accepted scene contains their authentic source
geometry. Designers cannot compare the actual daughterboard pads and artwork
with host circuitry as they can in TypeScript.

## Solution

Render accepted source footprints on the selected host board and add the separate
Mounted modules → Footprints control. Host visibility and module visibility
intersect without turning daughterboard pads into host parts or modifying a project.

## User Stories

1. As a designer, I want to see mounted source footprints in PCB, so I can compare their placement with the host.
2. As a designer, I want to hide only module footprints, so host parts remain visible.
3. As a designer, I want copper and hole controls to apply independently, so I can inspect each kind of geometry.
4. As a designer, I want front/back source artwork to follow its resolved face, so flipped modules display correctly.
5. As a designer, I want source references displayed once, so module identity stays readable.
6. As a designer, I want visibility retained through workspace and board changes, so inspection choices survive navigation.
7. As a designer, I want the module control on boards with no modules, so the menu stays consistent.
8. As a designer, I want visibility changes to leave the saved document and history untouched.

## Implementation Decisions

- Consume accepted resolved module scenes filtered by the current host board and session/document owner.
- Reuse shared Layers presentation with a separate transient module visibility signal.
- Consume already composed footprint pose/face and remapped artwork layers once.
- Keep source-local courtyards, pads, drills, silkscreen/fabrication and reference rules consistent with the TypeScript overlay.
- Add only the working Footprints control in this bounded slice. Remaining module categories and owning-module navigation stay explicitly required by their parent.
- Source geometry remains read-only; no catalogue, firmware, resolver or saved schema changes.

## Testing Decisions

- One affected page WASM compile/check and a paired module-bearing browser journey.
- Reuse the pinned VIK review demo and existing host-layer evidence; no new unit tests for this reversible presentation addition.
- Compare visibility, geometry/pose, host independence and unchanged revision/document; no full suite or per-child approval chain.

## Out of Scope

Owning-module Parts navigation, outlines, clearance/service, holes, supports and
finding-focus overlays remain F5.4 work. This slice does not accept that parent.

## Further Notes

The source-backed frontier and TypeScript hierarchy are retained in PCB02.
RF-001/RF-009 retain the shared visibility-owner gap; source-owned daughterboard
copper must never become host circuitry. All 62 parent criteria and joins remain.
