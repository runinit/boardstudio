# Inspect mounted-module overlays and artwork

## Problem Statement

PCB now shows authentic module footprints, but its Layers menu omits the remaining
TypeScript module categories. Designers cannot inspect source board outlines,
mounting holes, selected supports, front/back artwork and module error regions.

## Solution

Port the complete Mounted modules layer inventory in its existing order. Connect
every row to accepted source geometry through the current transient module owner.
Preserve the separate host object/copper controls and the document/history.

## User Stories

1. As a designer, I want the same Mounted modules menu, so I can find familiar controls.
2. As a designer, I want module outlines hidden initially, so source footprints remain the default PCB view.
3. As a designer, I want to show module outlines, so I can compare daughterboards with the host.
4. As a designer, I want source mounting holes and selected annular supports separately visible, so I can inspect their different ownership and dimensions.
5. As a designer, I want qualified source clearance/service polygons, so I can inspect existing mechanical envelopes.
6. As a designer, I want front/back silkscreen independently visible, so I can read source graphics on the resolved face.
7. As a designer, I want front/back fabrication artwork initially hidden and independently selectable, so I can inspect each source drawing.
8. As a designer, I want module error regions controlled separately, so ordinary PCB inspection can hide them.
9. As a designer, I want host pad/hole/artwork controls to keep their existing intersections, so unrelated geometry stays stable.
10. As a designer, I want transient choices retained across workspace navigation, so I can continue inspecting the same scene.
11. As a designer, I want empty categories and module-free boards to keep the reference controls, so the menu is consistent without fabricated geometry.
12. As a designer, I want visibility changes to preserve saved data and history, so inspection cannot edit my design.

## Implementation Decisions

- Reuse the accepted selected-board module scene, current snapshot admission and separate module visibility owner proven by the Footprints slice.
- Preserve the ten reference labels/order and hidden defaults. Artwork consumes already resolved side/layer names; geometry is already in host coordinates.
- Draw board polygons, source drill circles/crosshairs and designer-authored support rings from accepted data. Never substitute module body bounds for source footprints or synthesize missing geometry.
- Clearance/service draws only existing source volume/opening polygons and retains qualification metadata.
- Show existing error markers only when they belong to a module on the current host board and the module findings layer is visible. Shared focused finding navigation remains its existing acceptance frontier.
- Update only private presentation composition and CSS; reuse existing project formats, Core geometry and transient state.
- Owning-module selection/navigation remains explicitly required by F5.4. This slice does not introduce an inert selectable role before that action is mounted.

## Testing Decisions

- Run one affected strict page WASM compile/check and the changed paired browser journey; no new tests for ordinary reversible UI.
- Reuse the VIK above/below portable fixture and existing source footprint/document preservation evidence. Pin the actual reference default/all-visible artwork and module finding changes before implementation.
- Compare source outlines, holes/supports, artwork and marker geometry with the reference, exact label/order/defaults and host independence. Preserve empty-source limits explicitly.

## Out of Scope

Owning-module Parts navigation, general host finding navigation/focus and complete
PCB/workbench visual acceptance remain their existing parents/joins. No resolver,
CAD, circuit ownership, data format or fabrication readiness change is included.
