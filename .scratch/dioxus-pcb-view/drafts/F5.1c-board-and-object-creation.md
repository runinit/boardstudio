# Board and object creation from the PCB workbench

## Problem Statement

The PCB Objects pane omits the reference New board and Add object entrypoints. A designer cannot create an empty PCB or start placing a component from the workbench where they need it.

## Solution

Restore the board-picker plus action and the existing Add object inventory. Create a saved empty board and select it through the normal session path. Start a component from the selected PCB, then use the existing Layout placement interaction as TypeScript does.

## User Stories

1. As a designer, I want New board beside the board picker, so I can add another PCB without leaving my project.
2. As a designer, I want the new board selected and its generated Outline visible, so I can start designing immediately.
3. As a designer, I want a new board to use the existing name, thickness and envelope defaults, so it behaves like the TypeScript application.
4. As a designer, I want Undo/Redo and saved reopening to preserve board creation, so the new action participates in project history.
5. As a designer, I want Add object in PCB, so I can search the same accepted component catalogue.
6. As a designer, I want placement to target my selected board and layout, so components cannot be added to a stale board.
7. As a designer, I want Back to objects, search, categories and Browse all parts in their existing hierarchy, so the menu is familiar.
8. As a designer, I want disabled or superseded actions to leave the accepted project intact, so an old pane cannot navigate or write over newer work.

## Implementation Decisions

- New board proposes one existing ReplaceDocument edit through Session, using the reference empty board and generated part-envelope defaults. The action retains an exact captured scope/token/revision/generation/workspace owner.
- Navigate only after that operation is accepted and saved. An intervening board/project/workspace choice or accepted edit prevents stale navigation. Session owns durable history and persistence.
- Reuse the existing component catalogue, generator preparation, placement controller and Layout canvas. Extend the Add object action's admitted source workspace to PCB while retaining exact owner checks.
- Keep independent board creation and component placement as separate vertical tickets in one integration packet. Existing matrix/pair/script controls retain their own actual prerequisites and acceptance criteria; do not invent functioning affordances.
- No schema, provider, history or file-format changes. Roll back the private mounts if necessary; created board data remains readable by the existing format.

## Testing Decisions

No new tests for ordinary reversible UI. One root-owned affected check and a changed paired browser journey cover New board/select/Undo/Redo/reopen and PCB component chooser/placement. Reuse unchanged placement/history evidence and inspect only changed owner transitions. Preserve any reproduced RED and use the browser seam for its focused GREEN.

## Out of Scope

PCB artwork/findings, the shared status footer, geometry-script authoring, full matrix/pair migration and full F5/F3 qualification remain their existing tasks. Preserve all parent criteria and the refactoring ledger.
