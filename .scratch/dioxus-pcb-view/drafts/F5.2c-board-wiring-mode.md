# F5.2c: Edit selected-board wiring mode

## Problem Statement

The React PCB Wiring Inspector lets the designer switch the selected board between Matrix and Direct GPIO. The current Dioxus inspector shows the resolved mode as read-only text, so changing the board's wiring topology requires editing project data outside the interface. The existing project model, accepted edit path, and electrical resolver already support this behavior.

## Solution

Add the same board-level Wiring mode selector to the Dioxus PCB Inspector. Its value is read from the accepted selected-board electrical configuration. A change updates only that board's existing configuration through the normal accepted document edit/history path. The existing board-scoped resolver then refreshes from the newly accepted revision. This child does not add Apply, pin editing, controller selection, or protected remap behavior.

## User Stories

1. As a PCB designer, I want to choose Matrix or Direct GPIO for the selected board, so that the resolver plans the electrical layout I intend to use.
2. As a PCB designer, I want the displayed mode to reflect the accepted saved project, so that a rejected or unsaved edit is not presented as complete.
3. As a PCB designer, I want changing one board's mode to preserve its controller, locks, assignments, key bindings, jumper states and protected handoff, so that mode selection does not discard unrelated electrical configuration.
4. As a PCB designer, I want the selected board's new mode to drive the current plan after the edit is accepted, so that the view does not continue showing a plan resolved for the previous mode.
5. As a PCB designer, I want an old PCB control to be rejected after its project, board, session or selection context changes, so that a delayed interaction cannot edit another source.

## Implementation Decisions

- Keep all ownership private to the Dioxus PCB wiring feature and Editor-lifetime accepted-source owner. The Inspector receives a read-only projected mode and a typed action callback; it does not receive Runtime or writable document state.
- Use the existing `ElectricalMode` and `ElectricalBoardConfiguration` values and the normal `Event::Edit` / `EditOperation::ReplaceDocument` path. Do not add a request, contract, persisted field, or new public visibility.
- Scope the edit to the active board's configuration. Preserve all other board configurations and every field on the target configuration. If the target board has no configuration yet, create its existing default configuration with the selected board ID and chosen mode.
- Mirror the reference's behavior: the board-level control offers Matrix and Direct GPIO; it is absent from the selected-switch and selected-generic-part contextual Inspectors. A selected controller continues to use the board-level Wiring Inspector.
- Admit an action only while the captured accepted source is still current for the active PCB workspace and board, the editor is saved and ready, no preview or gesture is active, and the rendered board/selection identity still matches. Repeated selection of the already accepted mode is a no-op. The visible selector remains derived from the accepted document; do not optimistically claim a save.
- The existing resolver owner is keyed by the accepted board-plan identity, including snapshot token and revision. Accepting a mode edit naturally invalidates the old plan identity and starts resolution for the new accepted revision. Keep Resolve as the existing manual retry action.
- Preserve existing references' control placement, accessible name, values and selection behavior. Do not add a local draft or independent plan owner.

## Testing Decisions

- Exercise the production mounted editor action, not only a proposal helper: a valid current request changes only the selected board's mode through one normal edit; a stale project, board, session, revision, selection or workspace request submits nothing.
- Verify a missing board configuration gets the existing default fields and target board ID; an existing configuration preserves controller, locks, assignments, key bindings, jumper state and protected handoff. Verify other boards and unrelated document fields remain equal.
- Verify accepted mode is displayed, the old resolver result is no longer current, and a new resolution uses the selected mode after the accepted revision advances. A save/rejection failure must leave the accepted mode visible rather than exposing the requested value optimistically.
- In the paired browser journey, choose Direct GPIO, observe the accepted revision/save transition and current plan mode, Undo and Redo the edit, save/reopen, and verify the persisted selected-board mode. Confirm the other board's mode is unchanged.
- Reuse existing Runtime edit/history and electrical-plan identity tests. Run affected formatting, native, strict WASM, and packaged browser checks; report any check not exercised.

## Out of Scope

- Applying an electrical plan, controller choice, assignment locks/pins, existing-connection review/replacement, protected remap, manual part/net edits, firmware positions, or manufacturing readiness.
- Any Rust Core planning algorithm, schema, public API, generated contract, document serialization, or electrical semantics change.
- Closing F5.2, F5.3, F5.1, the shared shell, or the canonical parent acceptance graph.
