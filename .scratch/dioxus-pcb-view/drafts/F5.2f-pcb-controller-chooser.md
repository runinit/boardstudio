# Choose and place a controller from ordinary PCB wiring

## Problem Statement

The TypeScript Wiring Inspector offers Add controller when this board has no controller choices. Dioxus omits the action. Its existing controller chooser only admits an open Wiring setup guide, so reusing it from an ordinary imported PCB would do nothing.

## Solution

Expose the same Add controller journey from the board Wiring context: browse Parts filtered to controller, select a compatible definition, place it through the existing placement transaction, and return to this board's PCB wiring context. Cancel/back navigation preserves the existing design.

## User Stories

1. As a designer, I want Add controller on a board without controllers, so I can start wiring an imported board.
2. As a designer, I want Parts filtered to controller with the Objects pane available, so I can choose among the existing library candidates.
3. As a designer, I want the normal selected-part preview/settings and Place component action, so I can review the controller before placement.
4. As a designer, I want a placement preview and cancel, so browsing cannot write a component by itself.
5. As a designer, I want commit to use the existing accepted transaction and return to PCB, so the ordinary wiring plan can resolve the new controller.
6. As a designer, I want an old chooser/preview rejected after project or board replacement, so a controller cannot be placed in the wrong design.
7. As a designer, I want Undo and saved reopen, so the new controller follows normal history and persistence.
8. As a designer, I want existing setup-guide placement preserved, so its context and return behavior continue to work.

## Implementation Decisions

- Reuse the Parts catalogue, definitions, preview, placement adapter and Core controller edit path. Do not add an engine or choose a synthetic default definition.
- Introduce an explicit private ordinary-PCB browse origin beside the existing guided origin. Capture accepted project/session/board/token/generation and preserve it across the expected Parts→placement transition.
- Admit Add controller only from the current PCB board context with no controller choices and no competing canvas operation. Keep strict current-owner/revision/terminal checks throughout asynchronous definition loading and placement.
- The ordinary PCB origin does not silently open the setup guide. Guided origin retains its existing guide-stage requirements and completion behavior.
- Preserve board selection, pending/error feedback and no-mutation browse/cancel behavior. Reset or retire the intent on owner replacement/unmount.
- Use necessary private composition/placement interfaces. Any cross-crate widening must remain the narrow necessary facade already authorized by the user.

## Testing Decisions

One affected compile/check and the changed paired browser journey from the same VIK imported archive: Add controller→Parts filter→selected definition→placement/cancel or commit→PCB→Undo/reopen. Reuse sufficient existing placement owner/history evidence, add no ordinary-UI test matrix, and preserve existing regressions. A real reproduced bug gets its focused regression.

## Out of Scope

General Parts model viewer, generator rewriting, electrical resolver redesign, multiple-controller switching, existing-connection release and full PCB acceptance retain their existing tasks.
