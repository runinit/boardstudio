# Match the board Wiring context and diagnostic order

## Problem Statement

The PCB Inspector still presents a generic Electrical wiring heading, an extra Controller section, pin summaries without a controller and diagnostics after all assignments. The reference puts Wiring/controller/topology together and Review before handoff before firmware and assignments. This hides the main board readiness explanation in the Dioxus port.

## Solution

Port the accepted board Wiring panel hierarchy and typography around the existing resolver/edit owners. Designers see the same header, diagnostic priority and assignment count, with no change to their wiring.

## User Stories

1. As a designer, I want the Wiring title and current controller beside the topology badge, so I recognize the selected board context.
2. As a designer, I want pin summaries only when a controller is selected, so an empty board does not imply meaningful assigned pins.
3. As a designer, I want Review before handoff before firmware and assignments, so I can see the current Core errors first.
4. As a designer, I want the same assignment count and empty guidance, so I know what resolution produced.
5. As a designer, I want current mode, Apply, pin and protected-remap controls preserved, so presentation changes cannot alter accepted edit ownership.
6. As a designer, I want the board context to leave selected-switch/component panels unchanged, so contextual navigation stays familiar.

## Implementation Decisions

- Reuse the existing current-board Core plan, configured controller projection and guarded actions.
- Change only the private board presentation and its scoped CSS; do not alter resolver decisions, plan lifetime or saved data.
- Preserve pending/failure and durable edit feedback. Replace the extra invented readiness paragraph with the current diagnostic group at the reference position.
- Use the existing theme tokens and reference sizes, gaps and labels. Keep the base selected-part Inspector layout separate.
- The missing Add controller browse action needs an explicit PCB controller-placement intent. Its guided-only current owner is not broadened speculatively by this presentation packet; this remains a concrete next action gap.

## Testing Decisions

One combined affected page compile and one changed paired browser journey on the retained VIK fixture. Reuse existing electrical history/edit evidence; no new ordinary-UI tests or neighboring matrix.

## Out of Scope

Controller selection/browse intent, existing-connection release, general host finding/focus and full F5.2/F5.3/F5.5 acceptance retain their existing criteria.
