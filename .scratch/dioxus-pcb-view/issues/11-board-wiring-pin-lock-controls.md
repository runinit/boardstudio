# 11: Assign and lock current board wiring pins

**Parent:** F5.3 — Manual pin review, nets, and protected handoff. This child preserves the F5.2 resolver, F5.2c mode edit and F5.2d Apply contracts; none of those parents or joins close here.

**Reference:** `app/src/ui/WiringPanel.tsx` renders a pin selector and Lock/Unlock button for each current plan assignment. `app/src/useElectricalPlanning.ts` derives Matrix rows/columns, Direct assignments and peripheral rows, marks rows locked from `ElectricalBoardConfiguration.locks`, and offers the current pin plus resolver `freePins`. `app/src/main.tsx` writes selected pin values into the existing board `locks` map; Lock captures the current assignment pin and Unlock removes that key. Do not infer independent support from the presently unused `ElectricalBoardConfiguration.assignments` field.

**Capability-level start gate:** Existing current board `PcbWiringSource`, `ElectricalPlan` resolution, mode-owner identity/current-snapshot admission, `Runtime::observe_operation`, and normal `Event::Edit`/`ReplaceDocument` settlement are callable. A private action can edit the selected board's existing `locks` map and let the Editor-lifetime resolver refresh from the accepted revision. These consumed capabilities are present at the candidate base; no full F5.2 or F5.3 parent closure is required to implement this child.

**Behavior:** On the board-level Wiring inspector, render pin choices beside each current Matrix row/column, Direct assignment and peripheral pin. Keep the selected current pin available even though it is not in the free-pin list; offer the current resolver's free pins as alternatives. Choosing a different available pin records the exact assignment key and pin as a lock. Preserve the reference's `Unresolved` selection value as its existing empty-string lock entry; do not silently reinterpret it as Unlock. Lock records that row's current assigned pin; Unlock removes its lock. A locked row's selector is disabled and its button says Unlock. Rows without a current pin cannot be newly locked. Use the accepted selected-board configuration as the only saved state and the normal one-edit history/durability path. The Core resolver remains authoritative: locks may produce conflicts/findings, and such a plan must not be represented as ready merely because the user selected a pin.

**Boundaries:** No new public API, Core request, schema, file format, second plan store or independent pin allocator. Preserve every unrelated board/configuration field and every other lock. Scope actions to the current accepted session/document/board/revision, UI selection/generation, workspace, ready/saved lifecycle, no preview/gesture and matching current plan. Stale callbacks do nothing. Keep generic part terminal/pad nets (Issue 07), board wiring mode (Issue 08), Apply (Issue 10), protected remap, conflict-review actions, controller selection and full handoff acceptance distinct.

- [ ] Paired React/Dioxus board-level journeys show the same assignment rows, accessible `Pin for …` controls, selected values, current-pin-plus-free-pin options, and Lock/Unlock pressed state for the same accepted plan. Switch and generic-part contextual panes do not gain these board-level controls.
- [ ] Choosing a free pin changes only the selected board's matching `locks` entry; Lock captures the current pin; Unlock removes only that entry. Preserve other locks, assignments, key bindings, nets, other-board configuration and unknown project fields.
- [ ] A conflicting or invalid resolved plan remains visibly unresolved/not ready with Core diagnostics. Do not claim this control repaired the electrical plan until a fresh matching Core result says so.
- [ ] No-op and stale selection/board/revision/workspace/generation actions submit no edit. Accepted actions submit one exact `ReplaceDocument` edit; rejected, cancelled and persistence-failed outcomes retain the prior accepted value and use shared recovery feedback.
- [ ] After save the old plan is invalidated and the current accepted revision is resolved again. Verify one history entry, Undo/Redo and save/reopen, including a second board and unrelated locks.
