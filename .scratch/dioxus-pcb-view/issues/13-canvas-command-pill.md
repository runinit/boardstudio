# 13: Use the canvas command pill in the PCB workspace

**Parent:** F5 / PCB workbench parity, alongside F3.1 selection and F3.3 transform, align, and snap capabilities. This child does not close those parents or any canonical acceptance join.

**Reference:** The pinned React workbench (`app/src/ui/Workbench.tsx`) renders Select, Transform, Align, and Snap when the active view is PCB. Select changes the active matrix/row/column/key/part scope; Transform opens the current properties or selects the row/column context used by those properties; Align applies the selected-envelope command to the current selection against a distinct reference part; Snap exposes the same grid, geometry, and envelope-gap settings used by existing interaction paths. The paired PCB capture retained in `.scratch/dioxus-pcb-view/evidence/advanced-inventory-20261002/` shows the command pill in React and absent in Dioxus.

**Capability-level start gate:** The PCB canvas has an accepted board-scoped `Scope`, current selected `TreeContext`, context and scope generations, and clickable PCB part selection. The existing TreeSelect adapter projects Matrix/Row/Column/Key/Part scopes, `MoveParts` and matrix-transform operations are accepted edits, and the shared pill/menu UI plus Layout owner controllers are implemented. Implement this child against those callable seams; no completion of the broader Layout or PCB parents is required.

**Behavior:** Mount the shared command pill in PCB with its own exact-current PCB owner. Preserve the existing Layout owner and its Layout-only admission checks. Selection actions project from the current accepted board context and submit the existing typed selection request. Transform navigation opens the PCB Inspector on the current transform context; matrix/row/column/key fields use the existing accepted matrix-transform operation path, while a standalone component selection exposes accepted part-position fields. Align reuses the existing envelope policy and submits one normal accepted edit through `MoveParts` or the matrix transform operation. Snap edits the existing Editor-owned settings and feeds the active PCB movement path; expose geometry/gap values only when the consuming path uses them. Never duplicate geometry, snapping, locking, validation, or history policy in presentation.

**Ownership and stale-action rules:** PCB requests identify the accepted document/session/board/instance, token and revision, active workspace, current selection/context, and scope/context generation. Revalidate immediately before navigation or edit. Mutations require Ready + Saved with no display preview or active gesture, reject locked/constrained targets and stale reference/selection identities, observe the exact operation, and settle only from its accepted outcome. No-op commands submit no edit. Workspace changes invalidate PCB requests; Layout requests remain Layout-only. Menu/settings state does not create document history.

- [ ] Select Matrix/Row/Column/Key/Part against a legal board fixture, retain a cell anchor only when its matrix/row/column remains valid, update canvas selection and contextual Inspector, and reject stale requests after board/workspace/revision/generation changes.

- [ ] Align exposes React's six axis/bounds actions and a distinct reference choice; enabled state follows current selected envelopes and existing lock/constraint/splay rules. A changed align is one accepted edit, is undoable/redone once, and stale actions submit nothing.

- [ ] Keep Layout owner admission unchanged and verify both Layout and PCB route isolation. Selection/snap preferences create no document revision/history. Keep all edits board-scoped and preserve other boards/configuration.
