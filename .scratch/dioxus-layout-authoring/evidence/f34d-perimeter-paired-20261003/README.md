### Undo grouping source characterization

Source review of `OutlinePointCanvasOverlay` found that pointer-down creates one `outline-drag-{operation}` transaction ID. Changed pointer samples emit `EditPhase::Preview` with that ID; pointer-up applies its final sample and emits one `EditPhase::Commit` with the same ID when the point moved. The sample path passes the event's Alt state as the snap policy's free-move flag. In Core, outline previews return before revision advancement and before pushing Undo history; the single final commit pushes one prior document. The existing `core/tests/outline_versions.rs::first_point_edit_is_one_undo_step_and_preview_never_creates_a_saved_version` test covers that Core preview/commit history rule.

This source path does not reproduce a split Undo for one Alt drag. The earlier Dioxus stack also contained the intermediate `0.385 mm` point edit from the preceding probe, so its two Undo presses do not establish that the Alt drag itself created two history entries. No source defect or focused regression was reproduced, and no Layout source change was made. A clean isolated Alt drag followed immediately by one Undo/Redo remains necessary before claiming paired public history grouping for C05.
