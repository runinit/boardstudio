## Edit and policy boundaries

`core/src/model.rs` defines `MoveParts { positions }`, `SetMatrix { matrix, definitions }`, `SetMatrixSplay { matrix_id, column, change }`, `SetConstraint` and `RemoveConstraint`. `application/src/session.rs` accepts gesture begin/sample/end/cancel; Begin captures pitch, fraction, geometry-snap and optional gap, while Sample/End carry positions and live Alt. `application/src/interactions.rs::normalize_drag` snaps world X/Y positions and uses the shared board part snap helper. Those existing gesture events do not encode matrix row/column/cell-local operations. In addition, ordinary `Event::Edit` Preview uses no gesture generation, and GestureCancel invalidates only registered Gesture work; a late ordinary preview may still replace `ReadModel.display_preview`. Thus SetMatrix authority is sufficient for direct accepted field commits, not proof of safe pointer preview/cancel. RF-005 already records the matrix-local transform versus world-`MoveParts` distinction; this pass adds no new ID and does not claim member drag repair.

Current Dioxus `web/src/presentation/objects/layout_toolbar.rs` is the private F3.3a Select/Snap leaf; `web/src/presentation/layout_workspace.rs` mounts it. `objects/matrix_inspector_controller.rs` proves the accepted-snapshot/scope-guarded SetMatrix form pattern for structural matrix fields. Current selected-part inspector remains `MoveParts` X/Y. The candidate has operation authority and selection capabilities, but Transform/Align user controls and controllers are missing. Standalone part rotation is a separate, source-confirmed operation gap, not something this UI can implement using an existing `MoveParts` call.

Pointer transform preview/commit/cancel is a separate deferred capability and is not evidence for this child.

- Command pill: actual Select/Transform/Align/Snap working handlers together in one strip, separate view-switch group, menu/focus/cancel behavior and desktop/compact screenshots; no buttons added until their handlers exist.
