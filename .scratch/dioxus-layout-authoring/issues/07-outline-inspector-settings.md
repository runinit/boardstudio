# F3.4b: Configure the active Board outline

**Parent:** F3.4 — Outline editing and refinement UI. Parent criteria, dependency graph, history and acceptance joins are unchanged.

**What to build:** Complete the supported, non-point-editing controls in React's contextual Board outline Inspector: choose and rename saved versions; create an automatic outline when none exists; edit Generated or fixed-version corner/size settings, Generated bridge width and margin; configure generated gap repair, protected gaps and clearances; and preserve exact accepted/history/save behavior. Keep the existing Outline tree navigation and F3.4a copy/delete lifecycle as the authorities for their operations.

**Status:** implementing on the source-backed current private Layout owner. This child does not close F3.4a or the F3.4 parent.

- [ ] Render the Inspector from the current accepted Board and active `BoardOutline` only. Generated follows accepted component/keycap inputs; fixed settings/features come from the active accepted version. Do not create a second version/settings store.
- [ ] The active-outline control lists Generated and accepted saved versions. Choosing a value uses the existing scoped `SelectOutline` operation; selecting the Outline parent preserves the current active version. Renaming is available only for a saved version and uses existing `RenameOutline` validation/Undo history.
- [ ] Add object → Board geometry → Board outline opens the same accepted Outline Inspector from Layout or PCB. It routes the current board through the existing scoped Outline tree selection; it does not create or cache a second settings/version state.
- [ ] When no Generated `part-envelope` feature exists, offer Generate automatic outline. It adds one uniquely identified feature to the selected board through the existing edit/document history path. Do not duplicate an existing generator or alter another board.
- [ ] Provide the source-backed settings controls: Generated margin and bridge width; sharp/fillet/chamfer corners and applicable radius/chamfer size for Generated or fixed versions; and Generated automatic cleanup, maximum gap span, minimum connection width, and PCB edge clearance. Fixed versions do not expose bridge width in pinned React. Commit only finite values in the supported ranges. Enter commits by blur; Escape restores the accepted value.
- [ ] For each accepted Generated gap, display its span and Keep gap state. Toggling it updates the source-linked protected-gap definition on its generating part-envelope feature using the accepted scene control points; removal affects only matching stable/protected gap IDs. Hide Generated-only controls for fixed versions.
- [ ] Every mutation is admitted against current Layout workspace, full scope/session/document/board, accepted token/revision, generation, target membership, saved/readiness and no active preview/gesture. Register and correlate the exact operation outcome before submit. Retain pending settlement while the Inspector is hidden; report Saved only after the intended accepted state and current revision durability agree. Retry uses fresh operation/transaction IDs.
- [ ] Reconcile fields and version choices from accepted state after Undo/Redo, source replacement, save/reopen, version activation/removal and board/session changes. Reject stale callbacks and preserve normal matrix, row, column, key and component Inspector routing.
- [ ] Add mounted production-owner tests for accepted settings/rename/gap mutations, stale callbacks, generated feature creation, saved-version settings, exact outcomes, Undo-relevant Core history and keyboard draft commit/cancel. Keep public paired history/save-reopen journey as part of F3.4/F3.7 acceptance, not as a source-only test substitute.
- [ ] Do not expose unwired controls. Perimeter-point drawing/editing, manual additions/cutouts, bridge editing, refinement propagation and outline finding navigation remain open F3.4 work; do not claim this child completes them. Preserve their existing parent criteria.
- [ ] Update existing RF-001/RF-006/RF-009 evidence where applicable. Record “No new refactoring takeaway observed” if this bounded work adds no distinct issue.
