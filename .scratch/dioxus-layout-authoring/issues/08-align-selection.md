# Draft F3.3c — Align a Layout selection to a same-board reference

**Parent:** F3.3 — Transforms, constraints and snapping. **Reference:** React pin `5a472a9426e6e38993361da402cd4ec730feb369`; source/browsing evidence and review requests are under `evidence/transform-align/`.

## Goal and start capability

Add the actual Align menu to Layout and make its six alignment commands move the current live selection once relative to an independent real reference part. The existing Dioxus selected-context and accepted membership adapter identifies real selected IDs and active board; Core already accepts SetMatrix for matrix-owned geometry and MoveParts for part positions. These are sufficient capabilities to start a narrow private alignment adapter after the proposed source/standards reviews agree on its envelope source. Do not wait for whole F3.1/F3.2 acceptance, and do not change F3.3's canonical joins.

The alignment delta is a small private port of the pinned React policy, not a new domain/public API. Resolve live definition courtyard corners (or the current switch keycap envelope where React chooses that envelope), transform them by accepted pose, calculate the combined axis-aligned min/center/max coordinates and apply a single X or Y delta. If the candidate's accepted ReadModel lacks the exact source envelope needed for a target, disable the action and report that specific unsupported target rather than guessing a box or using board-level contours.

## Behavior

- The reference picker contains current visible real parts from the active board, excluding selected IDs and React's exact linked-selection partner set. When `partnerLayout` exists, React sets `linkedSelection = scope.kind !== 'component' || (activePart && matrixPartLookup.has(activePart.id) && !matrixPartLookup.get(activePart.id)?.assemblyId)`; if true, it excludes **the entire partner matrix's `partIds`**, even for a one-key/column selection. A selected assembly child component follows the component exception and does not trigger that exclusion. Preserve the current reference if it remains eligible; otherwise default to the first eligible reference. The reference itself never moves.
- Actions: Left, Center X, Right, Top, Center Y, Bottom. Rotated outlines use axis-aligned bounds of transformed courtyard/keycap-envelope corners, matching `selectionOutline` plus `alignmentDelta` in React. One click applies one delta; no repeated nudge or snap pass occurs.
- Matrix selection changes matrix origin with SetMatrix. Row/Column selection changes the corresponding accepted matrix-local offset with SetMatrix; Row is disabled because a row may cross columns with independent splay. Key and supported real-part selection use the existing MoveParts path and existing Core linked-member behavior. Align must not silently broaden membership beyond the currently resolved selected IDs.
- Disable six actions when there is no current live target/selection, when any moving part is locked or constraint-driven, or when scope is Row. Explain the disabled state using the corresponding React message. A locked/driven reference can remain selected as a fixed target if React permits it; it is never mutated.
- Admission is root-guarded by Layout workspace, captured/current full Scope and root generation, accepted token/revision, current active board, current selected IDs, current reference membership and current constraints/lock values. A stale action is a no-op with no document revision/history change.
- The reference picker is a root-lifetime preference independent of moving-selection changes: retain its current real reference while it remains eligible, and replace it with the first eligible reference only when it becomes ineligible. Each alignment button is an immediate command, not a geometry draft: key its exact OutcomeSlot/request identity by full Scope, moving target, reference, and command; register before submit, and settle only against that captured tuple after accepted token/revision advance or while the panel is hidden. Never auto-replay a failed command; another click is a fresh explicit retry. Escape dismisses the unsubmitted picker/menu state; Scope/target loss clears local feedback, while an admitted outcome settles for its original target and cannot retarget.
- No Relationships button is added until F3.5 supplies a real destination route. Do not add constraint creation/editor UI here.

## Acceptance

- With a same-board fixture, align standalone parts, a populated key/cell, matrix, and column selections against chosen references for all six anchors. Compare target/reference bounds and resulting accepted matrix/member positions with React; prove the reference is unchanged and one Undo restores exactly the prior accepted state. Save/reopen and redo. Include a linked pair and verify the entire partner matrix is excluded for matrix/key/row/column/primary-component moving contexts, but not for a selected attached assembly component.
- Verify rotated footprint and switch/keycap envelopes, linked mirrored layouts/counterparts, no eligible reference, changed/deleted reference, cross-board isolation, no selected IDs, locked moving member, constrained target, locked reference, row scope, and stale callback after context/workspace/revision change. Each unsupported or blocked case has no mutation and clear UI feedback.
- Use the same saved fixture/source identity in both public apps; record real adapter operation, changed IDs, revision, Undo history and console. A helper-only delta test does not satisfy the public journey.
- Keep alignment edits independent of snapping preferences; do not add a second geometry engine, direct document mutation, fictitious dimensions, or public API/member visibility. No new RF ID; preserve the source-confirmed RF-005 boundary between matrix-local and world-position gestures.
