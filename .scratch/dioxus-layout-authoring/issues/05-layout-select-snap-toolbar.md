# F3.3a: Layout select and snap toolbar

**Parent:** F3.3 — Transforms, constraints and snapping.

**What to build:** Add the real Layout Select-mode and snap controls to the private Dioxus Layout composition. Keep mode/settings in one root-owned transient adapter and route them through the existing scoped selection and Session gesture paths. Do not add a second selection/document store, new Session event fields, Core algorithms, or decorative Transform/Align/Relationships controls.

**Capability-level start:** The required source path is already available on the saved REVIUNG41 fixture: the T1-10 private tree adapter exposes current `TreeContext`, current-scope selection and live `resolve_selection`; `Session` accepts `SelectParts` and the existing gesture begin/sample/end/cancel events; `application::interactions::normalize_drag` accepts the existing snap options. This child may start from that proven capability without waiting for full F3.1 or F3.2 acceptance. Preserve the canonical graph: F3.3 remains start-after F3.1 and acceptance-after F3.2; F3.3a adds only its own capability evidence and does not change parent/62-parent criteria or joins.

## Scope and state ownership

- Add a private Select control with Matrix, Row, Column, Key and Part modes. Root owns one `LayoutSelectionKind` preference for the current Editor lifetime. Keep it separate from `application::SelectionMode` (`Replace`, `Add`, `Toggle`, `Range`), which carries pointer modifiers.
- The Select menu updates an existing valid matrix context immediately. If there is no current matrix context, changing the menu updates only the preference and the next unmodified canvas hit uses it. Apply the same preference to subsequent canvas cell/part selection and its selected-ID target set; do not make a one-shot tree-selection-only menu. This does not establish matrix/row/column/cell drag operation semantics.
- Reuse `presentation::objects::{context_for_part,context_for_cell,resolve_selection}` and the current private `TreeContext`/scoped selection adapter. For a live matrix cell hit, convert the actual source context to the selected Matrix/Row/Column/Key/Part context against the fresh accepted `ReadModel`; use only live enabled members belonging to the active board. Matrix/row/column resolution includes live enabled assembly companions as already defined by the tree resolver. Key resolves its real primary member. Part resolves only a real live part. If the chosen Part mode hits an empty cell, retain its semantic cell context and empty selected-ID list; never create a placeholder part ID. A standalone real part remains a component target.
- Preserve the current Shift/Ctrl/Cmd pointer-selection mapping. Do not fold rectangular-range behavior into this child; F3.1/T1-10 owns the existing modifier contract and any separately tracked range correction.
- Root owns one private transient `LayoutSnapSettings` containing the fraction (`0` off, positive unit fraction, negative mm value), geometry-snap toggle, envelope-gap toggle, and gap text draft. The private toolbar updates this root-owned preference; the same state is available to Layout consumers without a second snap policy. This child wires Layout drags; complete placement and outline journeys remain in F3.2/F3.4. The text draft remains editable when geometry snap is off; only the gap toggle is disabled. Parse effective overrides as finite nonnegative mm values; blank/invalid text follows React's current fallback to selected matrix `edgeGap.x`, then 1 mm. Send `gap=None` unless geometry and envelope-gap snapping are both enabled.
- Defaults are ¼u, Geometry snap on, Envelope gap on, blank override. Supported options are Off, ⅛u, ¼u, ½u, 1u, 1 mm, 0.5 mm, 0.1 mm. Positive fractions use the current accepted matrix pitch for a matrix-owned target; millimeter options use world units. Preserve the current 19.05 mm × 19.05 mm pitch fallback only when no accepted owning matrix exists.
- Copy pitch, fraction, geometry-snap and optional gap into the existing `Event::GestureBegin` for that newly admitted drag. `GestureSample` and `GestureEnd` carry positions plus Alt only: Alt remains sampled throughout the gesture and bypasses both grid and geometry snapping. Settings are captured per gesture; changing a toolbar control cannot mutate an active gesture. Do not widen/replace Session events or run `normalize_drag` a second time in presentation.
- Project and clear `ReadModel.snap_guide` using existing gesture/read-model lifecycle. Footer status reflects selected grid label and geometry-snap on/off. X/Y footer values match React's active selected-part world pose, or `0.00` when there is no active part; they are not pointer-hover coordinates. Do not include Fit, Findings, Transform, Align or Relationships in this child.
- Keep selection and snap callbacks guarded by current Layout workspace, full current `Scope`, root presentation generation, fresh accepted token/revision and live board membership. Root composition owns these guards and callback translation. All edits/history remain in application/Core; this child changes no durable document data by changing modes or snap preferences.

## Acceptance

- [ ] Mount the controls in the Layout toolbar and footer only; other workspace toolbars are unaffected. Keyboard activation, focus, compact layout and light/dark themes remain usable. Transform, Align and Relationships are not represented by inert controls.
- [ ] On a real matrix fixture, choose each Select mode and verify active context, live selected IDs and Inspector synchronization. Verify the preference also controls the next unmodified canvas cell/part hit and its live selected-ID set. When there is no selection, changing mode changes only the preference. Preserve current Shift/Ctrl/Cmd behavior. Board/workspace switch or stale callback cannot affect the new context.
- [ ] Cover populated and empty cells. Matrix/row/column selection uses enabled live accepted scene membership and includes live linked companions. Key selects only the real primary member. Part selects only a real part; an empty cell stays a semantic context with no fabricated domain ID and no accidental document edit.
- [ ] On the same saved REVIUNG41 project, compare React and Dioxus for Off, ¼u, 1 mm, 0.5 mm and 0.1 mm on drags of one real standalone board part that is not a matrix member. Verify the unit fraction uses the existing 19.05 mm fallback for a part without an owning matrix, and mm steps use world coordinates, and values are captured by GestureBegin. Verify a finite nonnegative gap override and the 1 mm fallback for this standalone selection. The selected-matrix `edgeGap.x` fallback remains part of the matrix-gesture contract and is not certified by a standalone drag. The gap text remains editable while geometry snap is off, but is excluded from the gesture; re-enabling geometry applies the existing draft and active gap toggle.
- [ ] Toggle Geometry snap and Envelope gap, verify correct disabled state and resulting guides, then Alt-drag and verify Alt bypasses both. Guides appear only for an active snap and clear on commit/cancel. A preference change during a drag does not alter that gesture's captured options.
- [ ] Each completed drag remains one normal Session/Core Undo step; Undo/Redo and save/reopen preserve the accepted geometry. Escape, pointercancel, lost capture, board/project change and workspace exit cancel each tested standalone-part drag, clear guides and leave accepted geometry unchanged. Include stationary click and sub-threshold nonzero drag so this child cannot mask F3.3's existing interaction mismatch and cancellation gates. Do not use a matrix, row, column, key or assembly-component drag as evidence of transform/local-snap parity; leave those traces open under F3.3.
- [ ] Verify the selected-part X/Y readout, grid label and Geometry snap status. No pointer coordinate, fit, findings, Transform, Align or constraint parity claim is required.
- [ ] Run paired public browser journeys against the same saved fixture and report actual build/source identity, console errors, geometry/history and scope evidence. This child does not close F3.1, F3.2, F3.3 or F3.7.
- [ ] Record an RF handoff with reviewed scope or state “No new refactoring takeaway observed.” Do not change the global RF register except through its owner.
