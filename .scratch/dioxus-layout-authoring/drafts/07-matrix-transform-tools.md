# Draft F3.3b — Matrix transform properties

**Parent:** F3.3 — Transforms, constraints and snapping. **Reference:** React pin `5a472a9426e6e38993361da402cd4ec730feb369`; behavior inventory and review requests are under `evidence/transform-align/`.

**Focused paired receipt:** [Selected Column/Key transform journey](../evidence/f33b-matrix-transform-paired-20261003/README.md). The paired edit/Undo/Redo/reopen path matched for a Column offset and Key-local X. The receipt also records a candidate-only generic world-position inspector on Key context; the isolated composition correction still needs a rebuilt public candidate check.

## Goal

Make matrix-owned position/orientation, row/column offsets, stagger/splay/origin, and key-cell local transforms editable from the selected Layout context through existing SetMatrix and SetMatrixSplay operations. Provide working Transform navigation shortcuts to those mounted properties. This child does not implement Stagger/Splay/Origin pointer tools: the current Session's ordinary Event::Edit preview path does not have gesture-generation cancellation or a clear-preview event, so a late canceled preview could replace `ReadModel.display_preview` and remain visible/block edits. Existing Core SetMatrix/Splay authority alone is not proof of safe pointer preview/cancel behavior. This is a bounded child of F3.3; it does not change its canonical `start_after=[F3.1]` or `acceptance_after=[F3.2]` edges and does not claim either parent accepted.

## Capability start

This slice may begin from the existing T1-10 selected-context/current-scope adapter, accepted live matrix/column scene, and fresh `Event::Edit` **commit** paths for Core `EditOperation::SetMatrix` and `SetMatrixSplay`. The matrix structural inspector work provides the private accepted-matrix form/admission pattern, but its whole acceptance is not an extra start gate. Verify the exact current source and coordinator's registration/mount seam before coding. Do not use normal `Event::Edit` Preview for live pointer drags unless a separately reviewed root-owned preview/restore protocol proves stale/cancelled results are suppressed and `display_preview` is cleared without a document revision. `Event::GestureCancel` applies only to registered Gesture work; it does not invalidate a normal Event::Edit preview. Do not add a Session/Core/public API as part of this child. Parent and 62-parent joins remain untouched.

## Scope

- For a live matrix context, expose matrix origin X/Y, rotation, and Mirror with React's linked-layout restriction on the incompatible mirror axis. Name, dimensions, pitch, assembly preset, diode direction and edge-gap preview remain the earlier structural-inspector ticket's ownership; do not duplicate them. Matrix selection remains the same semantic selection; fields do not create a second document or selection model.
- For Row/Column context, expose Position & rotation offsets X/Y with reset; Column additionally exposes numeric Stagger. For Column, expose numeric Splay angle, origin mode (Column base/Custom), origin X/Y, and affects (This column / This and following). Do not expose Pick origin here: it arms a canvas pointer tool and is deferred with Stagger/Splay/Origin handles until the cancellation prerequisite below is proven. For Key context, expose local X/Y and cell rotation/reset. Empty cells retain semantic context and use the real accepted matrix/cell; no part IDs are manufactured.
- Position & rotation, Splay & origin, and Row offsets are working navigation shortcuts only when the destination form for that current context exists. Numeric Stagger, Splay angle, origin mode/coordinates, affects policy, offsets, matrix origin/rotation/mirror and key-cell local offset/rotation submit one current accepted field value through existing SetMatrix/SetMatrixSplay commits. Fields use the source validation, do not preview on each keystroke, and do not expose writes to structural F3.2d fields.
- Use the matrix Inspector's reviewed direct-edit lifecycle: one unconditional root-lifetime owner keyed by full Scope/target/field identity, with the current accepted field value as the draft baseline. Register the exact OutcomeSlot/request identity before submit. After the matching operation advances token/revision or settles while the panel is hidden, merge that field against fresh accepted state; an unrelated field change must not erase a dirty draft, while a changed accepted value for the same field marks the draft conflicted and keeps it correctable. A failed field can be explicitly retried as a fresh request; it is never automatically replayed. Escape cancels only the unsubmitted draft and clears its local feedback. Scope/target loss clears draft/feedback; an already submitted operation settles only its captured owner and cannot retarget.
- Do not add Stagger/Splay/Origin pointer-tool menu actions or handles in this ticket. They require a proof-backed Session/UI preview/restore/late-result protocol first; if such an existing private protocol is discovered and independently reviewed, the coordinator may create a later child. Until then those actions remain an explicit F3.3 capability gap; do not mimic them with a no-preview or un-cancellable drag.
- Root owns `Scope`, workspace, presentation generation, accepted read projection, selection, gesture lifetime, and Runtime submission. The feature receives immutable current projection and typed edit/tool intents. Revalidate current matrix ID, scope, token/revision, board and cell membership synchronously before accepting an intent. An already-admitted operation settles for its exact captured owner; it cannot be redirected to a new matrix after board/workspace switches.
- For this fields-only slice, invalid input or a rejected/stale operation leaves accepted values and history unchanged; accepted edit creates one Undo step and survives save/reopen. Pointer transform gestures and their preview/cancel/final-sample requirements remain outside this child until the missing cancellation capability has been reviewed.

## Explicit exclusions / source gaps

- Standalone component Position X/Y remains the existing inspector. Core `MoveParts` only contains positions; no standalone-part rotation operation was found, so do not show a standalone Rotation field or claim that the Position & rotation shortcut is complete for that context. This child does not fabricate a pose operation.
- Key/cell local rotation is a SetMatrix field and is included, but arbitrary drag of a matrix member is not accepted as equivalent. Keep RF-005's local-vs-world drag gap and existing F3.3 parent gesture thresholds/cancellation gates visible.
- Alignment and constraints are separate F3.3 children. Relationships navigation stays with F3.5. Snap preference/UI ownership stays with existing F3.3a; reuse it without duplicating snap state.
