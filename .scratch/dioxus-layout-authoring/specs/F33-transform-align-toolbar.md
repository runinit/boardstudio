## Problem

The pinned React Layout command pill combines Select, Transform, Align, and Snap. It exposes real matrix-transform tools, transform-property navigation, and reference alignment. The paired Layout capture shows Dioxus currently separates Select and Snap, adds a selection-context chip, and has no Transform/Align controls. The existing F3.3a scope owns Select/Snap behavior; this pass must extend that work without duplicating it or presenting controls whose edit path is absent.

## Source-backed behavior and ownership

The full per-control inventory, source paths, candidate capability classification, browser observations, and retained screenshot hashes are in [source-and-browser-inventory.md](../evidence/transform-align/source-and-browser-inventory.md). The important behaviors are:

- Transform has Stagger, Splay, Origin, Position & rotation, Splay & origin, and Row offsets. Stagger arms a real row/column pointer operation. Splay and Origin arm column tools; Splay exposes angle/origin settings, and Origin picks a real world point. Property shortcuts navigate to context-appropriate Properties rather than being separate edit authorities. Matrix/row/column/key numeric property commits can start from the existing SetMatrix/Splay paths. Pointer tools require a separately proven cancel-safe preview path: normal Session Event::Edit previews have no gesture-generation suppression, and GestureCancel does not invalidate them or clear their display preview. Do not include Stagger/Splay/Origin handle commands in a ticket until this specific capability is established and reviewed.
- React writes matrix origin/rotation, row and column offsets, column stagger/splay/origin, and key-cell local offset/rotation with existing `SetMatrix` and `SetMatrixSplay` paths. Stagger changes local matrix offsets. Splay affects the selected column or that column and following columns. Pointer cancellation, Escape, capture loss and final pointer-up sampling retain their normal gesture behavior.
- The existing Dioxus edit path has Core `SetMatrix`/`SetMatrixSplay`, Session `Event::Edit`, current accepted matrix scenes and a reviewed matrix structural inspector path. This proves a start for direct transform-field commits, not cancel-safe pointer previews. The new transform adapter can submit the existing operations with exact scope and normal accepted-feedback/Undo ownership; it must not route matrix-local offsets through world `MoveParts`. F3.2d continues to own the matrix's name/dimensions/pitch/assembly/diode/edge-gap structure; F3.3b adds transform fields only. A later pointer-tool start requires a reviewed root-owned protocol that suppresses late canceled previews and clears the exact pending preview without a durable revision; do not widen Session/Core APIs or imply GestureCancel does this today.
- `MoveParts` carries X/Y positions only. No standalone-part rotation edit operation was found in the pinned Core model. Do not show a standalone Rotation field or a misleading Position & rotation route until an existing authorized operation is identified. Existing selected-real-part X/Y editing remains its current inspector owner. Matrix and matrix-cell rotation use `SetMatrix` and are in the matrix-transform slice.
- Align offers Left, Center X, Right, Top, Center Y and Bottom plus a Reference part picker. Targets are current visible same-board real parts excluding the moving selection and React's exact linked-selection partner set. With a partner layout, React marks linked selection for all non-component scopes, and for a primary matrix component (the `matrixPartLookup` entry has no `assemblyId`); when true it excludes the **entire partner matrix `partIds`**, not merely geometrically corresponding/moving members. An attached assembly component follows the component exception. The reference remains stationary. Selection bounds are axis-aligned bounds of transformed courtyard/keycap-envelope corners. A matrix selection adjusts matrix origin; row/column selection adjusts the corresponding matrix-local offset; Key/component selection uses the existing move operation. Row alignment is disabled because rows can cross independently splayed columns. Selected locked or constraint-driven targets disable the six actions; a fixed reference is not itself moved.
- Relationships in the React Align menu navigates to the separate Relations inspector. That navigation belongs to F3.5, whose inspector route is currently absent. F3.3 children must not add a dead menu action or duplicate the F3.5 relation editor. Add that menu item only when its real F3.5 navigation target is mounted.
- The final command pill is a composition join, not an excuse for placeholder buttons. It contains the already-implemented Select and Snap menus from F3.3a and the real Transform and Align menus from this work, with the view selector remaining in its separate group as in React. Root/composition owns placement and shared styling.

## Acceptance shared by the children

- Use the same saved, imported Layout fixture and current build/source identities in React and Dioxus. Record actual operations, accepted matrix/part values, scope/context, revision/history and errors; menu screenshots alone do not prove editing parity.
- Use fresh `Scope`, active workspace/presentation generation, accepted token/revision, live selected-board membership and current context at action admission. Stale callbacks, switching boards/workspaces, target deletion or changed selection cannot retarget an edit. A submitted operation settles against its captured target and exact transaction; new contexts do not inherit stale drafts or feedback.
- Maintain one Session/Core edit authority. Matrix offsets/rotation/stagger/splay/origin and cell-local fields go through the matching existing SetMatrix or SetMatrixSplay operation. Align uses SetMatrix for matrix-owned contexts and MoveParts for supported real-part contexts. Field edits verify accepted commit, rejection, Escape of unsubmitted draft, and one-step Undo/Redo. Pointer preview/commit/cancel and capture behavior apply only to any separately reviewed pointer-tool child; they are not claimed by the fields-only child.
- No fabricated IDs, mutable document copies, second selection store, new public/member visibility, Session/Core/schema changes, or React redesign. A required operation absent from current source is recorded as a precise blocker, not represented by an enabled no-op control.
- Verify desktop and compact toolbar placement, keyboard operation/focus, light/dark appearance, tooltip/accessible labels, menu open/close and Escape. The command pill order is Select, Transform, Align, Snap; the Design view-toggle remains separate. The context chip does not substitute for the command pill.
- Capture paired public outcomes and actual candidate build identity. Do not claim F3.3 or F3.7 acceptance from a child pass. Keep RF-005’s matrix-local versus world-MoveParts source distinction and its validation matrix until the remaining public scope traces are proven.
