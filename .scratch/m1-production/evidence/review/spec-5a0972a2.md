# Spec review: `5a0972a2` (optional CAD result bodies)

**Result: no blocking Spec findings.** The production change in `web/src/cad_worker.rs` treats an omitted `bodies` field as an empty list and rejects a present non-array value with an explicit decode error. Arrays continue through the existing per-body validation. The pending caller receives the decoder error through the normal `Result` settlement path instead of losing its reply after the pending entry has been removed.

This matches the M1 requirement that STEP use an independent export cache and deliver manufacturing geometry from the accepted snapshot (`.scratch/m1-production/spec.md`, user story 25; `.scratch/m1-production/issues/05-step-export.md`). STEP-only export replies may contain the STEP payload without preview body meshes; requiring `bodies` there incorrectly rejected a successful provider result. The change does not weaken archive/STEP identity guards, revision checks, or validation of body arrays, and it does not modify provider payloads, public production APIs, persisted schemas, or frozen budgets.

The added `test_cad_worker_request` symbol is guarded by the `test-harness` Cargo feature. It drives the existing `CadWorker::request` path against an actual browser Worker to check omitted and malformed `bodies`; the release builder's production feature selections omit `test-harness`. The test seam therefore does not widen the production API or replace real UI acceptance.

**Review basis:** compared `web/src/cad_worker.rs` and its evidence delta from `fe2ada03` to `5a0972a2`; inspected the M1 specification, acceptance ledger, and ticket 05. Candidate evidence records a browser red-to-green regression, real Sofle export/download and URL lifecycle checks, and native/format/strict-WASM checks. The full maintained-source release remains a separate acceptance gate; this review does not claim M1 completion.
