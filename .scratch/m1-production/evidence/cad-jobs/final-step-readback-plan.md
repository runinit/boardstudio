# Final REVIUNG STEP readback and release resource observations

Prepared for the final retained UI download `web/target/builds/m1-release-20261001-8f509433/qa-reviung41.step` (13,662,781 bytes; SHA-256 `f946d69c2ad39abd3f799ca996067d7f89dba7cc361a9516251c9e32307722f4`). Parent authorized correctness-only lifecycle/readback during a separate correctness window after the paired pointer timing attempt failed. This work makes no performance claims and does not overlap the reference-app timing session.

Run `node .scratch/m1-production/evidence/cad-jobs/inspect-final-reviung-step.mjs` from the integration checkout. The script invokes the exact public `cad/src/index.ts::readStepModel(Uint8Array)` API, records its bounds and mesh, computes the public returned mesh's signed tetrahedral volume, and independently imports the same file through the installed `libcascade` STEP reader to calculate BRep volume, solid count, and bounds. It writes `readback-final-reviung41.json` next to the script. The source was syntax-checked only before this authorized correctness window; readback remains pending.

The final release's `fixtures/reviung41.json` SHA-256 is `b577dd2009fffbf00489cc8d0f2ccc088861f62a7f30af42470d35c11534bdae`, and final release CAD JS/WASM hashes match the earlier 58-body configured/flipped oracle (`60f0f79a…d03e` and `408f80e7…8719`). That oracle used a different accepted input/configuration: it reported 58 prepared bodies, while the final public UI's default REVIUNG41 Preview/Exact reply contained four bodies. Therefore, do not interpret raw volume differences against its configured/flipped oracle as a regression or claim accepted-input parity. The prepared script instead checks whether the public `readStepModel` mesh for the actual final default STEP agrees with an independent BRep import of those same bytes. A same-input reference comparison requires capturing the default fixture/settings through the public archive path after the timing gate. `readStepModel` itself returns mesh and bounds, not volume; the independent native reader supplies the BRep volume. The script deliberately records deltas and does not assert an assumed value. The run completed successfully: public mesh had 41,736 vertices, volume 217,359.0776248333 mm³, bounds [-1.526, -90.879, -6.6] to [288.450, 17.090, 5.0]; independent STEP BRep readback found 5 solids, volume 217,359.08077987254 mm³, and matching bounds. The volume difference was -0.0031550392 mm³. This establishes internal same-file mesh/BRep agreement only; accepted-input parity remains unverified. Full measurements are in `readback-final-reviung41.json` and concise results in `readback-final-reviung41-summary.json`.

## Browser observer results

`renderer-resource-probe.init.js` is a page init script for the final release. It was loaded before navigation in the authorized correctness window using `agent-browser open --init-script <file> <url>`. Call `__m1ResourceProbe.mark(label)` to snapshot page-created Worker/explicit termination counts, RAF request/fire/cancel/drain state, event-listener add/remove counts by target/event, DOM observer lifetimes, Blob URL create/revoke counts, and compact worker reply metadata. It computes per-body signed mesh volumes for Preview/Exact replies without retaining vertex arrays.

Captured root-page snapshots cover Sofle Left/Right mount, scope clear/remount, a successful Right STEP export, cancellation of a Left export by switching scope, a subsequent fresh Right generation, and default REVIUNG preview/exact/STEP export. Across observed scope changes the departing CAD worker was explicitly terminated and departing ResizeObserver disconnected; each ready scope had one live core and one live CAD worker, one active resize target, and no pending RAF. Both completed STEP exports had Blob URL create/revoke pairs; the stale export created no URL. Full raw snapshots are in `final-resource-snapshots-8f509433.jsonl`, with selected transitions in `final-resource-summary-8f509433.json`. The probe's tracked listener counts observe explicit add/remove calls; automatic cleanup via `{once:true}`, `AbortSignal`, or garbage collection may not produce matching remove calls. Worker counts cover page-constructed dedicated workers, not a worker spawned internally by another worker. The probe adds computational work while scanning Exact/Preview mesh vertices; it was used only in a correctness window and the owned browser session was closed afterward. Runtime `Drop` source closes the core/CAD/export workers and cancels queued animation frames, but no actual tab-close path or late-import race was induced, so those remain source-inspected rather than browser-verified.
