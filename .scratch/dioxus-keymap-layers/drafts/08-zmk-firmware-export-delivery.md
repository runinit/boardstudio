# F6K.4c: Deliver qualified ZMK firmware output

**Parent:** F6K.4 — Encoder bindings, PCB firmware-position editor, and ZMK export handoff.

**What to build:** From the existing Keymap “Export ZMK source” action, a designer can request firmware for the accepted selected board, understand qualification/readiness failures, and download the same ZMK package produced by the current Core firmware provider.

**Blocked by:** F6K.1 Keymap mount/projection and F6K.2 supported Keymap edit path, matching the canonical F6K.4 start gates. The actual private Runtime/CoreWorker firmware-provider and browser-delivery route is an implementation gate for the complete integrated behavior; fixture-only request behavior cannot satisfy this ticket. This describes a missing implementation port, not a new canonical task-graph edge.

**Parent acceptance joins:** F5.2 selected-board electrical/readiness data and F8.2 reusable provider/snapshot/browser-delivery integration remain the exact F6K.4 acceptance joins. Do not add a whole F5 or F8 dependency or close either parent from this slice.

**Inspector presentation parity:** Keep the active Keys, Macros, or Encoders editor ahead of the export action. Place “Export ZMK source” after the active editor as the full-width primary action, followed by the existing local-source helper note. Match the pinned React Inspector's content inset, heading rule, and section rhythm. Preserve the current callback, enabled state, provider authority, and delivery lifecycle.
