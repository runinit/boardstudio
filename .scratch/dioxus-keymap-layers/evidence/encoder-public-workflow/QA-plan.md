## Public test sequence

1. **No canvas key selected / initial projection.** Enter Keymap without selecting a layout key or using a key-targeted binding editor. Confirm the Encoders section is visible while no actual key row is selected (use public selected/current markers and the canvas state, not private Runtime fields). For Main, confirm both direction controls for `left/SW25` show the existing Unassigned/None default because `Main.sensors` has no `left/SW25` entry. Confirm the exact `left/SW25/push` ID is visible as a push editor only if the live Core peripheral-description bridge reports it for the selected board. Record displayed encoder ID/label, push presence/absence, current layer/board, and selected-key indicators before editing.

2. **Clockwise and counterclockwise edits.** Through the shared public binding fields, set the left encoder's Clockwise behavior to Key press `A`, then set Counterclockwise to Key press `B`. Save/read the accepted document after each terminal operation. Confirm the stable Main `sensors["left/SW25"]` record contains the two distinct directions and no other layer's sensor data changed. Check project revision/history progression and that selection or board/layer context did not retarget the other direction.

3. **Reported push binding.** Only if the public Core peripheral-description bridge exposes the real non-null `left/SW25/push`, set its shared binding to Key press `C`. Confirm the persisted binding is keyed by that exact reported push ID and the rotation sensor record remains unchanged. If the input view does not report push, record the absent editor and skip mutation; do not infer it from the archive part ID or synthesize `/push`.

4. **Invalid input and recovery.** On one direction's free-form keycode field, enter the invalid expression `A)` through the actual visible input and blur by focusing another actual encoder field. Confirm the field shows the real validation error, the accepted saved binding and revision remain at their prior values, and the invalid draft remains correctable. Replace it with valid nested expression `LC(LS(A))`, blur, and confirm only that field changes in accepted document data. Keep UI error/draft evidence separate from saved-document evidence.

5. **Undo/Redo and scope preservation.** Use the public toolbar Undo/Redo once across the last rotation/push operation where possible. Compare readonly accepted documents or public-export archives before/after: verify the targeted field reverts/restores exactly, unchanged direction/push, other layer, other board, physical parts, and unrelated key bindings remain byte-equivalent at the relevant values. Switch Main ↔ Function and Left ↔ Right with real selectors, observe Right defaults remain None before its own edits, and return to Left/Main to confirm edits remain attached to `left/SW25` and `base`. Do not count switching the selected encoder as a binding edit.

6. **Save/reload and keyboard.** Export through the visible UI after final redo, reload the candidate page, re-open the saved project through the normal project card/editor flow, and export/read again. Confirm same stable encoder/layer/push IDs and values. Use actual focusable shared controls with Tab/Shift+Tab and Enter/Space where supported; record active labels, focus retention, validation feedback and the no-selected-key Encoders accessibility path. If the UI has no public deselect action and a key is automatically selected, record that actual limitation rather than mutating selection state privately.
