Existing `web/src/presentation/keymap/binding_editor.rs` and `binding_controller.rs` are key-target-specific: the editor request and feedback use `key_id`, and the accepted projection maps from a selected key in `KeymapView`. This is why encoder rotations need a reviewed private shared binding-target seam, not a fabricated key ID. Existing typed map edits run through `EditKeymap`; existing legacy key position edits use `SetKeyBinding`; both use the current accepted edit/history authority. Important current limit: `core/src/electrical_peripherals.rs::describe` reports physical rotary parts as `kind == "encoder"`, while the VIK module producer reports modules as `kind == "vik"`. `core/src/keymap.rs` `KeymapChange::Encoder` accepts only a matching described physical encoder and rejects module IDs as `Unknown physical encoder`, despite React listing module encoders. Draft06 therefore preserves the reference's editable module rows and requires the existing Core rejection to remain visible with a correctable draft; it does not claim module edits persist or change Core behavior. No source, public type, schema, or canonical task graph change is authorized by these drafts.

**Refactoring handoff:** No new refactoring takeaway observed. Preserve existing RF-009 source accounting/parity reconciliation. This source pass reinforces the separation among typed per-layer Keymap bindings, legacy board-scoped firmware positions, F5 electrical inputs, and F8 artifact delivery.
