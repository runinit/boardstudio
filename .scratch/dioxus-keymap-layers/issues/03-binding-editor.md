# F6K.2: Supported key-binding editor

**Parent:** F6K.2 — Binding editor, supported behavior fields, and keycode search (`.scratch/dioxus-frontend-v1/tasks.json`; source specification `.scratch/dioxus-frontend-v1/issues/06-keymap-keycaps.md`).

**What to build:** From a selected supported key and active layer, a designer can choose any currently supported behavior, edit only that behavior's fields, find common keycodes or enter a valid free-form keycode, and see the accepted binding reflected in the selected-key control and 2D layer labels. The edit goes through existing Keymap history and storage.

**Blocked by:** F6K.1 Keymap projection/selection/layers (the accepted-snapshot projection, current layer/key identities, binding read projection and private edit callback must be mounted). No F6K.3 or INT.2 dependency.

**Parent acceptance joins:** None beyond this slice's own public behavior and verification. F3.1/shared selection acceptance remains a separately tracked parent join; this ticket cannot close it.

**Status:** ready-for-agent; independently reviewed and automatically published. Canonical start blockers and acceptance joins remain required.

- [ ] Provide a private binding editor in the Keymap panel for key press, mod-tap, layer-tap, momentary layer, toggle layer, to-layer, sticky layer, sticky key, macro, transparent, and none. Match the existing field visibility and defaults: keycode A for key-press/sticky-key; LSHIFT/A for mod-tap; first non-base layer, or Base if alone, for layer choices; SPACE tap for layer-tap; first macro, or the existing empty reference fallback, for macro selection. Disable macro selection when there are no macros.
- [ ] Keycode and tap-keycode controls search the current curated choices and permit free-form ZMK expressions accepted by core. Preserve the React label/placeholder distinction and commit a trimmed changed value on blur; do not claim Enter commits as React parity because the pinned input has no Enter handler. Rejected input retains a recoverable draft with the existing validation message.
- [ ] Layer and macro controls display names but store and submit stable layer/macro IDs. Preserve distinct `Transparent` and `Unassigned` values, typed-over-legacy precedence, first-layer legacy `&kp`, `&trans`, and `&none` meanings, and higher-layer transparent fallback. Renaming/reordering must not retarget references.
- [ ] Scope a field draft by the accepted document/session/board/instance Scope, editor lifetime, active layer ID, selected key ID, field identity, and that field's accepted value. An unrelated accepted token/revision advance may preserve dirty text while those draft identities and the accepted field value remain unchanged; preserving text does not authorize a write. Scope each emitted operation separately to the latest accepted source token/revision and a request ID. Before submission, the root must re-read the accepted state and validate the current Scope, token/revision, layer, key, field, editor lifetime, and target; apply the field change to the current accepted binding, and never retarget a draft or operation to a different target or superseded source. Correlate pending/saved/failed feedback to the exact operation identity. A rejected or stale commit stays visible and editable until its target/value changes or the user corrects it.
- [ ] Use the existing private accepted Keymap edit callback and `EditKeymap`/`KeymapChange::Binding` path only. Re-read and validate current scope and target at commit; use core `KeyBinding` validation and existing edit/history error handling. Do not add a command, parser, field family, document field, public API/type/visibility, or alternate writable state.
- [ ] Paired public browser behavior against the pinned React reference covers every behavior switch and conditional field, common-key search and free-form validation/recovery, stable layer/macro reference across rename, selected-layer summaries, legacy base values, transparent/none distinction, input cancellation on scope/selection change, focus/keyboard interaction, Undo/Redo, save/reopen, and workspace switching. In particular, tabbing out of a changed Tap keycode commits it and advances focus to Hold modifier, as in React; the accepted-value update must not strand focus on `body`, and the pending commit must not submit a second edit while focus advances. Assert accepted document values and history outcomes, not component internals. Existing core keymap tests remain domain evidence; they do not replace Dioxus browser proof.
- [ ] Run affected native/WASM frontend checks, format/diff checks, and public Dioxus evidence under the project’s applicable checks. Keep parent F6K.2 acceptance open until these checks and review are complete.
