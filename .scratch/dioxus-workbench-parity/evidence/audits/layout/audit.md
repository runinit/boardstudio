## Existing Dioxus behavior: present and wired

- `web/src/presentation/objects.rs:53-59,117-127,193-260` mounts the Objects tree from the accepted `ReadModel`, active board and `scene.matrix_scenes`; it has board/instance navigation, persistent row/column grouping, disclosures, real component rows, row keyboard navigation and tree selection callbacks. `objects/tree.rs:4-35,116-...` defines private Board/LayoutGroup/Matrix/Row/Column/Key/Component contexts. The tree builder takes accepted-scene cells as its projection source and filters to active-board live parts.
- `objects.rs:32-50` exposes private resolution/context helpers. `objects/tree.rs` also has `context_for_part` and `context_for_cell`; empty enabled cells can be semantic Key contexts without synthetic `part_id`s. `selection.rs:82-150,153-214` validates live Scope/board/session/document, resolves only eligible current-board IDs, synchronizes scoped context with existing Session `SelectParts`, and guards canvas hit callbacks. Empty-cell semantics remain separate from Session real-part identity.
- `presentation.rs:972-1005,1981-2016` wires tree selection and matrix-cell canvas pointer hits to that adapter; Shift maps to existing Range and Ctrl/Cmd to Toggle. This ticket’s browser audit does not repair range math; T1-12 owns the rectangular correction. `Objects` rows expose nudge requests only for live primary component rows; no synthetic key/component IDs are added.
- `presentation.rs:1955-1973,1981-2024` draws the current accepted board outline and matrix cells/parts, exposes Footprints and the existing Layers view, and retains pointer move, Space-pan and wheel-camera behaviors. This is an existing renderer/read-model path rather than Layout authoring parity.
- `presentation.rs:2215-2229` renders a selected-context summary, then mounts `Inspector` only when real part IDs are selected. `context_summary.rs:11-87` provides labels/counts for matrix/row/column/key/component/board/layout-group contexts. `inspector.rs:18-153` edits only selected real part X/Y; `inspector.rs:163-181` sends existing MoveParts edits. In browser, selected matrix/row/column gets the semantic heading but no contextual fields; selected real key/component gets X/Y only.
- The Dioxus tree’s current `TreeKind` list (`objects/tree.rs:38-49`) contains no outline/version/bridge kinds. `build_tree` projects board/layout/matrix/key/component groups but no Outline node. The canvas renders `scene.board_contours`, so outline visualization exists while the Outline inspector, version selector, bridge navigation, point handles and edit drafts are absent from the Layout UI/adapter.

## Demoable slice proposal, using existing seams

1. **Finish F3.1/T1-10 public selection/context proof** around the already-wired private `TreeContext`/`ScopedTreeContext`, `resolve_selection`, `context_for_part`, `context_for_cell`, and `SelectionAdapter`. Demonstrate board → populated/empty key → component → standalone part, plus active-board invalidation and tree/canvas synchronization without creating part IDs or a parallel document/selection store. This is the nearest gap to the reported blank Inspector: the page already knows which semantic context was selected but does not show an editor for it.
2. **F3.2d matrix/key inspector** as a separate page-private renderer receiving a validated context + accepted `ReadModel`, emitting typed private edit intents through the current Runtime/Core history path. Let only F3.2d own matrix shape/assembly/attached-component settings. Its public demo uses existing resize/preset/replace/remove/Undo/save/reopen behaviors.
3. **F3.3 transform and snap controls** in a follow-on slice: share one scope-checked intent boundary for matrix splay/stagger/origin and canvas snapping; reuse Core's operations and application interaction helpers. Do not copy Core geometry into UI state. Capture current React menus and precise gesture behavior before wiring controls.
4. **F3.4 outline workflow** separately: active generated/saved version, copy/activate, then fixed perimeter edit/draft tools. Reuse Core outline/version/refinement and snap services; keep temporary drafts private and version/history semantics from ADR 0001/0002. T1-11 is not a substitute for this authoring slice.
5. **F3.5 inspector relations/findings** after F3.1: share context/target navigation with prior slices; avoid separate context enums, real-part lists or selection stores.

All five suggestions map to existing IDs. Do not add another parent, child ticket or edge from these observations alone.
