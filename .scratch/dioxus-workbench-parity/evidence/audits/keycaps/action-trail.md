# Keycaps paired exploration action trail

Named `agent-browser` session: `keycaps-parity-reset-20261002` (closed after capture). Source UI `http://127.0.0.1:5175/`; Dioxus candidate `http://127.0.0.1:34687/`.

1. Opened React and Dioxus in separate tabs. React started at the demo library; opened **Start REVIUNG41**. Dioxus opened saved **REVIUNG41 copy**. These were visually comparable REVIUNG workflows but were not proven to be byte-identical fixtures, so observations below are exploratory rather than paired acceptance evidence. Captures: `react-initial.png`, `react-reviung-open.png`, `dioxus-initial.png`, `dioxus-reviung-open.png`.
2. Selected **Keycaps** on both. React showed its populated physical keycap workspace. Dioxus showed `Keycap editing is not available yet in the Rust interface.` and a Back to Layout button. Captures: `react-keycaps-view.png`, `dioxus-keycaps-view.png`.
3. Opened Dioxus **Export** from the global menu. It exposes generic **Export archive** and **Export STEP** only; it has no keycap-specific readiness or STEP action. Capture: `dioxus-export-menu.png`.
4. Returned to Dioxus Layout, expanded `right keys` → `Column 1`, and selected `Key 1.1 SW1`. Tree selection works. The Inspector contains X/Y position and Apply position, but no key width/height, rotation, key assembly, keycap profile, legend, size, or color controls. Captures: `dioxus-layout-return.png`, `dioxus-matrix-selection.png`, `dioxus-key-selection.png`.
5. In React Keycaps chose the right-keys **Cherry** profile; selected `main-right-keys-SW8` from the selected-key control; edited the legend to `ALT`, then used **Blank keycap**. The selected key gained its own legend, blank-state, color, and Keycap overrides controls. Captures: `react-profile-cherry-settled.png`, `react-key-selected-sw8.png`, `react-legend-edited-alt.png`, `react-blank-toggle.png`.
6. Changed clearance to `0.8` mm and opened **Profile dimensions & socket**. React exposes first profile row, wall thickness, and matrix socket choices (inherited, MX, Choc v1/v2, Alps). Capture: `react-clearance-08.png`, `react-profile-dimensions-open.png`.
7. Opened **Keycap overrides**. React exposes per-key profile/socket inheritance, row, width/depth in units and color; entered a test width/depth. The width control did not reliably retain the attempted value in this automation, so no width-edit result is asserted. Captures: `react-keycap-overrides-open.png`, `react-keycap-unit-overrides.png`.
8. Switched React Keycaps to 3D. The initial pending state became a loaded assembly with `124 / 124 models`, Cherry profile, fit/top/bottom/isometric camera controls, display modes, and findings. Clicked **Fit board**. Captures: `react-keycaps-3d.png`, `react-keycaps-3d-settled.png`, `react-keycaps-3d-fit.png`.
9. Clicked the visible **Export keycap STEP** action from the keycap assembly route. Downloaded `keycaps-preview.step` (4,994,526 bytes; SHA-256 `a8d13e3a781f756e13414d127c90dabff4d07b6c455b27065a7047d24845dde4`). Pre-download view: `react-before-step-export.png`.
10. In React Layout selected SW8 to inspect the shared layout key Inspector. It presents width/height, Wide/Tall, enabled, local X/Y, rotation, reset transform, assembly selection, and component actions. Capture: `react-layout-key-context.png`. These Layout controls are separate from Keycaps-only profile/legend/color/row/socket/size overrides.
11. A color-input automation attempt set the board cap color to black rather than the requested test hex; this is treated as an automation limitation, not a product finding. No source/browser errors were observed. The named isolated browser session was closed after capture.
