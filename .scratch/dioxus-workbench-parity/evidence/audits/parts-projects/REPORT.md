# Parts + Project parity reset audit

**Disposition:** exploration only; no source files, Cargo checks, commits, app storage, or root integration files were changed. Paired screenshots and exact action trail are in this directory. Screenshots are tied to the session/build provenance in [ACTION-TRAIL.md](ACTION-TRAIL.md).

## What the public UI does today

The React Parts flow is a real three-surface workflow. Its Objects-side catalogue combines Key Assemblies, seven categorized component types, and grouped VIK modules behind one search; selected entries open read-only metadata plus the corresponding details/editor in the Inspector and a real preview in the center. The selected MCU view exposes fit-profile entry, 2D footprint and 3D-model modes, layer controls, and definition-side/reversible/hotswap/solder/keycap/Choc parameters. Key-assembly selection is distinct from editing saved assemblies. Module selection can group multiple variants and expose readiness/host-placement configuration. The 2D and 3D buttons are actual view transitions; the 3D sample reported `0/2 models` for the inspected MCU, while the module fixture provided a source preview. No model availability was inferred from a screenshot beyond those visible statuses.

Dioxus candidate `868edfcb` already has an interactive component catalogue and search. It displayed Switches, Controllers, Connectors & sockets, Encoders, Passives & LEDs, Utilities, and Custom; clicking a row changed selection and search filtered the list. It did not show Key Assemblies or VIK modules. Its selected MCU Inspector rendered only the component title in the served candidate; no central footprint preview, 2D/3D switch, layer controls, fit profile, assembly list, per-component generator form, or placement/settings surface was visible. The global layout canvas remained the underlying editor, not a Parts preview.

**Source/runtime caveat:** current integration checkout HEAD `89b1de8a` contains `presentation/parts/details.rs`, which renders definition ID, source, pad count, courtyard size, and generator/KiCad source detail. The running browser candidate was built from `868edfcb`, and its Inspector snapshot showed only the title. Do not treat this candidate as visual proof of current `89b1de8a` source; rebuild and repeat the selected-detail step before closing F4.1 browser acceptance.

React’s Project start/menu presents New project, Open project/import, current project naming, Save project copy, a searchable saved-keyboard list, Create new keyboard, and 18 demo choices. In this audit, New project and Create new keyboard both opened a five-step Setup guide: step 1 captures name/one-or-split/reversible; step 2 offers key-matrix creation and edit-existing-object paths. The saved list opened Sofle after it had been stored. Save project copy produced a portable `.boardstudio` file which was re-imported successfully. Sofle v2 and REVIUNG41 were exercised as two starter demos.

The fresh Dioxus start screen offered only two fixture-copy actions (REVIUNG41 and Sofle v2) and `.boardstudio` import. Importing the React-produced archive opened the document, but there was no visible New project/Create new keyboard action, saved-project library/search/open/delete, project rename, or Save project copy path. Existing global Export is not equivalent evidence for portable archive export.
