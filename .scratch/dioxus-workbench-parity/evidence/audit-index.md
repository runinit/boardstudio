## Evidence-handling rules

These are exploratory audits, not completion reviews. Keep the original source, candidate build, fixture and exact user action with every later claim. A visual/candidate red can be used to prioritize a vertical slice, but the same byte-identified fixture and accepted state must be used for paired completion. Never promote native/source/build evidence to a paired UI result. Do not treat an SVG overlay automation failure as evidence that a control is absent. Each feature author and independent reviewer must update the existing RF register/handoff or state “No new refactoring takeaway observed” with the reviewed scope.
