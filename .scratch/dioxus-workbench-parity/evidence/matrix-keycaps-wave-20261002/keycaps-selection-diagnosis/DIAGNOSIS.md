**Cause and intent evidence:** `Workbench.tsx:1006` explicitly calls `setSelectionMode('key'); choosePart(id)`. But `choosePart` from that render still captures Matrix mode (`useWorkbenchSelection.ts:70–76`), so it calls `selectScope` for the matrix; `selectScope:106` writes Matrix mode again. This overrides the attempted Key reset and persists on repeated activation. `KeymapLayout.tsx:9` names the action `Edit key <reference>` and sends the clicked exact ID; `KeycapPanel.tsx:50` likewise sends the exact chosen ID from `Selected key`. The latter also reproduces SW1/24 when SW7 is chosen. Choosing Key mode first in Layout makes the identical React SW7 click select SW7 alone (`reference-key-mode-control.json`), isolating the captured-mode cause and rejecting dropdown-only/stale-display explanations.
