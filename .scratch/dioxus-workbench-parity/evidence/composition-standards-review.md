# Composition contract v2 — Standards

Reviewed exact contract SHA-256 `a7e584a7bdc1e0129d23c72614e903eadd838c520c0d028b27e0ce50a6300d48` against source baseline `89b1de8a28fdf02db91d972c90a69235bfbbbffb`, CONSTRAINTS.md, ADR0003 and installed Dioxus 0.7.10. Source/design review only; no code, builds or central-document edits.

**P2 — Make dispatch identity unambiguous.** “Private calls and inputs” supplies both `workspace: &str` and an enum already tagged by workspace, then requires forwarding the corresponding feature input. The proposed interface admits incompatible pairs without defining their treatment. Use each surface input enum as the sole routing discriminator, constructed from the existing workspace value; alternatively require an explicit checked correspondence. This is a possible redundant-data/conditional-routing smell, not evidence of a current runtime bug. It can be fixed locally without a broader abstraction or new state.

**P2 — Preserve the actual existing feature lifecycle owners.** “Keep Editor as the caller and lifecycle owner” says it creates every hook/signal and submits all Runtime/Session events. At the pinned baseline, `cad_presentation.rs:9–11` already consumes Runtime and repaint context; CasePanel also owns generation/cancel callbacks. Requiring all ownership in Editor conflicts with the simultaneous prohibition on moving existing feature hooks or editing CAD feature files. State instead that existing Editor-owned hooks/actions stay there, existing mounted feature-local ownership stays unchanged, and the new render modules/dispatcher introduce no hooks, subscriptions or submission authority. This follows CONSTRAINTS.md’s explicit single-owner lifecycle requirement without expanding the extraction.

The six flat feature files otherwise provide disjoint ownership. Plain render functions are feasible: references may serve synchronous RSX construction, while event handlers/component props must retain owned IDs or existing shared handles; Dioxus Callback requires `'static` closures. Existing inline per-cell/part callbacks must be prepared by Editor or forwarded through typed existing-action adapters, never capture borrowed snapshot fields into retained handlers. Parent/sibling calls need narrowly restricted new visibility and consistent root module registration; no existing member/library visibility widening is necessary.

Public before/after checks, Export/fallback retention, panel framing and viewer identity obligations are appropriately bounded. Keep mandatory RF-001 updates in both the handoff and machine ledger; do not claim broader coupling resolved. Clearance is held for the two small contract corrections, followed by source and public verification. No new RF entry warranted.
