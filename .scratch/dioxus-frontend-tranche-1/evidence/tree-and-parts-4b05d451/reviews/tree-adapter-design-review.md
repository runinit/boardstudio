# T1-10 private adapter design review

Reviewed the proposed design against `/tmp/frontend-run/tree-contract-review.md`, actual Objects/tree source at `890fd54f`, and current Runtime/Session/presentation source. Source/design review only; no edits, build, browser reproduction or acceptance claim.

**Decision: approve the bounded private design for implementation with these explicit invariants.** App owns semantic context, full-Scope validity/generation and the sole Runtime observer; Session remains the only real selected-ID/anchor owner. Weak Runtime and lifetime-owned weak Editor cleanup registration avoid cycles without a new subscription or public API.

1. **Reconciliation must terminate before exposure.** Runtime `submit`/`complete` release the Session borrow before `changed()` (`runtime.rs:151–168`), so synchronous pruning is feasible. Update last Scope and invalidate context/anchor/generation before nested submits; release RefCell/Signal guards before calling Runtime. Submit Replace only when IDs actually differ. Nested notification must defer its render bump to the outer reconciliation, which rereads the fresh model before the single bump. Otherwise selection settlement/status notifications can recurse indefinitely or expose intermediate state.

2. **Pruning does not establish an anchor.** Session Replace with nonempty IDs rewrites its anchor; Replace([]) leaves the old anchor (`session.rs:622–624`). Do not mark the private anchor stamp valid from observer maintenance. Only an explicit eligible selection establishes validity. First Shift after invalidation must use Replace; preserve ticket 12's separately open rectangular-range join.

3. **Valid empty context differs from eligible selection.** Worker `tree.rs:793–807` returns `Some([])` for disabled/empty Key contexts. Testing only `is_some()` does not remove a stale selected part. Preserve semantic empty context while pruning ineligible IDs and invalidating an ineligible anchor. Revalidate removed contexts against fresh accepted data. For multi-selection, prune eligibility without replacing the whole selection with the last semantic context's resolved group. No second authoritative selected-ID vector.

4. **Pointer ownership requires scope AND gesture/lifetime identity.** Cancel an owned active gesture before a validated Navigate; the observer handles asynchronous adoption by clearing old DOM drag/capture before render. After scope changes, never issue GestureCancel merely because pointer ID matches: the event checks only pointer ID (`session.rs:750–757`). Verify recorded Session gesture generation and current owner before cancellation. Late move/up/cancel or cleanup may release capture only if its registration/drag generation still owns that pointer; never take a newer drag first. Clear pre-threshold drag, pan and space-key state too. Deregistration must compare its owner token so an old unmount cannot remove a replacement registration. Existing asynchronously driven ReleasePointer effects also warrant pointer-reuse evidence (`runtime.rs:291–299`).

Fresh-scope tree/canvas callbacks, validated navigation, semantic empty-cell selection and Inspector context display fit the existing private helpers/props. Route every canvas selection path through the adapter. Nudge remains an explicit open join until wired and verified.

RF: existing RF-001/007/010 cover shared composition, single observation and cancellation ownership; no separate new structural takeaway required. Full source review and public regressions remain required: same-ID reopen, async adoption, board/instance switches, invalid navigation, disabled/removed targets, stale callbacks and reused pointer IDs, plus selection/history/camera neutrality.
