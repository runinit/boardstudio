# Parts packaged-loader browser evidence

## Scope and provenance

This packet records a browser-only check of the fresh `f65` candidate served at `http://127.0.0.1:34659/`, as identified by the parent task. The candidate identity was supplied by the parent; this check did not build or independently attest the artifact digest. Browser automation used isolated named `agent-browser` sessions (`parts-loader-root-f65`, `parts-loader-subpath-f65`, and `parts-loader-error-f65`) with headless Chromium 154. No production source, configuration, or browser-provider/catalogue state was edited. The public demo was opened using the visible `REVIUNG41 copy` UI control.

The root and `/boardstudio/` sessions each opened the public demo, selected Parts, and allowed the actual packaged loader to run. Their captured accessibility trees and page text show `Components 47`, the categorized catalogue and part names, and the selected `MX switch` inspector. The inspector includes definition ID `ergogen:ceoloide/switch_mx`, catalogue source `Bundled Ergogen library`, 7 pads, and a 15.5 × 8.6 mm courtyard in the root capture. This is evidence for the browser UI’s packaged load path and rendered catalogue at these two served paths; it is not a standalone audit of every catalogue entry or a release-host test.

## Results

- **Root path: pass.** The UI rendered 47 components and the selected-part details. Browser network capture records HTTP 200 for `/assets/layout-generators/src/index.js` and `/assets/layout-generators/generated/catalogue.mjs`. Evidence: `root/parts-ui.json`, `root/parts-body.txt`, `root/loader-requests.txt`.
- **`/boardstudio/` subpath: pass.** The UI rendered the same 47-component catalogue and selected MX-switch details. Browser network capture records HTTP 200 for `/boardstudio/assets/layout-generators/src/index.js` and `/boardstudio/assets/layout-generators/generated/catalogue.mjs`. Evidence: `subpath/parts-ui.json`, `subpath/parts-body.txt`, `subpath/loader-requests.json`.
- **Loader failure UI: pass.** In the isolated error session, `agent-browser network route "**/assets/layout-generators/src/index.js" --abort` intercepted the actual module request. The Parts view displayed `Component catalogue could not be loaded` and the dynamic-import `Failed to fetch` error. The request log has the module request without an HTTP response status, as expected for the client-side abort. No fake provider or catalogue response was injected. Evidence: `error/parts-error.json`, `error/parts-error-body.txt`, `error/loader-requests.json`.
- **Offline reload/cache: pass with isolated disk-backed QA profiles; original temporary-filesystem failure preserved.** The unchanged f65 build at port34659 automatically installed and reloaded offline in eight fresh `/var/tmp` profiles (root×4, subpath×4). Final root/subpath captures each show an activated registration, controller and all51 manifest assets cached. Fresh default and explicit `/tmp` profiles still failed installation and offline reload. Worker lifecycle traces establish that installation became redundant while online, before the test switched offline. The initial baseline47 pass and candidate failures remain in this packet.

The preliminary application-regression classification is superseded by the controlled diagnosis in `offline/DIAGNOSIS.md`: the QA profile filesystem had insufficient free space for Chromium's blob paging reserve. Changing only the isolated profile filesystem made the same immutable candidate and server pass; changing only HTTP Content-Length did not. No runtime, build, manifest, production server or global configuration change was needed. `offline/environment-controls/` retains scripts, exact lifecycle timestamps, candidate hashes, profile identities and version-matched Chromium source. The initial cause-unknown diagnosis remains as `offline/DIAGNOSIS-PRELIMINARY.md`.

## Limits

This is browser packaging evidence only. Offline landing-shell reload is verified for the stated root/subpath artifact and disk-backed profiles; this does not cover every distribution host, exhaustive offline editing/export, or all catalogue definitions. The deliberate loader-error check covers an aborted top-level module request, not every possible network or decode failure. No source or compiler checks were run in this task.
