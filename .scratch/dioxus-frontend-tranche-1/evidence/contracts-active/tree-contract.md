## Authoritative sources

- `core/src/model.rs`: `ProjectDoc` owns `boards`, `parts`, `matrices`, optional hardware and `layouts`. `Board.part_ids` is the canonical board membership. `Matrix` has stable `id`, dimensions, optional `board_id`, `part_ids`, and sparse `cells`. `MatrixCell` has coordinates, `enabled`, optional definition/variant, and cell `assemblies` (each with stable assembly id and definition id). `Layout` associates a board and matrix and has its own stable id, name, `part_ids`, and optional `mirror_link`.
- `core/src/matrix.rs:60-77, 454-508`: each enabled coordinate maps to canonical member ID `matrix/{matrix.id}/r{row}c{column}`; disabled coordinates have no member. Projection resolves the member only against actual `Part` records. A missing cell config means enabled/default; sparse cells are overrides. A member ID is not proof of a live part.
- `application/src/session.rs:100-135, 562-633`: `ReadModel.selected_part_ids` and `selection_anchor_id` are the existing selection authority. `AcceptedSnapshot.scene.matrix_scenes` is the existing accepted matrix projection authority; use it for enabled/live member mapping rather than inventing an independent geometry projection. `SelectParts` filters submitted IDs against `document.parts`, applies Replace/Add/Toggle/Range, and updates anchor only from a real incoming ID. It is session-only and does not edit document/revision/history. Therefore empty cells and matrix/row/column selections must not be encoded as fake part IDs or overwrite the Session anchor with semantic IDs.
- `application/src/session.rs:634-674, 1480-1510`: `Navigate` validates board and optional instance membership, invalidates active gesture/jobs/exports when accepted, updates active board/instance, and normalizes selection to existing document parts. It currently does not narrow selection to board membership. Presentation context must discard a selected part when it is not a member of the newly active board, and no callback captured under old scope may select into the new scope.
- `web/src/runtime.rs:100-175`: one `Runtime` owns one `Session`; `model()` is a cloned read model and `submit(Event)` is the session entry point. Root’s page-local private context holder can be provided alongside Runtime. Keep this holder ephemeral; do not add another document/session or make APIs public.
- `web/src/presentation.rs:4-8, 799-805, 841-900`: `Objects` is mounted in the compact Objects panel. Canvas selection currently derives only from `selected_part_ids`. Canvas key click already maps a projected key with a real `member_id` to `SelectParts`; component click maps only a part present in the board parts. It cannot express empty-cell or matrix context, so tree selection needs the private context adapter and canvas-to-tree sync needs a narrow private mapping at that mount.
- React reference: `app/src/ui/Workbench.tsx:330-364` derives selected-board `boardPartIds`, visible matrices, `matrixCellOverrides`, actual scene members, and part-to-coordinate lookup. A matrix is visible on its explicit `boardId`; legacy unowned matrices are associated only by actual selected-board parts (or for a single-board empty matrix). `app/src/ui/useWorkbenchTree.ts:166-252` defines matrix/group/key/cell-component/standalone membership, stable IDs, labels, counts, independent disclosure and split linked-half ownership. `app/src/ui/useWorkbenchSelection.ts:29-83` establishes key versus actual-component selection.

## Exact selection mapping

Private semantic context variants needed for Objects: `Board(board_id)`, `Matrix(matrix_id)`, `Row(matrix_id,row)`, `Column(matrix_id,column)`, `Key(matrix_id,row,column)`, and `Component { part_id, optional matrix_id/row/column/assembly_id }`. Identity is the variant plus stable source IDs/coordinates, not a generated document part.

- Board row: semantic board context; sends `SelectParts(Replace, [])` if the selected-board scope requires clearing real selection. Board navigation itself stays `Navigate`.
- Matrix row: context matrix ID; selected real IDs follow the React selection contract: start from `matrix.part_ids` (which includes actual generated cell assembly companions), map through the accepted matrix projection plus cell assembly IDs to coordinates, then keep only live IDs in both `Board.part_ids` and `ProjectDoc.parts`. Preserve source `matrix.part_ids` order. Preserve a linked-half group visually when `Layout.mirror_link` links layouts; this does not merge matrix/document identity.
- Row/column group: context matrix and zero-based coordinate; selected real IDs follow React: filter `matrix.part_ids` through the matrix part lookup for that row/column (including assembly companion IDs), then filter to live `Board.part_ids` and `ProjectDoc.parts`. Never submit absent/disabled slots. Displayed key counts count primary enabled/live keys only, not companions.
- Key: context matrix and zero-based row/column. If enabled and its canonical generated member has a live `Part` record on this board, submit that one real ID; otherwise submit an empty replacement selection and retain the semantic key context. A disabled cell is not a selectable key member. React IDs are `key:{matrix}:{row}:{column}` for tree identity only.
- Cell component: each saved assembly row is identified under its key by stable `MatrixAssembly.id`, label from its definition; React uses `component:{canonicalMemberId}/{assemblyId}`. Only select the actual matching `Part` record if it exists on this board; otherwise retain component semantic context with empty Session selection. `diode` gets “Automatic companion”; other cell assemblies “Cell component”.
- Standalone component: actual board part with no matrix cell membership; tree identity `component:{part.id}`, label `part.reference`, detail definition name + pose as in React. Select the actual part ID.

Membership filters are always the current selected board’s `Board.part_ids` intersected with live `document.parts`. Matrix visibility follows React’s explicit-boardId rule; legacy matrices without boardId require selected-board live membership, with the single-board/empty-matrix exception. Do not include parts owned by another board. Matrix source membership and selected-board membership are separate; source `matrix.part_ids` is not a substitute for the board filter.

## Disclosure and presentation

Stable tree identities follow React: `matrix:{id}`, `row:{matrix}:{index}` / `column:{matrix}:{index}`, `key:{matrix}:{row}:{column}`, and `component:{realPartId}` or `component:{memberId}/{assemblyId}` for assembly rows. Display matrix name (trimmed) or `Matrix N`; group label is one-based “Row N”/“Column N”; key “Key {column+1}.{row+1}”; details carry enabled live counts, empty-slot state, reference and assembly role. Disclosure keys are independent per matrix/group/key, retained when switching row/column orientation if stable identity still applies. Preserve linked-half grouping. Tree work does not change the existing five layer visibility controls.

## Scope identity and cancellation

Scope key is `(SessionEpoch, project/document identity, active canonical board ID, active instance ID if applicable)`. `AcceptedSnapshot.session_epoch` / `Runtime.scope().session_epoch` distinguishes a reopen of the same document ID. On project or board/instance change: clear private semantic context, clear selection anchor/context captured in presentation, prune selected real part IDs to the new canonical board, and cancel any presentation-scoped pointer gesture before rendering children for the new scope. Use a monotonically changing local scope generation captured by callbacks; callback submits only when its captured key/generation still matches current scope. Session `Navigate` invalidates its engine gesture/jobs; presentation must also cancel its owned DOM pointer interaction (the current canvas stores one drag closure and submits `GestureCancel` for active gesture). Selection and disclosure actions submit no document Edit and do not increment revision or create history.

## Proposed same-page private adapter seam to review

One private page-context holder adjacent to `Runtime` exposes current semantic context and exact-scope selection operations to both Objects and canvas: semantic context is ephemeral presentation state; selected real IDs are read/written only through `Runtime.model().selected_part_ids` and `Event::SelectParts`; context writes require the current scope key/generation; tree and canvas set the same semantic context; canvas key/component hit mapping emits it when available. The holder must not be public/re-exported through `web/src/lib.rs`, add Session fields, duplicate document state, or widen application/core visibility. Parent owns its implementation and inspector integration. Objects owns only rendering/projection and private child files. Clear/recreate this context synchronously in the page's board/project transition path before exposing the new board, with same-scope generation guards for callbacks.
