## Blocking join A: full open intent

`runtime.rs:689–696,764–795` advances/checks open_sequence around provider loading. It does not carry that identity through `submit(Event::Open)` and the core/persist completion. `runtime.rs:188–213` forwards every matching core reply; `application/src/session.rs:912–927` queues opens, `1174–1263` accepts matching core replies into persistence, and `1292+` adopts successful persisted snapshots. A source-supported race is A submitted/core pending, B begins, B missing/errors, A completes and persists/adopts despite B being the latest intent. A public/native controlled failing reproduction is still required before a repair; none was executed in this review.

Do not repair only the card click handler. Guarding the Runtime callback and silently dropping an obsolete reply strands Session.active_core. Reporting CoreFailed enters RecoveryRequired (`1409–1444`), violating the usable prior-project requirement. Synthesizing CoreReply::Error after core already opened A leaves the engine and accepted snapshot inconsistent. Reopening a cloned prior document resets the worker's history and is not an equivalent rollback. Disabling/suppressing B changes the requested supersession semantics. The analogous A-save-pending/B-begins boundary also needs an explicit disposition.

Existing public Session events/completions expose no open-intent cancellation/adoption operation. A narrow Runtime private helper can own attempt metadata, but cannot by itself settle/cancel the existing Session and restore engine history. The next bounded repair packet must first reproduce the exact public interleaving and design an existing Session/core ownership solution preserving previous accepted document, history, selection and engine agreement, plus operation settlement and save ordering. If that solution requires an additive Session event/method or provider cancellation contract, present that concrete API change for approval; no existing member visibility widening is justified. This review does not approve a new API or broad Session/provider rewrite.

Required race oracle: accepted P (with undo history) -> start A -> allow A into core -> start B -> force B missing/error -> release A; P remains usable, stale A never becomes current, no stale active-project preference or save adoption, pending callers settle. Also cover successful B, failure of A, A queued behind save, and B starting while A persistence is pending. Test real effect-driving path; a synthetic Session test that never submits B's real public intent is insufficient by itself.

## Blocking join B: malformed stored records

Reference `app/src/storage.ts:45–60` returns raw IndexedDB records; `ProjectLibrary.tsx:60–71` catches missing/damaged preview fields per record, preserving the damaged card's identity/open action and healthy cards. `web/src/host/storage.rs:203–225` deserializes all values and collects Result<Vec<ProjectDoc>, PersistError>; one malformed representation rejects the complete list before private projection. Example source oracle: an otherwise identified/named record with missing `parts` next to a healthy project. This is distinct from a typed ProjectDoc containing non-finite geometry, which the cleared projection can isolate.

The current BrowserStore public surface has no raw/per-record listing. Its database_name and list_values are private in the library crate, whereas Runtime/presentation are the page binary (`web/src/main.rs`, `lib.rs`). A private page wrapper cannot recover damaged IDs/names from the aggregate PersistError. Skipping invalid records loses the damaged card/open action; fabricating default ProjectDocs weakens document authority; opening a second direct IndexedDB access path duplicates the provider boundary. None is cleared.

Smallest concrete boundary decision if full isolation is implemented: retain existing list_documents and load_document semantics, add a narrow read-only per-record discovery result to the SAME BrowserStore with usable ID/name and optional typed preview document (or explicit preview-unavailable classification). Keep exact identity, isolate record decoding errors, keep transaction/provider failure as list failure, and leave opening on the existing strictly decoded load path. No stored-format change, migration, second store or visibility widening. Because this is an additive library API, existing authority requires explicit approval before implementation. This proposal is concrete; do not ask for a general permission to rewrite persistence. An implementation design still needs precise malformed/missing-ID disposition and no arbitrary raw JSON widening.
