# T1-07 desktop panel modes: source-grounded private contract

## Scope and ownership

Baseline is the isolated `codex/frontend-panels-20261002` branch at `598b2c026941130f9b95ff4fee57353f8eefcb0d`; shared implementation integration remains root-owned. This work adds only `web/src/presentation/panels.rs` (and private child modules if needed). Root retains `web/src/presentation.rs`, `web/assets/m1.css`, Runtime/session, build/ledgers, and candidate browser/build evidence.

The module will export the private types `PanelSide`, `PanelMode`, and `PanelSettings`; `use_panel_settings(side: PanelSide) -> Signal<PanelSettings>`; and two `pub(super)` Dioxus wrapper components, `ObjectsPanel` and `InspectorPanel`, each accepting `compact_open: Signal<bool>`, `settings: Signal<PanelSettings>`, and `children: Element`. Editor creates each independent durable preference Signal through a private `use_panel_settings(side)` hook, then passes it to the relevant wrapper. Each wrapper owns only ephemeral menu/reveal/focus state and wraps the existing Objects or Inspector component, without changing either component's API or the session path. Keeping durable Signals in Editor preserves unavailable-storage in-memory preferences when Inspector conditionally unmounts. Root composes each wrapper around its existing child at the same mount point. Objects remains mounted for all editor workspaces as today. Inspector remains mounted only for Layout as today; other workspaces currently have no Dioxus inspector content. Hiding a desktop panel changes presentation attributes/styles while retaining child mount and event closures. `Runtime` remains the sole Session, document/history, selection, and camera authority.

The existing compact fallback remains the current `<=760px` CSS layout and its two root-owned open signals/toggles. This ticket does not change those breakpoints, add scrim/drawer behavior, or add resize gestures/handles. Desktop panel modes are only active above that existing compact breakpoint. The wrappers use the passed compact-open signals and a cleaned-up reactive `(max-width: 760px)` media-query listener so hidden compact content stays `display:none`, inert, and aria-hidden after viewport transitions. The parent-owned integration patch supplies the CSS and composition hook; it does not widen any public API.

## Private component behavior contract

- `ObjectsPanel` uses preference side `left`, label “Objects”; `InspectorPanel` uses side `right`, label “Inspect”. Their local persisted modes and optional widths are isolated. Both default to pinned. Their preference Signals live in Editor so Inspector settings survive its conditional unmount, including storage failures. They share no mutable state except a panel-action helper; no project/workspace keying, no Runtime writes.
- Persist only validated `{mode,width}` at the exact reference keys. Load malformed JSON or storage access failures as pinned/null, clamp finite width by side, retain invalid/non-finite width as null. Attempt writes after initialization and preference changes; ignore storage failures without warning UI. No transient reveal/menu/hover/focus state is persisted.
- Desktop panel heading/actions contain an accessible Options button, a labeled `role=group` options container and the relevant Pin/Auto-hide/Collapse action. Expose a rail only outside pinned mode, with accessible name, `aria-expanded`, and `aria-controls`. Pointer reveal applies only to non-touch hover; keyboard activation always works. Hide after 280ms idle only when focus is outside panel and rail. Escape closes the menu with trigger focus return; Escape from a revealed non-pinned panel closes reveal and focuses its rail. Outside pointerdown dismisses menu while target containment includes the options group and trigger only; remove the listener when menu closes or wrapper unmounts. Clear pending idle timers on unmount.
- Hidden desktop panel wrapper must set `inert` and `aria-hidden="true"` and be non-interactive. It remains mounted. The wrapper's own trigger/rail remains exposed. Do not let a timer hide a panel while focus is inside it. Explicit collapse first transfers focus to rail, then panel is hidden.
- Compact closed wrapper follows the existing root compact boolean and is excluded from focus/accessibility; compact menu modes are not exposed there. The current root toggle is retained as the accessible open control. No scrim/close button/Escape drawer policy is added in this ticket.
- Width preferences are loaded and applied as the appropriate CSS custom property to both pinned grid column and revealed overlay. They clamp to exact reference bounds. No resize UI or viewport constraint algorithm is introduced here; resize ticket 08 owns pointer capture, keyboard resizing, canvas min-width, and active-resize hide suppression.
- Mode actions only change local panel state, browser preferences, focus, and presentation CSS. They never submit a Runtime/Event action; accepted document/revision/history, selection, view/camera, and pending canvas operations stay unchanged. Opening a panel does not call fit/zoom/pan.
