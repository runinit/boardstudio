## 2026-10-03 page-feature Rust ownership extension

The initial exact-leaf allowlist remains intact for historical compatibility. The implementation adds a conservative source-derived path for ordinary page-feature Rust edits: it resolves external modules from `web/src/main.rs` and `web/src/lib.rs` under the page feature set, resolves provider modules from the three worker/service feature sets, and permits only the difference. Cargo's `boardstudio-web` required feature, declared features, and the full command generator's explicit `--no-default-features --features ...` selections must agree with the reviewed page/provider matrix. The verified baseline still records and validates its exact22 command identities before reuse. `web/src/lib.rs`, `web/Cargo.toml`, `web/build.rs`, `core/Cargo.toml`, and the packaging helper remain byte-pinned. `main.rs` is compared after removing only top-level cfg-page module roots and its exact native-only test stand-in; other edits reject.

New or moved Rust source paths are eligible only when the current parsed module graph reaches them from a page root and no provider root reaches them. Module deletions, unresolved/ambiguous paths, unknown cfg syntax, unsupported `cfg_attr`, provider-overlap modules, changed shared inputs, and untracked/uncommitted deltas reject before output creation. The existing `layout_align_geometry.rs` alias is explicitly excluded because Core's native worker test compiles it. Separate Rust unit-test module files are recorded outside release graphs, and only `core/tests/electrical_wiring.rs` is recognized as the proven Core integration-test-only path. This proves compilation ownership for guarded reuse; it does not run those tests as part of package construction or alter Cargo's full22 build path.

The expected-red case, graph-derived positive/negative guard suite, and source compatibility rationale are retained under [the 2026-10-03 packaging evidence](../evidence/packaging-page-rust-reuse-20261003/RESULTS.md). The amendment is a private packaging-tool extension. Full22 baseline qualification, an actual guarded reuse build, route/offline browser checks, and parent acceptance remain separate gates.

## 2026-10-03 fail-closed ownership correction

Independent production preflight probes found three unsafe admissions in the ownership extension: historical allowlisted paths could override a detected provider owner; command feature roots omitted Cargo's transitive local features; and literal includes/nested inline modules could hide compiled source edges. Tiny actual Rust/Cargo probes confirmed transitive feature activation and different provider WASM bytes after an admitted included-source change. These are guard defects, not evidence that an already served candidate reused changed providers.

Provider ownership now overrides every legacy Rust allowlist. Feature configurations resolve transitive local/implicit optional-dependency features from the unchanged Cargo manifest while retaining provider labels from the command matrix. Unsupported dependency-feature or weak-feature forms reject reuse and require an explicit full build. Literal Rust includes resolve inside `web/src`, record their module-free input paths, and reject missing/escaping/recursive paths; included code with module registrations requires a full build rather than guessed include-context semantics. Inline modules recurse with their actual directory base. Unknown item macros, macro definitions, function-local module registrations and unsupported inline path attributes require a full build. Only the exact existing OUT_DIR data-table includes in service_worker/bundled_models are recognized, under the byte-pinned build script and maintained generator-input proof; include scans overapproximate inactive branches conservatively.

The historical fixed source/proof/asset/tool/command guards, full22 path and eight-command construction remain intact. Regression evidence, including expected unsafe-admission failures before correction, is retained by the root reviewer/repair handoff. A fresh helper-matched full baseline, actual measured reuse, provider hashes and both route/offline browser qualification remain open. This correction does not create another source approval handoff or accept a parent.
