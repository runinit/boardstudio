An error leaves `catalog_built_for` unset (or built for the previous construction), while every subsequent effect for the same construction returns at line 151. The newly added gate at lines 327–341 rejects every changed `KeyAssembly` or `KeyAttached` request until `catalog_built_for` matches. Consequently even **Remove** on an attachment already present in the accepted document becomes permanently unavailable after catalogue failure. The displayed instruction, “Retry in a moment,” cannot recover: an Inspector retry only resubmits the edit; it never clears/restarts the catalogue request. Opening another same-construction project does not reset this Editor-lifetime state.

Failure is reachable: `parts::load_all_catalogue_definitions` delegates to `catalogue::load_bundled`, which propagates dynamic-module import, catalogue decoding, and per-definition normalization errors. This is source-confirmed control flow, not an observed public network failure. Repair with explicit failed/loading state and an effective reload action (or controlled retry), and require catalogue readiness only for definitions the edit actually needs; removing an existing attachment requires no catalogue lookup. Add an owner-level regression that returns a failed load, submits Remove for a document-owned attachment, and exercises recovery without changing reversibility. Capture RED before the fix.
