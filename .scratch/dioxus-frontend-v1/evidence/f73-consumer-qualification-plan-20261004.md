## Parts control reconciliation and remaining qualification

The 2026-10-04 paired observation that Parts initially shows only **Fit sample** and **Layers** is a presentation-placement difference for camera/render controls, not evidence those common actions are absent. `PartsSampleViewer` passes a `ViewerSource::Parts` to `CaseSharedViewer`; that source selects the Parts canvas context and Fit label. With default `inline_case_controls: false`, the standard **View controls** `<details>` contains camera presets/orbit/zoom, Shaded/Wireframe/Hybrid, assembled/exploded/section, section/explode adjustments, and Show hidden lines. Thus the named F7.3-C02/C04 actions remain mounted behind the disclosure. The observed Dioxus Layers menu, however, has only the aggregate `Models` row (and PCB), while the paired React MX sample exposes individual `P1 · 47.stp` and `P1 · 43.stp` visibility rows. This is a real missing per-model visibility action, not a placement difference: `matching_model_rows` admits the current Parts delivery rows, but `component_models_for_source` explicitly selects only Layout or physical-preview model sources, excluding Parts, so `physical_component_layers` receives no Parts model list. It violates existing F7.3-C03's individual model visibility acceptance (and the five-consumer C01/C09 join), not F4.4-C02, which requires loading assets and preserving transforms but does not require per-model visibility. `Sample PCB` is the reference label for the same aggregate PCB layer action; its label difference alone is not functional evidence.

Parts does have distinct supported behavior: `project_parts_preview` builds a one-layer isolated sample-board scene, injects delivered sample model meshes, and does not project live Layout/Case layers or mechanical assembly semantics. `PartsSampleViewer` accepts only current preview owner/scope/token display and viewer events, keeps display state local, and reports renderer failure through Runtime. Picking is intentionally sample-local and must never map to a live-project part. These scope and lifecycle contracts remain to be publicly qualified alongside the specific missing per-model visibility action.

The smallest remaining journey is a Parts 3D sample round-trip on a retained model-equipped definition: enter Parts through the existing Layout chooser, retain its definition/placement form, load the viewer, open View controls and exercise one camera action and one render mode, then expand Layers and hide/show each delivered model row independently while confirming other rows and PCB stay visible. Pick a delivered sample model, verify no live-project part selection/edit or revision change, then return to 2D. On the same fixture, verify actual provider/model failure followed by the existing 2D-to-3D retry if a supported trigger is available; renderer initialization/context loss must stop cleanly, leave the form/2D return usable, and expose no canvas retry. Do not invent fault injection without a public trigger. The existing C10 isolated sample and error behavior and F4.4-C03/C04 failure, retry and lifecycle branches remain qualification work.

The existing native policy seam for the reproduced visibility gap is `physical_component_layers` in `web/src/presentation/case_assembly_layers.rs`: a focused native test can pass the Parts preview's ordered model rows and exact delivered/pending IDs and assert per-model IDs, labels, order, and availability. The source-selection seam is `component_models_for_source` in `shared_viewer.rs`; its current test checks Layout vs Case fallback (WASM test), so a source-qualification regression can extend that policy to current Parts rows while preserving scope admission at `ViewerSource::is_current`. `PartsPreviewOwnerLease`/`PartsPreviewLeaseSlot` in `web/src/parts_preview.rs` and existing pure preview tests cover current sample scope/generation; `case_display.rs` tests visibility/color state policy. Do not test markup in place of these policies. Existing receipts still do not prove a paired 3D pick into Keymap or Keycaps editors; retain that limit until observed. C01/C09 remain `implemented` pending the five-consumer integrated public join, with the Parts per-model visibility omission recorded as a reproduced existing-criterion gap.
