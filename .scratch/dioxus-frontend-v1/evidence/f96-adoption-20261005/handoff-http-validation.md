# F9.6 rollback worker HTTP validation

The actual final run reached the new Rust worker and passed import, save, export, and reload before reverse deployment. In `rehearsal/run-worker-handoff-final-20261005/proxy-requests.jsonl`, reverse serving returned `/service-worker.js` 304 repeatedly, then `/boardstudio_offline_worker.js` 404. The retained page stayed Dioxus with both IndexedDB stores and cache namespaces present; rollback had not occurred.

Root independently captured the discriminating HTTP evidence: candidate port34834 worker is 99,940 bytes (SHA prefix a1c22e), Last-Modified 17:18:27; rollback port34835 bridge is 1,198 bytes (SHA prefix a8607a), Last-Modified 17:17:47. Neither server supplied ETag or Cache-Control. Sending the candidate timestamp as If-Modified-Since to rollback returned 304 despite different content. Exact full hashes/headers remain in the coordinator/Case author's HTTP capture; the prefixes here are not complete identities.

`continue_rehearsal.py` forwards incoming conditional headers unchanged. The installed Python SimpleHTTPRequestHandler.send_head implementation emits 304 whenever file modification time is <= If-Modified-Since (unless If-None-Match is also supplied), without comparing content. Changing the upstream artifact can move filesystem timestamps backward. That causes the browser to keep the prior module bootstrap, explaining the subsequent import request for a Rust worker absent from the React rollback artifact. This is a staging HTTP validation failure; changing the bridge cannot repair a response that falsely asserts unchanged bytes.

Minimal correction, delegated to the existing rehearsal author: for the scoped sw.js and service-worker.js URLs only, fetch current upstream bytes unconditionally by removing If-Modified-Since/If-None-Match, omit upstream timestamp/ETag validators, and return Cache-Control:no-store with the actual status/body. An alternative is strong content ETag comparison; it is not necessary for this bounded rehearsal. Unconditional validation is not cache, storage, or registration deletion. Preserve artifact bytes and their existing provenance.

Before resuming, replay the captured old validator against the corrected proxy and require 200 plus the exact rollback bridge hash. Continue from the failed reverse boundary in the same profile/origin, preserve the successful forward evidence, prove React worker control and durable readback, then final forward and Rust readback.
