# BoardStudio frontend migration roadmap

Inventory is read-only against React `dev` at `5a472a94`; Rust integration is `f0ac0a19`. Machine-readable file ledger: `/tmp/boardstudio-frontend-inventory.json`.

The scope is now entirely the frontend migration. Port every production TSX view/component to Dioxus/Rust, including the full React theme and responsive behavior. Continue to use the existing document engine, application session, host/storage, renderer, CAD, generator and export service boundaries. Do not rewrite those service implementations as part of this UI roadmap. Any React hook that currently owns user-visible navigation, selection, panel, theme or workflow coordination must be expressed as Dioxus presentation state or use the existing Rust session/host service; it must not survive as a hidden TS coordinator in production.

The source ledger accounts for all **79 TSX files**: **63 production presentation files**, **15 test TSX files**, and **one workbench bench/demo harness**. Every production TSX is assigned once to a milestone; tests and bench are listed separately with their owning milestone. The ledger also lists 18 source CSS files, 10 production `use*` hook files (the additional `use*` test is accounted for under verification), two source font assets, and selected visual references. Export has no standalone React TSX: its route is composed inside `Workbench.tsx` and callbacks in `main.tsx`, and is explicitly covered in the Export milestone.

## Ordered milestones

1. **Shell and project** (`01-shell-project-and-topbar`): reproduce the React topbar and project menu, six workspace tabs in their existing order (Layout, PCB, Keymap, Keycaps, Case, Parts), plus the separate Export action, save/undo affordances, project start/library, setup guide, theme choices, workbench frame, panel drawers and compact behavior. Keep current Rust Layout and Case screens connected; make the other four tabs clearly labeled, keyboard-reachable placeholders with no fake editing actions. This is the first visible progress checkpoint. **Exit:** paired screenshots and DOM review against React at desktop and compact sizes; matching tab order/selected/focus behavior; no placeholder changes the document; zero new axe violations and manual keyboard/focus review pass.

2. **Layout, tree, inspector and tools** (`02-layout-tree-inspector-and-tools`): port object tree, board picker, canvas objects/layers, selection, inspector controls, command menus, matrix creation/resize, mirrored layouts, constraints, outlines, guides, findings and navigation. **Exit:** matched blank/REVIUNG/Sofle user traces for create/select/move/edit/snap/mirror/outline/findings/Undo/Redo/reload; matching displayed states and geometry; keyboard and pointer semantics, compact layout and accessibility pass. Existing Rust APIs remain the authority.

3. **Parts** (`03-parts-library`): port the searchable Parts/library workspace, definition/profile forms, assemblies, module/footprint/model previews, inspector and import/create/place flows. **Exit:** React-matched browse/search/create/import/preview/place flows; same project and asset roundtrip, stable identities, source attribution and visible empty/error/loading states. Reuse catalogues and backend import/compile services.

4. **PCB** (`04-pcb-workspace`): port PCB layer/overlay and module views, board references, hardware instances/readiness, controller and wiring/pin assignment panels, remap/review states. **Exit:** matched module placement/inspection, layer visibility, controller/topology/assignment and finding traces; all data routes through current Rust electrical/module services; fixtures and failure/recovery states compare with React.

5. **Keymap and Keycaps** (`05-keymap-and-keycaps`): port keymap canvas/layers/key selection, behavior editor, macros/encoders and firmware controls, plus keycap profile/legend/size/fit controls. **Exit:** matched editing, selection, history/reload, fit/findings and generated preview workflows; current Rust keymap/keycap/firmware services produce the same accepted results. Unsupported behavior families remain explicitly reported.

6. **Case and 3D** (`06-case-and-3d`): port case choice/generation controls, settings/inspector, mechanical assembly panel, 2D overlays, 3D viewer/scene, model failure boundary and instance controls. **Exit:** paired config→preview→commit→save/reload→STEP path over every supported fixture and physical instance; findings, errors, cancellation, camera and 3D lifecycle match; no material/resource claims beyond direct evidence. Resolve or explicitly scope the known unready right-PCB input.

7. **Export** (`07-export`): implement the Export route currently embedded in `Workbench.tsx`, plus export status/readiness/error/download UI composed by `main.tsx`; include archive/project copy, STEP, PCB/manufacturing, firmware/keymap and other currently supported outputs. **Exit:** every supported export can be selected and run with exact scope/readiness; bytes or independent semantic outputs match established React oracles; cancel/stale scope suppresses delivery and browser resources clean up. Reuse existing Rust exporters.

8. **Crosscutting theme, accessibility and retirement** (`08-crosscutting-theme-accessibility-and-cutover`): reconcile shared theme tokens, fonts, responsive rules, keyboard shortcuts/focus, loading/error/empty states, startup/offline UI, panel persistence and cross-workspace navigation. Audit all UI hooks/orchestration from the ledger and adjacent TS entrypoints; move application coordination into existing Rust session services or Dioxus-only presentation state. **Exit:** all production TSX has a Dioxus counterpart and is removed from production entrypoints; all modes pass shared responsive/theme/keyboard/screen-reader/axe checks; complete browser parity and build checks pass; runtime dependency/reachability proves no React/TSX UI remains. Keep test/bench TSX only as dev tooling until equivalent Rust/browser coverage exists, then retire or replace deliberately.

## Working rule for visible progress

Build the shell first and show a coherent, themed interface with all six workspace tabs plus the separate Export action. Placeholder screens should resemble their future workspace frame and say what belongs there, while clearly remaining unavailable. Then replace placeholders one vertical workspace at a time. A milestone is complete only when its React behavior, visuals, responsive layout and accessibility have a matching Dioxus trace; component presence or a screenshot alone is insufficient.

The JSON ledger is the checklist of source files; update it as files are ported, split or retired. Do not interpret the existing M1 case/STEP acceptance as full frontend parity. This roadmap does not move backend/generator code, alter schemas or approve production cutover. Final React retirement requires the full frontend suite, preserved rollback/data access, and confirmation that Dioxus calls the existing Rust services for application behavior.
