# Page-feature Rust packaging reuse

This isolated change extends the existing explicit page-leaf reuse guard to ordinary Rust modules only when the current active module graph proves page ownership. It preserves the full22-command path, provider/source byte manifests, root and `/boardstudio/` routes, offline regeneration, and fail-closed behavior for shared inputs. It does not claim a public frontend result or parent completion.

The guard reads the `boardstudio-web` required feature and feature declarations from `web/Cargo.toml`, then derives page/core-worker/CAD-worker/service-worker cfg roots from the packaging helper's exact full-command matrix. It resolves external module declarations from `main.rs` and `lib.rs`, applying the crate's wasm32 release cfg values. Current-source graph inspection finds132 page-only Rust inputs and13 test-only Rust modules; the explicit provider graphs contain3 core-worker,4 CAD-worker and3 service-worker paths. The `layout_align_geometry.rs` Core native test alias remains excluded. Only `core/tests/electrical_wiring.rs` is treated as a test-only Core input. Cargo/build roots and helper source remain pinned, and `main.rs` only permits cfg-page module-root additions plus the exact native-only test stand-in. Unsupported cfg attributes, unresolved paths, provider overlap, source removals, and all other changed inputs reject before output creation.

No actual packaging build was run in this isolated author change. Because the packaging helper is itself byte-pinned, this source change invalidates any older helper-matched full-build baseline; root must first establish a fresh full22 baseline from the integrated helper before exercising a real8-command reuse candidate. The verified `a8fd8988`/34739 baseline remains evidence for the timing motivation, not a valid baseline for this changed helper.
