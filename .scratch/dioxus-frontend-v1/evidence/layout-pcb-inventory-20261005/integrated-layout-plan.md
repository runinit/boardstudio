1. Select Left PCB and existing `keys` matrix; record board/matrix IDs, accepted revision, board part count, and initial Layout 2D camera. Use public **Add object → Matrix…** to create one 1×1 MX Solder matrix on Left PCB. This single create operation is the matrix authoring step; it should leave one new matrix and its generated switch/diode IDs on Left only. Do not add a second placement journey.
2. Select `keys` → Column 1 and change **Offset X** from 0 to 2 mm (F3.3 paired control). Select the existing standalone `U1`; in its Relations inspector add the public **Offset from part** constraint sourced from `left-keys-SW1` (the fixture-local counterpart of the accepted `main-right-keys-SW1` source), with Offset X 2 mm, Offset Y 30 mm, Rotation 0°. Record the source/target IDs, accepted constraint, and resulting U1 transform. This reuses the paired accepted C01/C05 constraint shape without repeating Align anchor matrices. Avoid re-running Align, gesture threshold, pointer-capture, and general draft matrices already covered by F3.3 receipts.
3. Open Board outline → Generated perimeter, select point 2 and change X by one ¼u step using the public perimeter control; commit. Record the resulting contour coordinate and joined SVG path/hash. Existing f34d evidence establishes this exact point/control, one-step Undo/Redo and save/reopen route.
4. Open Layout findings and activate the Left PCB **Show outline** warning. Confirm navigation selects Layout, Board outline, and **Outline Generated**, then record resulting focus/fit/camera state. This reuses the supported live same-board finding branch; do not invent a missing-target case.
5. Switch 2D → **Layout 3D** → 2D. Record selected board, selected matrix/context, placement tool cleared, and each app’s own 2D camera restored. Do not claim cross-app camera pixel identity; compare restoration within each app as F3.6-C02 does.
6. Before reimport/reload retires session history, Undo the final outline edit once, verify its prior coordinate/path and one history step, then Redo and verify restoration. Save a project copy in each app; compare normalized accepted documents for Left/Right membership, matrix/layout/constraint values, generated associations, outline and assets. Existing fixture IDs must remain stable; independently allocated new IDs are compared by semantic role and internal references rather than assumed byte-identical UUIDs. Reload each saved copy through its public Open project flow and re-check the accepted state. Record revision/history and save/reload separately; do not require archive import to retain session undo history.

The paired receipt should separate expected floating-point tolerances from exact ID/association checks and explicitly log any error, rejected operation, cancellation, or service result. The saved fixture begins with 70 Left and 70 Right parts; the 1×1 placement should add two Left parts only. Keep the final comparison on this one combined journey; do not repeat all leaf matrices.
