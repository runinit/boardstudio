## Operational finish line and limits

1. Freeze the 24 source paths after the review's concrete blockers are clear. Stage only those paths and the coordinator's intended canonical records; preserve unrelated staged evidence.
2. Run the required combined integration gate once. A repeat `prepare-gates`/commit should reuse exact successful receipts; show actual reuse in the coordinator log. Source/tool/config changes must miss, and zero/incomplete/excluded results must fail.
3. Commit the frozen batch, then use one full snapshot package for the new donor. Independent live edits may continue while the isolated package runs. Validate provenance and both served routes before public qualification.
4. Reuse this candidate for grouped desktop journeys, including the actual Case export file. Keep F8/F9 and other unsatisfied final joins open. Publish another package only for an actual changed outcome.

Historical package observations were 470.7s for a full package (341.7s provider work) and 128.0–129.6s for previously eligible reuse packages. Those are evidence for potential savings, not a new measured acceleration result. No extra package should be built solely to produce an attractive benchmark.

The implementation effort itself exposed a process failure: ready product work was coupled to a new infrastructure batch, while shared fixture revisions and late infrastructure review findings extended the critical path. The coordinator's binding delivery-policy revision is therefore part of the correction: one named public outcome, bounded authors, one coherent review/gate/frozen package, and no optional coverage or tooling on that product critical path.
