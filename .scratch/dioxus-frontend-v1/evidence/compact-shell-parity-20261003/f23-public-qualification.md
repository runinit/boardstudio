## C03 Escape repair handoff

The read-only TS reference (`app/src/ui/WorkspacePanel.tsx`) handles Escape from within the panel aside: it closes compact state and focuses the corresponding workspace toggle. The new Dioxus regression covers the separately reachable state observed above, where the drawer is opened by its visibility toggle and focus remains on that trigger. Dioxus now handles Escape at the compact visibility nav when either drawer is open, closes both mutually exclusive open signals, and returns focus to the active drawer's trigger. Existing panel-descendant Escape handling remains responsible for Escape from inside the drawer (including existing options-menu handling); the nav handler cannot receive those descendant events because the nav and panel are siblings.

A focused browser regression was prototyped for trigger-focused Escape, scrim removal, returned focus, `aria-hidden`, and `inert`. The first attempt was blocked by concurrent unrelated compile errors in `web/src/case_gesture_preview.rs` (`crate::cad_jobs` unresolved) and `web/src/presentation/pcb_board_reference.rs` (`is_model_filename` inaccessible); after those were repaired, it compiled but its strict 760px viewport assertion failed under the headless browser default. The Objects compact breakpoint is 980px; a test-scoped resize attempt was rejected at compile time because the current web-sys feature set does not expose `Window::resize_to_with_x_and_y`. Per coordinator direction, the harness test was removed instead of adding shared browser config or retaining a permanently failing test. The public RED observation above remains the behavior evidence; the coordinator will verify the source fix once on the packaged compact candidate. `rustfmt --edition 2024 --check web/src/presentation/panels.rs web/src/presentation/panels_scroll_tests.rs` and scoped `git diff --check` pass.

**Candidate:** `http://127.0.0.1:34800/`, build `frontend-functional-batch-20261004`, source `14434d50`; owned browser sessions `f23escape-7dd31abc1fc4` and `f23both-7dd31abc1fc4`; viewport 800×700. The existing TS source comparison above remains the reference; no paired retest was done.

For Objects, the drawer was confirmed open before Escape: toggle `aria-expanded=true`, focused element `Objects`, scrim present, Objects `aria-hidden=false`/`inert=false`, and Inspect `aria-hidden=true`/`inert=true`. After Escape, Objects was closed, the scrim was absent, focus was on the Objects toggle, and both panel slots were `aria-hidden=true`/`inert=true`. No project editing action occurred. The Escape handler only changed the compact panel open signals and restored focus.
