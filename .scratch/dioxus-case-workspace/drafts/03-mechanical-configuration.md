# Draft F7.4a: Configure the mechanical stack

**Parent:** F7.4 — Mechanical assembly configuration editor.

**What to build:** A designer can enable and configure the selected board's mechanical stack, choose supported construction and mount arrangements, edit the represented stack dimensions, inspect resolved layers and diagnostics, and disable the stack without losing authored Case bodies.

**Blocked by:** INT.1 only, matching F7.4's canonical `start_after`. This saved-fixture editor does not wait for F7.3's viewer or F3/F4/F5 completion.

**Parent acceptance join:** INT.2 remains required for F7.4 integrated acceptance. F7.4a is only one bounded child and cannot close the parent.

**Status:** draft for independent review; not published or counted.

- [ ] When no matching mechanical configuration exists, offer the existing “Configure mechanical stack” action with the current supported initial settings. For the selected canonical board use `SetMechanical`; for a physical-instance Case scope, apply to that instance through the existing shared-construction/instance update and normal accepted document edit path. Preserve unrelated document, per-instance features, bodies, board/instance IDs, and existing config fields.
- [ ] Expose the represented construction choices only: PCB FR-4 / printed / CNC / cut-sheet method; tray / rigid / gasket mount; shell / sheet bottom; middle frame only for sheet bottom; integrated plate frame only where allowed. Choosing gasket mount performs the source-prescribed compatible state updates and disables incompatible construction controls; do not invent choices.
- [ ] Edit plate, plate foam, PCB, bottom foam, bottom, wall, clearance and radial opening allowance dimensions. Show the existing profile-derived plate-to-PCB gap and supported-thickness range, including unresolved/missing-profile explanations; do not recalculate core geometry in the UI.
- [ ] Show the resolved stack layers in current order with derived thickness/Z and stable layer IDs; selecting a layer follows the existing Case display-selection path. Show current mechanical diagnostics/findings and route a selected finding through the existing finding navigation.
- [ ] Keep generated and authored Case modes exclusive. When the selected instance has matching mechanical configuration, keep authored Case body records saved but hide/disable their authoring controls while the generated stack is active; disabling the mechanical stack restores authored-body editing without deleting or rewriting those body records. When configuration belongs to another board, show the existing mismatch explanation and “Show configured board” action beside the selected board's authored-body editor; do not expose the mismatched configuration as editable for the current board.
- [ ] Scope every field draft, submit and feedback to the current full session/document/board/instance Scope, accepted snapshot token/revision, configuration board ID and component lifetime. Admit only when the current instance-selection guard passes, Runtime is Ready, no display preview or gesture is active, the accepted revision is Saved, and no configuration operation is already pending. Serialize commits; apply each accepted field patch to the latest matching configuration after the prior operation settles so an older full-configuration replacement cannot erase a successful edit.
- [ ] On successful operation outcome, clear a field draft only after the expected accepted revision is saved. On rejection/failure retain a correctable draft and show the current error; a busy/stale request cannot replace or settle another field's pending request. Escape restores the accepted field value; preserve the source numeric field's blur/Enter commit and Escape rollback behavior with one commit per field.
- [ ] Use existing `SetMechanical`, physical-instance configuration/update and replace-document operations, current profile/stack resolution, Runtime operation outcomes and standard Undo/Redo. No public API/schema/visibility changes, new geometry engine, duplicate state/history, or second persistence route.
- [ ] Public paired browser evidence covers configure/edit/disable; tray/rigid/gasket and sheet/frame conditional controls; valid/invalid numeric blur/Enter/Escape; derived dimensions, stack selection and diagnostics; generated mode hiding/restoring authored editing with body retention; cross-board mismatch navigation; busy/failure/stale feedback; selected-instance transitions; actual native saved document/archive payload, Undo/Redo, save/reopen, and return after scope changes. Fixture-only form rendering does not establish F7.4 or INT.2 acceptance.
- [ ] **Ownership:** a private stack-settings component and feature-local styles; coordinator owns Case root mount, Runtime admission/outcome callback and shared CSS; F7.2 owns authored body editor and mode join; F7.3 owns viewer. Coordinate one private configuration patch callback and avoid concurrent edits to those owners.
- [ ] **Profile:** Luna High author and verifier; Astra independent reviewer. The scope-keyed full-configuration editing and selected physical-instance path require High until integration proves the private operation-outcome seam.
- [ ] **Refactoring handoff:** No new refactoring takeaway observed in this source pass. Preserve relevant RF-006 (Case physical-instance versus canonical scope) and RF-001 (private host/service boundary) evidence; update only if implementation proves a distinct finding.
