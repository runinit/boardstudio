## Public test flow

Use dedicated fresh disk-backed browser profiles, a named agent-browser session, the new candidate URL supplied by root, and supported UI actions only. Do not reuse the React `:5173` profile or another agent's browser session. Import `.boardstudio` files via the visible import control; never seed IndexedDB or mutate browser storage. Record exact build commit, manifest, served app/WASM asset hashes, route, viewport and profile at run time.

### A. Fresh REVIUNG41: Configure, field edits, generated gate, history and reload

1. From the fresh candidate landing page, use the public REVIUNG41 copy action, open `Case`, and expand `Case settings`. Wait for actual accepted/durably-saved status; capture before/after snapshots/screenshots. Configure the unconfigured real demo through the visible button.
2. During `Saving mechanical settings…`, observe whether `Generate case` is disabled while the mechanical controller resolves/commits. Once an exact current Case scene has non-empty suggested locations and closure initialization is pending, the Generate gate must remain closed until that request settles Saved. Do not assert against a guessed timing window; capture only the real pending interval if it is observable. A failed/stale resolver must remain visibly retryable and must not expose success.
3. After `Mechanical settings saved.`, inspect the actual stored document from IndexedDB using a **readonly** transaction and independently save a public `.boardstudio` archive. Compare accepted stored `project.json` and archive `project.json` (at minimum canonicalized full-document hash plus the focused fields below). Check project/board/instance IDs, top-level or physical-instance ownership, default processes/dimensions, generated `case-closure/` part IDs, `assembly-closure/definition/` IDs and board membership. Expected Reviung defaults match the table; expect four real generated NPTH closure parts/definitions if the actual resolver returns the four fixture suggestions.
4. Change `Plate method` to CNC, wait for saved acknowledgement, read the accepted record and save archive. Verify the selected configuration changed, plate/bottom process became CNC/Aluminium, foams remain cut-sheet/EVA, and all four closure records/parts/definitions and board memberships remain. Change it back to 3D printed and verify plate/bottom reset to printed/PLA with the closure data preserved.
5. Exercise dimension editing on `Clearance`. First type a changed draft then return to the accepted `0.30` before blur; assert no saved revision/document hash change (no-op/revert). Separately type a changed draft and Escape; assert immediate rollback and no durable edit. Enter `-0.1` and blur/Enter; expect a validation alert and no accepted revision, stored document, or generated hole change. Then set `0.45` and commit with Enter (and optionally a separate blur case if time permits); wait for its own Saved acknowledgement and assert exactly one accepted revision for the edit. Real boss holes should be 6.9 mm (6 mm boss + 2 × 0.45 clearance), with 4 parts/definitions/memberships updated atomically. Capture all values from the accepted record and archive, not only the UI label.
6. Press public Undo once: clearance returns to 0.30 and corresponding NPTH drill/definitions/membership return together. Press Redo once: 0.45 and 6.9 mm return together. Verify one history action per user commit; the entire configuration/projection changes as one entry.
7. Change one numeric draft without submitting and navigate `Case` → `Layout` → `Case`. Verify the remounted field reflects its accepted value and no abandoned draft/error/acknowledgement binds to the new presentation. For a best-effort stale-request case, trigger a real field request then navigate away/back immediately; only count it if the operation actually remained pending, and require the new view to show only current accepted state. Do not force delays or patch runtime state.
8. Disable through `Disable mechanical stack`; after Saved, assert instance mechanical settings absent, `constructionLinked` false for that target according to the real scope, zero owned closure parts/definitions and zero owned board/layout memberships, while unrelated parts, definitions, board memberships, matrices, assets and authored-body records remain. The Reviung reference has `caseBodies: []`, so it cannot establish retention of a non-empty authored-body fixture; report this limitation rather than treating empty preservation as proof.
9. Public Undo/Redo around Disable must restore/remove the same configuration and all generated PCB projection in one history step. Save archives for baseline/edit/disabled/history states; reload the same candidate profile and publicly reopen the archive in a separate fresh profile. Read IndexedDB only after `Saved`, compare the actual stored record to the archive payload, and record imported project identity and revision.

### B. Sofle v2 split physical-instance scope

1. In a separate fresh profile, use the public Sofle v2 copy workflow. Confirm from the live tree/inspector which physical assembly is selected. 2. Save/read-only-snapshot the Left accepted record before touching Right: `left` instance printed/PLA, clearance 0.3, same four closure mounts; right unconfigured; four owned closure parts/definitions on board `left` only. This becomes the actual candidate baseline for the Right comparison.
3. Select the real Right case assembly via the visible tree/physical-instance control. If public UI shows a cross-board mismatch, follow its public `Show configured board` affordance and re-select Right through visible controls; if the public candidate still refuses a supported edit, preserve that as a failing observation rather than forcing scope through devtools.
4. Configure Right if it is genuinely unconfigured, then choose CNC. After its own Saved acknowledgement, compare full readonly accepted state against the baseline and the React archive reference: Left config object, clearance, process material, mount IDs and board `left` memberships must be unchanged; Right should be CNC/Aluminium, clearance 0.3 unless changed through public UI, with 4 closure records and 4 NPTH definitions/parts on `right`; total generated closure count 8; shared construction follows Right. Verify exact serialized process records, all 8 owned IDs and drill parameters from the accepted record.
5. Save candidate `.boardstudio`, reload same profile, and reopen in a separate fresh profile via public import. Confirm both physical instances and board membership remain. Do not claim the canonical-board Disable rule from this physical-instance exercise; explicit Disable in physical scope is separately known to clear shared construction and every instance config/link flag by issue 03.
