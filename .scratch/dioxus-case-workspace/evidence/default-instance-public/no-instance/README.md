# Public no-instance Case route

A real no-instance project was produced through the React public Create new keyboard control and saved through Export → Save .boardstudio. The archive is included; SHA-256 `1ed5423b426de67eee93267eb5d699590128334aa8967a029eb8ffa0ac11fcdb`. It starts as id `c2489560-66ff-4b1f-b074-c0b8e29e672f`, revision0, 0 parts, no `hardware`/instance records. The exact public export was imported to the candidate profile. Before edits, both apps' saved ProjectDocs exactly matched the archive and each other.

Before adding a body, candidate Case had no Physical instance selector; its Main board selection plus Add case settings/Generate case and `+ New case body` were visible. React presented the public Setup guide with `One keyboard` / `Split keyboard`, but `+ New case body` was also available.

Clicking real `+ New case body` in both apps succeeded. Each saved one Main board Plate at revision1, fields match (thickness3, clearance.5, z0, PLA, wallHeight14, wallThickness2, empty mounts), generated IDs differ. This confirms the authored-body route remains reachable for a public empty keyboard with no physical instance; it does not prove broader setup-case behavior.

Snapshots and pre/post screenshots are included. No direct storage writes, synthetic providers, or private APIs were used.
