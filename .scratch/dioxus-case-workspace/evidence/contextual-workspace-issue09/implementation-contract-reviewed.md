## User-visible behavior to preserve

The Case workspace has an assembly tree at left and one Case Inspector at right. In authored mode the Inspector contains the mechanical section and the authored Case stack editor together. The editor always exposes `+ New case body`, including when there are zero bodies. The selected authored body controls the existing body fields; Add Body creates the real accepted body and selects it. The assembly row, generated mechanical rows, PCB disclosure and live PCB component rows follow the reference hierarchy and labels. Selecting a PCB component selects the real part in the existing selection route but keeps the Case Inspector; it does not switch to Layout’s generic position Inspector.

With a matching mechanical configuration, generated mode shows its actual generated rows. With no generated row/layer selected, show the source-authored-body retention note. With a selected generated row, preserve the existing Case display controls and keep their visibility/color/reset actions in display state. When the mechanical configuration belongs to a different board, show the mismatch message and configured-board navigation in the mechanical section while retaining the selected board’s authored Case editor. Keep these visible source contexts even if their stateful editor observers must remain mounted while another view is active.

## Exact tree membership and labels

Preserve the reference hierarchy rather than flattening all features into a new generic tree:

1. **Assembly roots:** one row for each actual hardware instance on its actual board. If the project has no hardware instances, use the existing boards as reference fallback roots. Row selection/navigating uses the real instance or board identity; disclosure/select state may use a derived UI key but never pretends it is a saved domain object. Keep the active selected board/physical instance from the current Case scope. Changing instance goes through the root-provided existing navigation callback.
2. **Generated Case rows:** while a mechanical configuration targets the active board, list only current projected `MechanicalAssembly.stack` layers with the exact layer IDs and reference labels (for example Plate, Bottom case, Plate foam, Bottom foam, Middle frame, Battery; unknown real rows keep the producer label). Exclude the PCB pseudo-layer and gasket support rows from this direct layer loop as the reference does. Add the Gaskets disclosure/side-labelled support rows only when supplied by the actual matching mechanical projection; their row IDs remain UI identities over real support IDs and are not ProjectDoc selections. If the configured stack is stale, not resolved, or has no current layer rows, do not synthesize a hierarchy. Preserve the visible retained-authored-body note in the generated Inspector when no selected display layer controls are shown.
3. **Authored Case rows:** show actual accepted `case_bodies` for the active board only when there is no matching generated mechanical assembly. Use real CaseBody IDs and accepted body names/kinds. The Case Inspector remains mounted with MechanicalSettings plus authored editor even when this list is empty; the editor’s existing `+ New case body` is the reachable empty-state action. A mechanical configuration on another board produces the mismatch section and does not hide this board’s authored body list/editor.
4. **PCB branch:** show a PCB disclosure with the count of represented actual board components. Rows come from active board membership joined to accepted live `document.parts`, retaining their part IDs, references and definition labels. Route each through the actual `objects::context_for_part`: primary enabled matrix member → `TreeContext::Key`; represented assembly companion → `TreeContext::Component` with its matrix/cell/assembly lineage; live non-matrix board component → `TreeContext::Component` with its part ID. If `context_for_part` returns `None` (including a member in a matrix whose scene/member cannot be represented), render it non-selectable with truthful row content or omit it according to the reference source visibility; never coerce it to another context. A group/disclosure container is display-only and never selects a fabricated component.

All body/stack rows require the exact active board and current Case `Scope`; generated rows additionally require exact current `CadScene` scope/token and actual membership in its `mechanical.stack`. Board, session, instance or accepted-snapshot changes reject stale callbacks. Tree entry IDs may be derived UI keys; domain selections always carry producer IDs and their real lineage.

## Selection transitions: no new store

The root dispatcher remains the owner of `SelectionAdapter.selected_context`, `CaseSelection.body`, and `CaseSelection.layer` signals and passes current values plus scoped callbacks into these render leaves. Keep the reference’s independent active body and selected mechanical display layer behavior; do not force every row category into one newly invented exclusive-selection enum.

| User action | Required transition |
|---|---|
| Select Case body | Set the existing body ID through the Case selection callback; preserve the Case Inspector composition and its MechanicalSettings section. Do not submit a part selection or create a domain row. The selected body is resolved only against the current board’s accepted body list. |
| Select generated stack/gasket/display row | Use the existing scoped Case layer/display callback with the exact producer ID. As in the React tree helper, clear the prior generic `Scope` selection and selected part IDs before choosing the Case layer. Preserve the existing viewer/body/layer signals and appearance controls. |
| Expand/select PCB group | Expansion is view state; selecting the group selects the reference PCB context, clears generic selected part/scope, and retains the Case Inspector. |
| Select representable PCB part | First choose the PCB context (clearing stale generic selection), then use the existing root `TreeSelectRequest` / `select_tree` route with the exact `context_for_part` result and current scope. Keep the Case Inspector visible; do not route to generic position Inspector. A previously active authored body remains the Case editor selection, matching React’s independent `caseBodyId`. |
| Select assembly root / change physical instance | Use the existing scoped navigation callback. Selecting the active root clears the selected mechanical row and generic part context as in `choose('')`; changing instance uses existing navigation/scope reconciliation. Do not rewrite canonical mechanical configuration or drop a saved body. |
| Change workspace or accepted scope | Existing root reconciliation invalidates stale adapter/body/layer selections. The Case leaf filters rows and ignores stale callbacks; it does not maintain an independent scope or clear unrelated history. |

This resolves the precedence ambiguity without introducing a second selection authority: the Case Inspector is a composed Case panel in authored mode, not a per-tree-row switch to the generic selected-position editor. The selected body remains body-editor context; selected PCB part is a distinct active workbench part selection; selected mechanical layer controls generated display context.

## Mode and editor lifetime rules

- Authored mode always shows the mechanical settings/mismatch section plus the complete Case stack editor, including Add Body and the empty-state text when no body exists.
- Matching configured/generated mode shows the mechanical section, and only current stack rows. When no row is selected, show the “authored bodies remain saved / disable stack” note; when a real row is selected, preserve its current display controls. Hide authored edit controls from accessibility while generated, but keep `CaseBodyInspector`’s existing pending outcome observer mounted so an accepted save is not abandoned.
- Mismatch mode keeps the mismatch source section and configured-board action together with the selected board’s authored editor. Do not show matching-stack generated rows for another board/instance.
- Reuse one Editor-owned `MechanicalSettingsMount`; do not conditionally remount/recreate its controller or request sequence. Keep `CaseBodyInspector` observer alive across Inspector context/display switches. Hide inactive UI accessibly without disabling or removing source-visible messages that the reference displays in the current mode.
- Case body add/edit/mount writes continue through existing `CaseBodyInspector` → Runtime accepted edit flow. Mechanical writes continue through `MechanicalSettingsController`. Display visibility/color/reset stays in `CaseSelection.display` and never enters Session history.
