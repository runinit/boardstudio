# 09: Case assembly Objects tree and contextual Inspector

**Parent:** F7.2 authored Case workspace and F7.4 mechanical configuration.

**What to build:** In Case, the Objects panel presents the actual selected assembly rather than the Layout grouping tree. The Case Inspector is one composed surface: in authored mode it shows both the mechanical section and the Case stack editor, including `+ New case body` when the accepted body list is empty. Selecting an authored body updates the existing body editor. Selecting a generated row updates the existing Case display context. Selecting a live current-board PCB part uses the exact context returned by `objects::context_for_part`—`Key` for a supported matrix primary key, `Component` for a represented companion or non-matrix board component, and non-selectable/omitted when the helper returns `None`—while keeping the Case Inspector visible. It does not open Layout’s generic position Inspector. Preserve source selection semantics: Case body context, mechanical layer context and the root-owned selected-part context remain distinct signals; selecting a PCB part does not erase the active authored body selection.

**Blocked by:** INT.1 (accepted). No F7.3 viewer blocker for the Objects-tree-to-Inspector route. This slice uses existing accepted document/session, Case editor and mechanical-settings capabilities; 3D picking/model mapping remains with F7.3. Case may author its private hook-free workspace leaf against the reviewed contract while shared composition is in progress. Root owns dispatcher registration, shared inputs/callback wiring and shared panel/CSS integration; Case does not edit that boundary concurrently.

**Parent acceptance joins:** F7.4 still requires INT.2; F7.3 still requires INT.2 and BND.1; F7.7 still requires F5.6; F7.8 remains the downstream cross-workflow acceptance. This ticket changes none of those joins and does not close F7.2/F7.4.
