# F7.5: Edit supported Case mounts and gaskets in the viewer

**Parent:** F7.5 — Case viewer direct-manipulation preview edits.

**What to build:** A designer can use the existing Case viewer's supported gasket and mount handles, preview a constrained move, and commit or cancel one coherent edit to the currently selected physical assembly. The standalone toolbar action for unlinking a selected gasket pair is extracted to [Issue14](14-case-contextual-gasket-support-unlink.md); Issue07 retains its full gesture and linked/unlinked movement acceptance.

**Blocked by:** F7.3 shared viewer interaction seam and completion of F7.4 mechanical configuration (all F7.4 child slices 03–06). This preserves the canonical F7.5 `start_after: [F7.3, F7.4]`; fixture-level renderer work cannot claim integrated direct-manipulation acceptance before these gates.

**Parent acceptance joins:** None beyond F7.5's own slice acceptance. Do not infer F7.8 or F7 viewer closure.

**Status:** source-confirmed and still unimplemented in the Case projection. React `AssemblyScene` derives current gasket/mount handles when the corresponding edit mode is active and attaches drag/cancel handlers. Dioxus already has the shared pointer/handle lifecycle in `shared_viewer.rs`, and Case exposes the Edit gaskets/unlink toolbar, but the current Case scene projection supplies `handles: Vec::new()`, so Edit gaskets cannot materialize the reference handles. Issue 14's unlink action remains a separate implemented workflow; it does not satisfy placement editing. The existing F7.3/F7.4 start gates and this ticket's constraint/rollback criteria remain unchanged.

- [ ] Reuse Issue14's Case-viewer unlink action and expose the remaining existing viewer actions: edit gasket handle placement and edit the supported mount targets. Do not add arbitrary 3D object manipulation. Gasket cut length and width remain selected-support numeric Inspector controls from F7.4c; viewer drag is placement, not resizing. Controls are available only when current prepared geometry and source readiness conditions allow the relevant handles.
- [ ] During gasket dragging, use the current perimeter projection and transient preview path. Cancel if no valid perimeter location exists; a projected move is committed once through the existing mechanical edit path, then fit diagnostics report `fitError` and block preview/export if the placed support does not fit. Do not treat fitError alone as a pre-commit drag rejection: the source explicitly checks fit after placement. For mount dragging, preserve current edge/hole/other-mount constraints; blocked positions cannot commit. A successful move commits exactly once to `SetMechanical` for suspension/closure mounts, `SetCase` for an authored body mount, and the corresponding per-field body/config owner.
- [ ] Cancel/rollback on pointer-cancel, Escape, explicit cancellation, viewer unmount, physical instance/document/board Scope change, accepted token/revision change, no valid gasket perimeter projection, or invalid constrained mount placement. Release pointer capture/renderer drag resources and clear transient preview so no draft leaks into another instance. A gasket fitError discovered after a projected move has been committed is shown as the current fit diagnostic and blocks preview/export; it is not retroactively treated as a rejected drag sample.
- [ ] Route mount movement to the exact current target: non-gasket suspension mounts in the mechanical `mounts` field; closure mounts in `closureMounts`; authored body mounts by body ID; each preserves its stable mount ID. Reuse Issue14's saved unlink state when testing linked/unlinked gasket movement. Inspector numeric resize remains F7.4c and updates the linked pair unless unlinked.
