- **Zoom (paired C04 follow-up, 2026-10-03):** pinned TS source `5a472a94` at `http://127.0.0.1:5175/` and the current Dioxus candidate at `http://127.0.0.1:34786/`, in named sessions `f73c04-ts-zoom-20261003` and `f73c04-dioxus-zoom-20261003`. The reference canvas accessibility label says “scroll to zoom”; the Dioxus canvas handles the same wheel input. The earlier `agent-browser mouse wheel` captures were a driver-coordinate issue: its event landed on the page header (`target=HEADER`, `defaultPrevented=false`), not the canvas. With the pointer coordinates set to each canvas center through its `agent-browser stream`, trusted wheel events landed on `CANVAS` and were handled (`defaultPrevented=true`). A `deltaY=-400` wheel event visibly enlarged the assembly in both apps; the opposite `deltaY=400` returned both views near their starting scale. Reference captures: `11-zoom-wheel-base.png`, `12-zoom-wheel-negative-400.png`, `13-zoom-wheel-positive-400.png`; candidate captures: `20-zoom-wheel-base.png`, `21-zoom-wheel-negative-400.png`, `22-zoom-wheel-positive-400.png`. The initial byte-identical wheel captures do not indicate a Dioxus defect.
- **Render modes:** Dioxus visibly changed for Wireframe, Hybrid and Show hidden lines; matching React controls also responded. Candidate captures: `06-wireframe.png`, `07-hybrid.png`, `08-hidden-lines.png`; reference: `05-wireframe.png`, `06-hybrid.png`, `07-hidden-lines.png`. Shaded is the default mode.
- **Section plane and position (paired follow-up, 2026-10-03):** pinned TS reference source `5a472a94` at `http://127.0.0.1:5175/` and Dioxus candidate source `f6aa4cb0` at `http://127.0.0.1:34785/`, using named sessions `f73c02-ts-position-20261003` and `f73c02-dioxus-position-20261003`. ## F7.3-C03 Case layer appearance qualification (paired, 2026-10-03)

Candidate: published `frontend-case-layer-appearance-20261003`, source `f6aa4cb0`, at `http://127.0.0.1:34785/`. Pinned React reference: `http://127.0.0.1:5175/`. Fixture: fresh public built-in **Sofle v2**, selected `Left PCB`, generated default mechanical stack. Both app sessions were named (`f73c03-ts-7dd31abc1fc4`, `f73c03-dioxus-7dd31abc1fc4`) and closed after evidence capture.

- **Selection and control ownership:** In the reference, selecting the `Plate` row in Objects selected `Plate` in the Inspector. In Dioxus, opening Assembly layers and choosing `Select Plate for appearance` selected the same layer and opened its existing Inspector display controls. Both Inspectors showed `Plate`, Colour (`input[type=color]`, initial value `#b4bac2`), Reset colour and checked Visible. Reference screenshots: `reference/f73-c03/01-plate-selected-default.png`; candidate: `candidate/f73-c03/06-plate-selected-default.png`.
- **Colour/display and reset:** Filling the color input with `#ff0000` through agent-browser produced `#000000` in both browsers (the same driver outcome on the paired apps). Both swatches and rendered previews changed visibly from the default state; the Inspector remained on Plate. Clicking Reset colour restored `#b4bac2` in both. Changed-state screenshots: `reference/f73-c03/02-plate-color-input.png` and `candidate/f73-c03/07-plate-color-input.png`. Dioxus reset-state screenshot: `candidate/f73-c03/05-plate-reset-default.png`; the reference reset value was also read back as `#b4bac2`.
- **Independent visibility:** With Plate selected, Hide Plate changed the action to Show Plate and the Inspector Visible checkbox to unchecked in both apps. Show Plate restored the Hide Plate action and checked state without changing the selection. Paired screenshots: `reference/f73-c03/03-plate-hidden.png`, `reference/f73-c03/04-plate-restored.png`, `candidate/f73-c03/08-plate-hidden.png`, and `candidate/f73-c03/09-plate-restored.png`.

No candidate/reference mismatch was observed. Automation limitation: the native browser color picker’s RGB controls could not be filled as DOM nodes (`DOM.resolveNode` reported that the node did not belong to the document), and the color-input fill substituted black for the requested red in both builds. This qualifies a visible color change and reset, but does not claim an exact red value or arbitrary hue selection. The app behavior under the successful paired interaction was equivalent.
