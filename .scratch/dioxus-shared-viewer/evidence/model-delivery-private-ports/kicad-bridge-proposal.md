# F7 model delivery: private Dioxus page bridge feasibility

**Status:** source-grounded implementation proposal; not an implementation or acceptance claim.  
**Reviewed contract:** `.scratch/dioxus-shared-viewer/evidence/model-delivery-contract-reviewed/contract.md` (SHA-256 `e3529ac79f1b7d69211a8fa4cdc9e4d1170ec39a3c6510ab458dddc3a634b946`).  
**Integration source inspected at:** `9ef5bc5cad09ab3064711b45fc348b4cc09a74d4`; this is a mutable integration tree, so hashes below pin the inspected source files, not a release artifact. No source edits, Cargo invocation, or build were performed.

## Decision

The existing Rust artifact boundary can prepare and validate a generated board preview without any Core/schema/public API change. The missing private bridge has two separable responsibilities: (1) execute the existing TypeScript Ergogen-to-KiCad conversion on each ordered Core `ExportPlan` job, preserving the React net allocator and model path rewrite; (2) resolve each resulting `PcbPreview.models` entry to verified bytes, decode STEP/STL/WRL through existing page workers/WASM, and supply `LoadedModelInput` under the exact Core model ID. Keep both behind the Dioxus page binary. Do not duplicate generator logic in Rust or synthesize preview geometry in the UI.

A small dedicated module worker is the best page seam: Rust `Runtime` uses its already-owned `CoreWorker` to issue `PreparePreview` and `FinishPreview`; a page-private JS module worker accepts the prepared plan plus safe path map, returns ordered `ErgogenJobResult`s and model bindings, and contains a bundle of the existing `@boardstudio/v2-kicad` / `@boardstudio/v2-ergogen` modules. The page then submits `FinishPreview` through the same CoreWorker. This keeps synchronous generator/render work off the Dioxus UI thread and lets Core retain plan, reserved-net, generated-form, and result-order validation. The worker is a port of the `runErgogenJobs` portion of `app/src/export.worker.ts`, not a new artifact implementation.

## Existing transformation and trust boundaries

- `kicad/src/ergogen.ts` exports `exportErgogenForms(definition, part, paths, netIndex)`. It calls Ergogen `render`, upgrades legacy `fp_arc`/`gr_arc` center/start/angle forms to start/mid/end, converts `module` forms to `footprint`, serializes allowed footprint/object forms, rewrites model paths through `modelAssetId` and the supplied safe `paths` map, and rejects missing/unsafe paths and unsupported forms. It must remain the sole converter for this work.
- `ergogen/src/index.ts::modelAssetId` maps `boardstudio-asset:<id>`, `${KIPRJMOD}/models/boardstudio/<path>`, and `${EG_INFUSED_KIM_3D_MODELS}/<path>` to saved asset IDs. `modelBindings(definition, part)` renders model bindings and returns the same canonical asset ID (or `unresolved-model:<encoded-original-path>`), offset, rotation, and scale. It flips Y offset and Z rotation to the renderer convention. It is the exact source for model lookup and placement binding; do not recalculate these in Rust.
- `app/src/export.worker.ts::netAllocator` clones `plan.reservedNets`, resolves existing names first, appends previously unseen names at monotonically increasing `nextNetIndex`, and returns snapshots. `runErgogenJobs` maps `plan.jobs` in order, calls `exportErgogenForms` with the prepared job definition/part and that allocator, and emits `{snapshotToken, revision, jobId, source, nets}`. Preserve this exact ordering and per-result net snapshot behavior. `finishRequest` additionally rewrites unresolved preview model paths under `models/unresolved/<encoded-path>` before finish; preserve it for preview jobs.
- `core/src/artifact/kicad/planning.rs::prepare_preview` reuses private `prepare(request, false)`. It validates v2 format and exact committed revision, resolves the board and definitions, computes reserved nets and terminal parameters, and builds ordered Ergogen jobs with IDs `<board-id>:<part-id>`. Its `ExportPlan` captures revision/token, target, jobs, nets, contours, document, and model paths.
- `core/src/artifact/kicad/output.rs::finish_preview` rejects non-board plans, then calls the shared `finish(request, true)`. That validator requires exact result count and order, matching token/revision/job ID, unchanged reserved nets, contiguous appended net indices, and valid generated KiCad forms. It then returns the preview board. `core/src/artifact/preview.rs::board` creates `PcbModel.id` as `<reference>:<global-model-index>` and keeps reference/path/pose/side/offset/rotation/scale. The renderer joins loaded meshes by that exact `PcbModel.id`; loaded-byte identity is not the part ID or reference.
- An imported/routed `BoardReference` remains on the direct `PreviewBoard {source, revision}` path, as in `app/src/assemblyPreview.ts::prepareBoard`; it does not run Ergogen jobs. Its `modelAssets` lookup precedes preview-path lookup, which precedes `modelAssetId(path)`. Generated-board previews use Core Prepare/Finish as above.

## Proposed private page protocol

1. Capture the current `Rc<CadScene>` plus its accepted snapshot and full `Scope` in the page presentation layer. Build the native PreparePreview input from `captured_case_document(&scene.snapshot, &scene.scope)` and that exact `scene.contours`, matching `shared_viewer.rs::project_case_scene` and React's physical Case document/scene choice. Preserve the accepted scope/token/revision as provenance; use the effective physical document's same committed revision for Core validation. This projection is required because an instance flip changes physical model poses/sides and disables the effective imported-board reference. Never substitute the canonical accepted document/contours where the current Case scene provides physical inputs, mutate Session, or invent a public projection API. Check canonical and flipped-instance inputs in the eventual page test.
2. Keep the original `ExportPlan` in the root and send only its ordered jobs, reserved-net state, next index, paths, and correlation envelope to a dedicated private JS worker. Use the approved model-delivery `ModelOwnerIdentity` (full Scope, SnapshotToken, viewer instance, projection generation, weak pointer to exact `CadScene`) and `ModelBatchIdentity` (owner plus accepted revision and replacement-batch generation). Do not include renderer scene sequence in these identities. Add a private monotonically unique worker request ID and worker-lifetime generation. A concrete request is `{kind: "generate-preview-jobs", worker_generation, request_id, owner: {scope, token, viewer_instance, projection_generation}, batch: {accepted_revision, batch_generation}, plan_key: {snapshot_token, revision, job_ids}, jobs, reserved_nets, next_net_index, paths}`. The matching success reply is `{kind: "generated-preview-jobs", worker_generation, request_id, owner, batch, plan_key, results}`; an error reply carries the same envelope plus a bounded error string. Validate exact worker generation/request ID and every identity/plan-key field against the pending waiter before consuming the result. Keep full plan authority in Runtime; do not accept a worker-provided/reconstructed plan.
3. The worker processes jobs sequentially with the React allocator semantics and `exportErgogenForms`, then returns ordered results. For preview, derive unresolved model paths using `modelBindings` exactly as `finishRequest` does. Do not send a mutable document back to the generator; its only domain input is the captured immutable job projection. Root checks current owner/batch before FinishPreview, calls `CoreWorker::artifact` with `FinishPreview { plan, results }`, then checks owner/batch again before publishing the preview. Core remains authoritative for artifact validation and preview construction.
4. Settle every waiter exactly once. A worker `error`, `messageerror`, explicit close, or replacement must remove and settle all waiters belonging to the failed worker generation; a request-specific error settles only its matching request. Supersession removes/cancels its waiter and is silent: a late result/error from an old request cannot settle a replacement request, display an obsolete error, or publish. Before FinishPreview and after every asset/decode await, require `ModelBatchIdentity::is_current` against the current owner, accepted revision, and batch generation; owner checks also require the exact live `CadScene` pointer. Keep healthy per-model results mergeable while new renderer scenes submit; renderer sequence remains independently allocated by the renderer owner.
5. For each accepted `PcbModel`, resolve the renderer source ID in this order: `BoardReference.modelAssets[model.path]` for routed/reference boards; the exact generated model-path table; then version-matched `modelAssetId(model.path)`. Match that stable ID in the captured document. For this archive-backed port, resolve document assets through the approved private model-delivery owner: current-import Runtime bytes by SHA, then SHA-verified durable `BrowserStore::load_asset`. The bundled model byte registry is absent and explicitly deferred; return the existing `MissingBundledProvider` outcome for an unarchived bundled ID. Do not add or claim a bundled manifest/provider in this slice. Missing assets are visible diagnostics, not fabricated geometry or IDs.
6. Decode by format using existing processing ports: `.step`/`.stp` through `CadOperation::ReadStep` in `web/src/cad_jobs.rs`/`cad_worker.rs` (bounded to 32 MiB with finite mesh validation); `.stl`/`.wrl` through renderer WASM `decodeStl`/`decodeWrl`. Consume the approved private model-delivery cache/decoder interface rather than duplicating it. Loaded inputs use exact `PcbModel.id`; renderer applies pose, board side, offset, rotation and scale. A stale or superseded batch completes silently; only errors from the current live batch reach the UI. Do not transform vertices again.

### Safe path map

Reuse the accepted document's asset IDs and model IDs, mapping each to a deterministic project-relative path beneath `models/boardstudio/`. Preserve current saved references and aliases; never derive a path from an unchecked original path. Apply the existing `modelPaths` safe-path validation in `exportErgogenForms`. The React unresolved preview rewrite is intentionally a placeholder path so Core can preserve diagnostics and a missing-model row; it is not an asset claim. The page should keep that missing result out of `LoadedModelInput` and report the missing source.

## Packaging feasibility and open build gate

The repository has a precedent for a private static browser module: `scripts/web/build-layout-generators.mjs` strips types from `ergogen/src/index.ts`, copies its generated catalogue, writes a small ESM entry, and writes source/output hashes to provenance. `scripts/build-m1.py` packages page assets and writes the offline manifest.

However, `kicad/src/ergogen.ts` has a runtime bare import of `@boardstudio/v2-ergogen`; `ergogen/src/index.ts` itself imports `../generated/catalogue.mjs`. The layout helper's simple strip-and-copy strategy alone is insufficient for Kicad: browser ESM will not resolve the workspace bare package name without a bundler/import-map rewrite. `@boardstudio/v2-app` already has Vite 8.3.1 and workspace dependencies on both packages, but no dedicated Kicad worker build entry exists. Recommended first implementation step is a minimal private worker entry importing the workspace exports plus the existing Vite/Rolldown toolchain, then emit a standalone worker bundle with source/output hash provenance. Verify no bare package imports remain, every generated chunk is offline precached, and the URL honors root and subpath deployments. Do not claim package feasibility until that isolated build and offline load test passes. This packaging work changes build assets only; it adds no Core/schema/public Rust surface.

`app/src/bundledModels.ts` enumerates vendor STEP/STP/WRL/STL files via Vite `import.meta.glob` and preserves three `thqwgd001` aliases, but Dioxus has no equivalent byte provider. The approved archive-backed model-delivery port explicitly defers a bundled byte provider. Keep that boundary: do not port the glob, add a manifest, or claim unarchived bundled-model delivery in this slice. Such a provider is a separately reviewed future build port. Current archived project assets resolve through document IDs/SHA bytes only.

`web/src/host/core_client.rs::CoreWorker::artifact` already dispatches a typed ArtifactRequest and checks request-ID agreement. But `Runtime.core` is private and `Runtime.assets` is a private in-memory map. The root/page owner must supply a narrow crate-private Runtime helper (or keep orchestration in `runtime.rs`) that uses that existing CoreWorker and captured asset-store semantics; do not expose CoreWorker, Runtime fields, or new library API to presentation consumers. `BrowserStore::load_asset` is public on the browser host wrapper and checks SHA, but imported unsaved assets can exist only in Runtime's map. A bridge that only calls BrowserStore will falsely report those as missing. The minimal correct seam is a page-private method that resolves exact asset IDs/hashes against current Runtime memory and then verified durable storage, with a stale-scope check around asynchronous loads.
