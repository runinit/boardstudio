# F7.3 model delivery and picking contract (draft for review)

**Status:** source-grounded integration plan; not an implementation or acceptance claim.  
**Review base:** integration worktree HEAD `3c83cc0f0d151f60518ae5ecaa5ed3e2dfef281e`; source inspection only.  
**Scope:** private browser adapter from the accepted project/board projection to existing model bytes, decoded meshes, renderer scene IDs, and existing Part selection. No Core, schema, CAD engine, renderer-export, or public visibility changes are authorized here.

## Decision

F7.3 can keep the existing Core and renderer contracts. Core already has artifact operations that return the renderer-oriented `PcbPreview` (including transformed component model metadata), the page storage layer can read archived asset bytes by SHA-256, the CAD worker already imports STEP into a mesh, and the renderer WASM already decodes STL and WRL. The remaining work is frontend adapter delivery and lifecycle ownership.

There are two concrete gaps in the current Dioxus Case route:

1. `web/src/presentation/shared_viewer.rs::project_case_scene` sets both `board.models` and top-level `models` to empty arrays (lines 290–307). It appends only bodies from `CadScene.result.bodies`. Thus that projection cannot display PCB component meshes even though the renderer accepts them.
2. No Dioxus page code currently resolves bundled model IDs to model bytes or calls the existing renderer `decodeStl` / `decodeWrl` exports. The React-only bundled URL catalogue is in `app/src/bundledModels.ts`; `web/src/presentation/parts/catalogue.rs` loads definitions but is not a model-byte provider.

These are private web-adapter/provider-integration gaps, not evidence of a missing Core document field or a need for a new model API. Local and archive-backed model bytes have an existing stable identity (`Asset.id` → `Asset.sha256` → verified BrowserStore key). Bundled Ergogen models need an equivalent private byte lookup in the Dioxus build; do not substitute a fabricated path or pretend catalogue definitions contain file bytes.

## Proven source contract

### Preview model source

- The document stores a `BoardReference` as `{ boardId, assetId, enabled, pose, elevation, modelAssets }`; `modelAssets` maps KiCad model path to the document's stable asset ID (`core/src/model.rs::BoardReference`). `Asset` separately stores `{ id, name, mediaType, sha256, ... }` (`core/src/model.rs::Asset`). A source model path is not itself an asset-byte identity.
- For an enabled imported-board reference, React loads the board source by finding `Asset.id == BoardReference.assetId`, then calls `loadAsset(asset.sha256)`, and sends its text through the existing `preview-board` artifact operation (`app/src/assemblyPreview.ts:230–239`). `ArtifactRequest::PreviewBoard` returns `ArtifactReply::PreviewBoard { result: PcbPreview }` (`core/src/model.rs::ArtifactRequest` / `ArtifactReply`). The resulting model path must be resolved through `BoardReference.modelAssets[model.path]` first (`assemblyPreview.ts:246–249`).
- For a generated/native board, React calls the existing Rust `PreparePreview` / `FinishPreview` artifact flow. The private middle step is not currently packaged for Dioxus: the React worker uses `@boardstudio/v2-kicad::exportErgogenForms`, a reserved-net allocator initialized from the plan, footprint/object form serialization, unresolved model-path rewriting, and the exact plan snapshot token, revision, and job IDs. The Ergogen wrapper also applies model-path rewriting and legacy-arc upgrading. The smallest bridge is private page-binary packaging/adapter work owned with the Case model-delivery slice; it must invoke the existing generator and preserve allocator, serialized source, and token/revision/job correlation rules. It must not substitute a raw Ergogen render or add a public API. The prepare request carries the accepted document, board, contours, revision, and `modelPaths`; after generation the existing finish operation returns the preview. `core/src/model.rs::PrepareExportRequest`, `ExportPlan`, `FinishExportRequest`, and React `app/src/export.worker.ts::prepareRequest/finishRequest` define the contract. `PcbPreview.models` contains one record per non-hidden KiCad footprint model (`core/src/artifact/preview.rs::board`); its `id` is the source-compatible `"{reference}:{modelIndex}"`, and it retains `reference`, `path`, pose, side, offset, rotation, and scale.
- React model resolution precedence is: imported-board `modelAssets[path]`; the preview path table built from current asset IDs; then Ergogen `modelAssetId(path)` (`app/src/assemblyPreview.ts:244–249`). The saved ID grammar for attached and bundled Ergogen paths is defined by `ergogen/src/index.ts::modelAssetId` (lines 301–309). Missing/unresolvable assets produce a model notice and no mesh; they do not get synthetic geometry.

### Byte identity and supported formats

- Local bytes are looked up by `Asset.sha256`, not by display name or path. `BrowserStore::load_asset(sha256)` reads IndexedDB and re-computes SHA-256 before returning bytes (`web/src/host/storage.rs::BrowserStore::load_asset`). The runtime also retains in-memory SHA-keyed bytes for assets being imported/saved (`web/src/runtime.rs::assets` and save/archive paths). Archive entries use `assets/<sha256>`; unpack verifies every document asset is present before persisting its bytes (`app/src/storage.ts::packProject/unpackProject`).
- React's bundled provider uses `ergogen:model:<vendor>/<filename>` stable IDs and a Vite glob over `ergogen/library/vendor/*/3d_models/**/*.{step,stp,wrl,stl}`; it preserves three upstream filenames that Vite cannot address literally (`app/src/bundledModels.ts:4–22`). Its bytes are fetched from the generated static URL (`bundledModelBytes`, lines 30–35). Packing an archive embeds used bundled IDs as ordinary `Asset` records with a computed SHA-256 and `assets/<sha>` bytes (`app/src/storage.ts:172–200`).
- The retained public fixture is the actual React `REVIUNG41` demo archive, not a separate “Reviung124” board. Its archive SHA-256 is `833533fa7fee58180c4721be54325c65b8600a935f75ac44a95c9de9059ab93e`; the existing React render contains **124 model instances** backed by four unique source assets: `Nice_Nano_V2.step` (`77fcad08…`), `SW_Hotswap_Kailh_MX.stp` (`31dd9ab0…`), `SW_Cherry_MX_PCB.stp` (`ddf0fb3a…`), and `Diode_1N4148W.step` (`abe50072…`). The archive’s `project.json` has 89 parts and those four model `Asset` entries. Existing public evidence uses the same archive SHA and records React Case mesh selection of `SW8` → “Key 2.2” / `main-right-keys-SW8` ([public Case QA](/home/chris/.local/share/boardstudio/worktrees/migration-m1-continuation-20261001/.scratch/dioxus-shared-viewer/evidence/public-case-first/RESULTS.md), [viewport regression](/home/chris/.local/share/boardstudio/worktrees/migration-m1-continuation-20261001/.scratch/dioxus-shared-viewer/evidence/case-viewport-layout/public/README.md)). This fixture proves the STEP/STP path and real reference selection; it does not cover STL/WRL decode.
- STL and WRL decode through existing renderer WASM exports `decodeStl` and `decodeWrl`, returning `positions`, `normals`, and optional `colors` (`renderer/src/wasm.rs::decode_stl_wasm/decode_wrl_wasm/encode_mesh`; React wrapper `app/src/renderClient.ts::readMeshModel`). React caps a source model at 32 MiB and rejects unsupported extensions.
- STEP/STP decode through React's existing CAD worker `readStepModel(bytes)`, which returns a triangle `mesh` and bounds (`cad/src/index.ts`, `app/src/case.worker.ts`, `app/src/CaseClient.ts::requestModel`). The Rust page already has the equivalent `CadOperation::ReadStep`, which accepts the bytes in `CadRequest.input_bytes`, returns `CadResult.mesh` and bounds, and transfers mesh buffers (`web/src/cad_worker.rs::validate_request/run/result_transfers`). That request is correlated by request/job ID plus exact `CadSnapshotIdentity`; `validate_reply` rejects an identity mismatch (`web/src/cad_jobs.rs`). It also enforces a nonempty source no larger than 32 MiB.

### Renderer mesh and pick identity

The renderer input is already sufficient: `BoardInput.models` carries `PcbModel` metadata; top-level `LoadedModelInput` is `{ id, mesh }` (`renderer/src/wasm.rs`). The renderer finds the board model whose `PcbModel.id == LoadedModelInput.id`, applies the source pose/side/offset/rotation/scale, and creates the render object with **ID equal to `PcbModel.reference`**, not the model ID. The scene must also retain the enabled `BoardReference` as the renderer’s `reference` input, including its nonidentity pose and elevation; the renderer multiplies that reference transform into board and component transforms. For an effective physical projection whose selected instance is flipped, preserve the existing reference-disable rule rather than applying the canonical board reference a second time. The object also receives groups `Models` and the loaded model ID, plus `Keycaps` for a path containing “keycap” (`renderer/src/wasm.rs::build_scene`, PCB model loop following the surface loop). This is the necessary identity bridge:

```text
PcbPreview.models[i].id  == LoadedModelInput.id   // renderer joins mesh to transform
PcbPreview.models[i].reference                  // renderer pick() result
current Board.partIds + Part.reference == pick  // existing selection lookup
```

React follows that bridge. `AssemblyScene` passes the picked renderer ID through; `AssemblyViewer` normalizes its generated keycap/module prefixes; and `Workbench` maps an exact reference through the currently selected board's `partIds` to the live `Part.id` before selecting (`app/src/ui/AssemblyScene.tsx::createRendererCanvas` callback, `app/src/ui/AssemblyViewer.tsx` `onSelect`, and `app/src/ui/Workbench.tsx` Case/assembly `onSelect`). A private Dioxus mapper should mirror this existing owner-side lookup: scope it to the captured document/board, require a current board part with the exact reference, and return no selection if none exists. It must not treat a model filename, `PcbModel.id`, or arbitrary renderer string as a Part ID.

For generated non-PCB scene objects, existing identities remain distinct: CAD bodies use `CadBodyMesh.id`; module preview bodies and model placements use the IDs returned by existing Core module resolution; keycaps use current keycap body IDs. Their mapping must follow the actual producer result and existing owner mapping, not reuse the PCB reference rule.

## Minimal private adapter plan

1. Capture the accepted `ProjectDoc`, selected board, existing `Scope` and `SnapshotToken`, selected physical instance, viewer instance/projection generation, and renderer scene sequence. The Case viewer's current `CadScene` already captures scope, token, accepted snapshot, body `CadResult`, mechanical assembly, exact flag, and board contours (`web/src/runtime.rs::CadScene`). Keep this identity beside every pending model request; a changed scope/projection or unmount invalidates it.
2. Obtain the current board preview using the existing artifact contract: `PreviewBoard` for a referenced source board, or `PreparePreview` → a private page-binary adapter around the existing KiCad `exportErgogenForms` generator/allocator/serialization → `FinishPreview` for native project boards. Preserve reserved-net allocation, source serialization, unresolved model-path rewriting, and snapshot token/revision/job IDs end to end. This bridge is not currently in the Dioxus bundle; do not replace it with raw render, add a `CoreRequest`, or alter `PcbPreview`.
3. For each `PcbPreview.models` row, resolve `model.path` to its existing asset ID using the React precedence above. Resolve document-local assets by `Asset.id` then verified `Asset.sha256` bytes from `Runtime.store.load_asset`; keep a bounded per-viewer decode cache keyed by SHA-256 (bundled IDs only when no document `Asset` exists). Retain a visible existing-style pending/missing/error/retry state; absent bytes must not produce a placeholder mesh.
4. Decode by the asset filename extension: STEP/STP through existing `CadOperation::ReadStep` and exact current snapshot identity; STL/WRL through the already exported renderer WASM decode functions. The page host currently keeps only the `Renderer` instance and has no decode method, so F7.3 needs a private page-host bridge that uses the same initialized renderer WASM module exports (without adding exports or widening library visibility). Preserve the 32 MiB input limit and validate returned finite/triplet mesh buffers before scene submission.
5. Build an immutable renderer projection that retains `PcbPreview` metadata, the enabled `BoardReference` pose/elevation (unless the effective physical projection disables it for a flipped instance), and pairs every successfully decoded mesh with the exact `PcbModel.id`. Include existing Case bodies and current mechanical stack in their existing positions. Do not transform models in a second frontend implementation: the renderer's `PcbModel` and BoardReference inputs own their existing transform application.
6. Before publishing bytes, decoded meshes, preview results, or picks, re-check the captured owner identity. Require `PcbPreview.revision == accepted document revision`; for `ReadStep`, use the existing request/job/snapshot identity validator; for renderer submission, keep the already separate strictly increasing renderer sequence and its accepted/stale result. A pending completion from a prior board, instance, snapshot, projection, or mount is discarded. A failed/closed worker or viewer clears its cache and settles pending work; `RendererHost` disposal owns renderer/GPU/listener cleanup.
7. On a current pick, map the returned **reference** through the selected board's `partIds` to the current captured document Part. Leave `pcb`, case-body IDs, module IDs, unknown refs, and empty picks to their existing workflow mappings. Never map a Parts sample object ID into the live project; F7.3's shared contract requires Parts sample generation identity independently of copied project/board/revision IDs.

This is a private presentation/provider seam only. Existing `BoardReferencePanel` and `PartsInspectorPanel` remain the model-authoring owners; this adapter only consumes the accepted document/assets and produces render input plus mapped pick output.

## Boundaries and remaining evidence

- The current Dioxus Case scene is a captured physical-instance projection and currently has no `PcbPreview` or model bytes in `CadScene`; add model delivery at the frontend owner, not to Core/CAD output shape. Do not alias a physical Case scene to a canonical-board scene.
- The React Vite bundled byte registry and native-preview generation worker are not presently exposed in the Dioxus page build. A private static-resource mapping for stable `ergogen:model:*` IDs and the KiCad generator/allocator/source-serialization bridge must be proven from the actual page packaging. Until then, archived/local models can use existing verified SHA bytes, but there is no demonstrated Dioxus byte source for an unarchived bundled model and no packaged native-preview middle step. These are private bridge gaps; no new public API is indicated.
- The exact saved archive above is already used for public React/Dioxus Case viewport evidence. The existing evidence proves Case geometry rendering and React’s reference-to-Part selection, while noting that the candidate’s renderer pick-to-Inspector mapping was not established. It does not prove the Dioxus 124-model delivery, full pick behavior, STL/WRL decode, or archive-reopen asset path; those remain F7.3a checks.
- No Cargo/build/compiler/browser run was performed for this contract task. This draft does not close F7.3, INT.2, BND.1, or the F7.8 consumer join. Shared-viewer issue 02 remains a Case-first slice; Layout, Parts, Keymap, and Keycaps adoption require their own source projection and mapped selections. Shared module registration, workflow mount/composition, and CSS changes are root-owned and must land serially; isolated consumer projection work may proceed after the common bridge contract is reviewed. This is coordination guidance, not a new canonical dependency.
