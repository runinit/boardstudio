# F2.2 bundle-aware archive packet — independent Spec review

**Verdict: NEEDS CHANGES.** The archive semantics are mostly source-grounded, including opaque model bytes and the separation between F2's private option input and F8's visible checkbox. However, the prerequisite packaged-byte provider has no identified owner or executable ticket, and the ticket makes an unimplemented private boolean input a pre-edit gate even though this packet is supposed to create/use that input. Those conditions make the implementation frontier ambiguous and currently non-dispatchable.

## Findings

**S1 — Name and ticket the packaged model-byte provider prerequisite.** The audit and current Rust code establish that `Runtime::pack_archive` can load project-owned assets, but no archive-capable packaged Ergogen catalogue provider exists. `model_delivery::select_model_asset` only classifies an `ergogen:model:*` reference as `MissingBundledProvider`; its `VerifiedModelBytes` is a renderer path that rejects empty bytes and then hands bytes to STL/WRL decoding or STEP reading. It does not supply catalogue identity/metadata/bytes for archive packaging and cannot be reused unchanged while meeting the spec's opaque-byte contract. The current spec and ticket say this provider is “separately owned” and a prerequisite, but identify no owning workstream, ticket, interface, or prerequisite acceptance artifact. Add an explicit provider ticket/owner and make this child depend on its exact callable contract, or assign the provider work to a named bounded child. The current spec correctly states that archive bytes stay opaque (including empty/unrecognized content if within archive limits); retain that distinction and do not route them through renderer format validation.

**S1 — Treat the private boolean as this capability's input, not an already-callable prerequisite.** The pinned Rust page has no `embedUsedModels` value or prop. The current spec correctly says a private boolean input is enough to implement/exercise the pack adapter before F8 integration, and the visible F8 checkbox is not a prerequisite. However, the current child ticket still requires proving that boolean “at the existing composition boundary” before editing and lists it as blocked-by capability, which cannot be satisfied from current source unless the packet itself creates it. Amend the ticket to make the private `embed_used_models: bool` pack-operation/composition input part of this child and test it with true/false fixtures. F8 later owns the visible checkbox and connects its shared page preference to that seam. Issue16 may consume the completed capability while the checkbox remains an F8 integration gate.

## Contract assessment

The amended opaque-byte and digest decision is correct. React `packProject` fetches each selected bundled file as raw bytes, calculates SHA-256 to make the packed `Asset` record, and forwards those bytes to `PackProject`; Core verifies that `assets/<sha256>` matches the actual byte digest and applies path/count/size limits. React's bundled metadata has no independent expected digest, so the spec correctly avoids inventing one. The archive path does not decode STL/WRL/STEP or reject empty model content. Preserve that behavior. The Rust viewer's `VerifiedModelBytes::verify` currently rejects empty bytes, so it is not an interchangeable archive provider.

The ownership distinction for the preference is also right in principle: React stores one `embedUsedModels` value at the root, passes it to the Export checkbox, captures it in the export snapshot, and both Export and the Project-menu action dispatch the same `project` artifact. F8 owns the visible control; F2 owns the pack semantics and Project-menu action. Private adapter fixtures can test both bool values before the F8 control exists. The spec's current prose says this, but its capability start gate must stop implying that the absent input already exists.

The reference closure trace is broadly accurate: React includes Ergogen-rendered models for placed parts, `definition.models`, module/circuit definition models, assembly member models plus generated member overrides, and board-reference models; `false` skips newly bundled copies while existing `doc.assets` still travel. One fixture phrase, “unused bundled definitions,” should specify whether the definition itself contains a referenced `models` entry. React unconditionally adds bundled `definition.models` from every document definition, even when that definition has no placed part; do not accidentally filter those out under an interpretation of “unused.”

The exact closure scope is broadly right. React adds Ergogen-rendered models for placed parts, module/circuit definition models, assembly member models plus generated member overrides, and board-reference models; it also unconditionally adds `definition.models` for every document definition, even when that definition has no placed part. The current tickets mention “unused bundled definitions/models”; fixture wording must preserve this actual React behavior and distinguish a model referenced by an in-document definition from an unused library model.
