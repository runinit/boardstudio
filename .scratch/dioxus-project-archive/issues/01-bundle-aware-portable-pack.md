# 01: Package a portable project with optional used bundled models

**Parent:** F2.2 — Project lifecycle and portable archive (`.scratch/dioxus-frontend-v1/issues/02-projects-shared-ui.md`). F2 owns portable archive semantics; F8 owns its Export-route checkbox and route. This child adds no parent-task graph edge and does not change F2.2's existing F2.1 start / INT.2 acceptance joins.

**What to build:** The existing Rust archive operation can save a current accepted project snapshot as a TypeScript-compatible `.boardstudio` copy, always including project-owned assets and optionally including the exact referenced bundled Ergogen model assets selected by the same `embedUsedModels` value used by the React Export control.

**Capability start gate:** Before editing, prove callable access to (1) `AcceptedSnapshot` and its export `Scope`/stale guard, (2) BrowserStore local asset bytes by SHA-256, (3) the existing Core `PackProject` worker request/reply and guarded browser delivery, and (4) provider ticket 02's packaged identity/metadata/raw-byte interface for supported bundled Ergogen models. Ticket 01 itself adds and tests a private `embed_used_models: bool` input; no existing Rust composition bool is assumed. Provider 02 supplies the bytes; ticket 01 consumes that source and implements closure, option handling, packed-document construction, and archive invocation, not a second provider or network fetch. The visible F8 checkbox is integration acceptance, not a start gate. The TypeScript source establishes the closure oracle. F2.2's parent start and INT.2 acceptance joins remain unchanged.

**Blocked by:** Draft 02 — packaged Ergogen model-byte provider. Ticket 01 owns its private `embed_used_models: bool` input, so no existing preference input is a blocker. The ticket owns model-reference closure and the option-aware archive adapter. A visible F8 checkbox is not required to begin adapter work; it is required for paired settings integration acceptance. Do not substitute a fake provider or runtime network fetch. The visible preference control remains F8-owned.

**Status:** ready-for-agent

- [ ] From the existing accepted-snapshot archive path, package an immutable packed-document value and verified asset bytes; never mutate the live accepted ProjectDoc, BrowserStore project entry, or asset store while exporting.
- [ ] Always include all document-owned local assets. When `embedUsedModels` is true, resolve and embed the exact referenced bundled model closure from used Ergogen parts/instance overrides, definition models, module/circuit definitions, assembly members/overrides, and board references. Preserve existing document-owned assets and do not duplicate asset identities. When false, omit only newly resolved bundled catalogue assets.
- [ ] Preserve bundled asset ID, reference filename, media type, source attribution, and SHA-256. Consume the separately provided packaged bytes and compute their SHA-256 for the packed asset record/archive path. The React catalogue supplies no independent expected digest; rely on existing Core archive validation to check path/payload digest consistency, and reserve mismatch rejection for inputs with an independently declared expected digest. Do not pass archive bytes through renderer-only `VerifiedModelBytes` validation, which rejects empty bytes and has a stricter per-model limit than Core. Treat model bytes as opaque: do not reject empty or otherwise content-unrecognized bytes beyond existing provider availability/read, independently expected digest (if supplied), archive path, and Core size checks. The operation must work offline from packaged assets.
- [ ] Send `archive.json` with the same `embedUsedModels` value through the existing `PackProject` request; keep existing Core archive size/path/hash validation and archive schema unchanged. Test both boolean inputs at this private operation boundary before the F8 checkbox is mounted.
- [ ] Use the accepted snapshot's project name for `${project.name}.boardstudio`. Recheck snapshot/scope immediately before delivery; stale/cancelled/failing operations do not download and cannot alter current document, save state, revision, history, or assets. Retry remains the existing action behavior.
- [ ] Test true and false with independent fixtures covering used generator models/instance overrides, recognized `definition.models` on an unplaced document definition (included), an unused library model and a no-part Ergogen definition without static model references (omitted), modules/circuits, assemblies and board references; prove local assets are always retained and archive round-trip restores the expected augmented packed document and exact bytes. Preserve React's unconditional `definition.models` traversal. Include opaque empty/content-unrecognized bundled bytes if admitted by the packaged provider, computed bundled digest/path generation, Core path/payload digest validation, and the absence of an invented expected catalogue digest. Test independently declared expected-digest mismatch only where an input contract actually supplies one.
- [ ] Pair the visible archive-save journey on the same React and Dioxus project fixture, option value, scope, viewport and theme. Inspect filename, ZIP/project JSON/assets and isolated import result; test both preference values once the F8 checkbox is integrated. A private boolean input permits implementation and adapter testing before that checkbox exists. Include delayed snapshot change, failure/no-download, offline assets, keyboard/focus, desktop/compact, and no page errors. Tests through Core/private helper alone do not close F2.2.
- [ ] Record relevant takeaways under existing RF-001/RF-002/RF-009 as applicable, or record that none were observed. Keep issue16's Project-menu action, F8.1's checkbox, F2.2's INT.2 join, F8.6→F2.2, and shared F2/F8/F9 acceptance gates intact.
