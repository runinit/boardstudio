# 03: Inspect isolated Parts 2D and 3D previews

**Status:** ready-for-agent; dispatch waits for the declared start blockers and concrete private consumer contract.

**Parent:** F4.4, “Inspect isolated 2D and 3D library previews” in `.scratch/dioxus-frontend-v1/tasks.json`.

**Start blockers:** F4.1 (accepted Parts selected-definition/companion inputs) and F7.1 (reviewed common-viewer feasibility/adapter contract).

**Acceptance joins:** F7.3 (single shared viewer plus isolated sample-project consumer) and INT.2 (scoped async/file/asset delivery seam). These are joins, not additional start blockers. Preserve the parent graph and all existing joins unchanged.

## Outcome

In the central Library/Parts workspace, selecting a component or assembly presents the same read-only footprint sample as React: a 2D geometry view with named visibility controls and a switch to the shared 3D model viewer. The sample represents the selected definition and its companion recipe while remaining isolated from the active project. This ticket owns Parts-specific sample inputs, view selection, 2D layer/part visibility, and selection-scoped preview feedback; it consumes, and does not duplicate, the shared F7.3 viewer and INT.2 service/lifecycle seams.

## Acceptance

- [ ] For the same selected definition and companion fixtures used by React, the 2D sample shows available pad geometry and numbers, plated/mechanical drills, authored or compiled footprint copper, retained-generator graphics and text, and the keycap envelope or courtyard. Use the existing F3a projector for authored geometry and the retained generator output for generated artwork. Preserve the reference Y-up transforms, rotation/pose, sizing and initial fit; do not invent a separate zoom control where the reference has none.
- [ ] Show available footprint layers by their reference names and per-part visibility controls. Match the reference visibility owner: hidden-layer state is keyed by selected `definition.id`, so companion/orientation/recipe changes for the same definition preserve it; another definition receives an effective empty visibility set, and returning to the remembered definition restores its state unless a later toggle replaced that stored pair or the workspace unmounted. Visibility never edits the source definition or active document.
- [ ] The 2D/3D choice is local view state. Reset to 2D on explicit catalogue or preset activation, including reselecting the currently active entry; do not reset it for every recipe/companion/orientation mutation. Keep that activation policy separate from async stale-result scope, which must include all relevant recipe inputs. The preview is mounted in the central Library/Parts canvas while the catalogue and selected details remain in their accepted Objects/Inspector owners.
- [ ] Preserve the full reference 2D empty and feedback path: with no selection show “Select a component or key assembly.”; with a selection but no usable footprint geometry show “Preparing footprint preview…” while compilation is pending and announce compile errors as alerts; when geometry is available show “Compiling footprint preview…” during pending recompilation and display current compiled diagnostic messages. Use actual compiled geometry/service inputs and preserve the reference Ergogen fallback geometry while compilation is pending; do not replace an absent non-Ergogen compile result with invented/static geometry. These states belong to preview consumption, not F4.3 generator-edit forms.
- [ ] The 3D view consumes the one F7.3 viewer with an isolated sample project built from the selected definition and companions, source project assets, expected sides/poses/transforms, and no project wiring. Use existing renderer/model conversion behavior and distinguish loading, unavailable/missing model, conversion failure, and render failure. Preserve supported model/provider retry behavior. Renderer initialization or context-loss failure stops cleanly and leaves a usable 2D return; do not add an unsupported canvas/context retry control.
- [ ] Preview construction, selection, layer toggles, view toggles, and supported retry leave the active document, revision, nets, history and saved assets unchanged. Key asynchronous work to the accepted document/session/selection scope, cancel or ignore superseded work, publish no stale scene after selection or unmount, and release owned workers/renderer resources through INT.2/F7.3 lifecycle owners.
- [ ] Paired React/Dioxus public-browser evidence uses identical definition/companion fixtures and compares service outputs plus light/dark desktop/compact captures for 2D, layers/part visibility, 3D loading/ready/error and return to 2D. Include keyboard and accessibility behavior for the view switch and layer controls. Record the active-project revision/history before and after the journey.
- [ ] Preserve the existing F4.4 acceptance joins and the inherited independent Standards/Spec and RF handoff gates. No graph row or parent acceptance is closed by fixture-only evidence.

## Ownership and limits

Parts-private implementation owns only the sample-preview composition and local view/layer state after F4.1 inputs are accepted. Integration owns central mount placement, Runtime wiring, shared CSS and manifests. F7 owns the only viewer/renderer lifetime. Existing Rust/CAD/artifact services remain authoritative for geometry and conversion. Do not add a Parts-specific viewer, fake rows or permanent mock service, static geometry masquerading as compiled output, a second authoritative active-project document/store/session, public API/visibility or schema change, CAD/model algorithm change, or new readiness claim. The isolated ephemeral sample `ProjectDoc` required by the reference is allowed and is not authoritative. Do not absorb Issue 01 catalogue/details or Issue 02 bundled assemblies/VIK module browsing; do not include F4.2 imports/editors, F4.3 generator editing, F5 mounted-module/PCB behavior, or F7 canonical-board/Case preview behavior.

They do not yet form a Parts sample viewport/layer controller.
- Existing 3D seam: `web/src/renderer_host.rs` has the private renderer mount/update/camera/disposal wrapper. It is not itself a Parts sample builder or a complete F7.3 consumer contract. F4 must use the reviewed F7.3/INT.2 integration; it must not reach across the page-binary/library boundary through a new public visibility change.
- Selection inputs originate in the accepted Parts read model. React's `sampleAssembly` creates a fresh ephemeral sample project, reuses source assets, adds only selected definitions/companions and clears terminal nets locally; the active project is not the preview project. Copy only the data necessary to form the accepted scoped input and avoid cloning full immutable definitions on every repaint.
- Reference retry distinction: React model/provider retry belongs to the existing model-preview path; F7.3 specifies clean stop and 2D fallback for renderer initialization/context-loss, without an extra canvas-retry control.
